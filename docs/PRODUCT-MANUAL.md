# WindowsToLinux 产品说明书

启动配置统一使用 Config 模块资源目录中的 `config.yaml`，随 Config JAR 发布，字段、路径基准和填写方式见 [Config.md](Config.md)。CLASS 默认只启动主 APP，不读取或加载 Mod，也不要求开发工作区参数；在 class 区开启 Mod 自动加载后，才执行以下 Mod 操作及加载流程。JAR/APP 固定装配 Mod 能力，保留各 Mod 已保存的启用选择，不提供全局自动加载开关。修改 YAML 后重新构建并重启，已保存的 DB 用户设置优先。

“设置 → 外观 → 入口排序”以圆角卡片分别展示平台和已发布 Mod 根入口，可上下拖动调整顺序，也保留上移、下移与恢复默认。拖动时卡片跟随鼠标，相邻卡片平滑让位；松开后自动保存，保存成功才更新导航，重启后恢复，保存失败保留原顺序。AI 模型清单与用途顺序使用相同拖动方式，用途顺序仍需点击保存，卡片不会跨清单转移。暂未发布的 Mod 保留排序位置；当前不提供单独隐藏根入口，设置按钮继续位于底部。

“设置 → 外观 → 语言与外观”提供语言、外观及界面缩放选项。语言按“原名（当前界面语言译名）”对照显示；界面缩放可选 100%、150%、200%，相对于系统显示缩放放大文字和控件。点击“保存外观”后立即应用到当前窗口并在重启后恢复，不清空页面输入；保存失败不改变当前生效的显示设置。

侧栏展开时，左上角 Logo 旁按 `Windows`、`ToLinux` 两行显示完整名称；收起后只显示 Logo。标识和文字跟随界面缩放，收放时固定文字布局并按可用宽度淡入淡出。Logo 可以点击及用空格返回首页，悬停、焦点和点击均不绘制背景框或选中效果。

底部锁定区展开时保持状态在左、反向操作在右；折叠时沿连续弧线改为操作在上、状态在下，设置按钮同步上移，文字渐隐，按钮尺寸与位置同时变化。收放及反转共用侧栏动画，关闭系统动画时直接应用最终布局。首次点击设置默认进入排序首项“语言与外观”，随后保留当前会话中已访问的设置分类。

默认启动进入首页，完整等比展示随 UI 资源打包的 16:9 项目封面。点击左上角 Logo，或用键盘聚焦后按空格，可从其他页面返回首页；折叠和锁定时也可操作。主密码设置仍从“设置”进入。

“设置 → 语言与外观 → 启动页面”提供“下次启动时恢复上次页面”开关，默认关闭，点击“保存外观”后生效。正常关闭时把当前平台页面、Mod 根与内部页面身份或 Mod 管理子页写入 `desktop_preference` 的 `ui_last_page`，恢复开关保存在 `ui_restore_last_page`。开启时下次启动恢复该页面，关闭时进入首页；Mod 工作区等待启动发布完成后恢复，旧部署内部页身份转到当前根后仍恢复对应标签；页面已停用、删除或不可用时回到首页。仅恢复导航位置，页面输入草稿与弹窗不随之保存，锁定状态按原安全规则处理。外观页整体可滚动，小窗口和较大缩放下仍可访问保存及入口排序。

APP 与官方 Mod 的普通开关统一使用圆形滑块，关闭时滑块在左侧，开启时滑块在右侧并显示强调色；鼠标、空格键、禁用状态及原有保存方式保持原含义。开关过渡遵守系统动画偏好。

Mod 商店已提供搜索、详情、下载确认、进度和重试界面，当前默认适配器仍返回服务不可用；填写商店 URL 不代表已接通线上服务。未配置或不可用时显示“网络未连接，请点击重试”，重试保留搜索词。成功下载及安装流程由测试适配器验证，CLASS 保持不能安装发行包的限制。

安装版当前已接入选定版本的启动、数据准备和逆序停止；安装后仍默认关闭，需要明确启用并重启。原包已删除不影响完整已登记程序启动；程序损坏时保留选择并报告问题，不自动换版。首次安装后从未开启的 Mod，同样需要下次启动确认未加载且无占用，才可删除或重装。以上为本机源码和隔离安装目录验证，正式 JAR/APP 发行打包仍暂缓。

已完成的平台任务现在会保存脱敏摘要并清理临时执行记录，不再因旧终态记录阻止 Mod 删除。可在“数据库管理”查看平台任务摘要；清理历史不会重新生成旧摘要。网页终端救援结束后也会归档状态摘要并清理临时事件，可在“数据库管理”的 browser_recovery 类别查看。归档失败保留原任务待收尾，继续核对不重新发送已确认完成的动作。结果不明或资源未释放的任务仍保留占用。

“任务与恢复”页现可查看保留任务的原所有者、版本、类型、进度和未释放资源，点击刷新更新状态。“请求取消”仅发出协作请求，原工作与资源收尾后才结束；“重新核对原任务”调用精确原恢复实现，宿主救援另须确认旧终端命令已结束。“补齐归档”仅补存已核实结果，不再执行业务。“查看日志”打开已有数据库管理页。锁定或关闭会撤销未提交确认；缺原版本恢复登记时保持禁用与占用。默认 CLASS 启动已按原发布和依赖图加载隔离恢复上下文；独立 Mod 可正常启动，旧图保留到原任务与资源明确收尾，程序变化或未知结果继续保留，不重发业务。

## 当前界面

主窗口采用左侧导航、顶部标题和中央工作区。侧栏首次展开，可在 168／64 逻辑像素宽度之间切换；折叠后使用图标、提示和键盘焦点访问。平台入口为服务器、AI 配置、Mod 和任务；每个成功启用并发布根的 Mod 自动显示一个工作区入口；设置及锁定在侧栏底部，左上角显示随 UI 资源打包的项目 Logo。界面采用 IDEA 风格的浅深表面和紧凑圆角，控件以底色区分，导航的选中、悬停与颜色焦点分别显示。设置内集中提供外观、安全、连接与传输、文件操作、日志和各 Mod 的设置；窄窗口使用分类下拉框。部署的审批和授权策略一起放在部署工作区，由部署 Mod 独立保存。

服务器、AI 模型、Mod 管理、商店、原包及官方部署的应用清单统一按圆角卡片展示，任务和日志保留表格。Mod 管理在清单旁显示当前运行、用户选择及待重启信息；安装、删除、迁移与重装仍走原确认流程。Mod 根入口自动按保存顺序出现在侧栏；内部功能页由 Mod 自行组织。APP 提供紧凑工作区标题和关闭按钮，明确关闭先确认并默认取消；确认后未保存输入丢弃，已接受后台任务继续。切换保留页面输入和选择，关闭后重新进入才创建新实例。

官方部署保留静态／辅助部署、自主部署、应用管理及运行环境预览。部署页以源码卡片、目标服务器卡片、审批策略、主要操作及日志结果组织内容。Git 技术参数、秘密修订和自主部署约束在所属页面的“高级选项”独立窗口中编辑；关闭该窗口保留草稿，关闭业务页释放其窗口。锁定隐藏从属窗口，页面关闭不取消已接受任务；任务取消与恢复继续通过原入口明确操作。上述说明适用于当前桌面 APP，后文标注为历史 0.x 的高级侧栏及备份说明不代表当前入口。

## 1. 产品定位

WindowsToLinux 是面向个人和小型自托管场景的 Windows 桌面部署管理工具。用户提供本地源码或 Git 版本、目标 Linux 服务器和必要配置后，软件完成静态分析、服务器检查、目标机环境准备、受控传输、目标机构建、发布、健康检查、失败恢复、生命周期管理，以及版本化备份、恢复和离线迁移。

产品只管理能够验证 WindowsToLinux 归属的应用和资源，不是以下工具的替代品：

- 通用 SSH 终端或任意命令执行器；
- 通用服务器面板、systemd 管理器或容器管理器；
- 自动 DNS、负载均衡或外部流量切换平台；
- 会执行用户项目代码的 Windows 本机构建器；
- 自动删除外部数据库、用户源码、独立备份或非本软件资源的清理工具。

## 2. 一体化部署界面

左侧导航栏贯穿窗口内容区，顶部显示 WTL 图标和产品名，设置固定在底部；收起后保留图标。右侧顶部栏的左端显示当前页面标题和说明，切换部署、服务器、已部署应用、备份、AI 配置或设置时同步更新。

点击导航收放按钮时，栏宽平滑过渡，两行品牌文字随之淡入淡出，导航项的上下位置保持稳定；折叠后品牌与导航图标居中。收放按钮下方始终显示左右留白的细分隔线，不再显示「工作区」文字。侧栏和卡片运动按实际经过时间平滑推进，快速反向保留当前位置；系统关闭窗口动画时直接切换。浅深主题共用圆角导航、柔和的选中背景、无描边卡片和按钮反馈。

首页上方左侧选择本地源码目录，或填写 Git 地址；右侧选择已保存服务器，也可就地添加。两张等宽卡片之间以圆形向右箭头标明部署方向。点击“一键部署”后，程序自动识别单应用或多组件项目，补齐必要输入、检查服务器、准备环境与 DB、构建并启动，最后执行健康检查。Git 默认使用仓库默认分支，开始分析前固定到同一提交。

每次部署只选择一个项目和一台目标服务器。源码识别成功后，地址或目录显示在上方圆角选择区，下方输入框隐藏；两侧选定后均须先点击“清除”才能更换。已选源码不再接受新拖入或粘贴，清除服务器后刷新列表也不会自动重新选中。服务器环境摘要可通过悬停查看。

下方日志框持续显示当前动作和结果。只有部署及必要健康检查成功，才显示可复制的网址或服务器启动命令；网址可点击打开，多组件分别列出入口。取消、失败、回滚或等待人工处理时不显示成功交付信息。

主页面的“高级选项”入口位于顶部栏右侧并垂直居中，修改提示和帮助随入口一起显示；独立弹窗保留自己的入口。高级选项默认收起，展开后可修改当前页面的技术参数。长标签按侧栏宽度自动换行，行高随文字增长；每个参数右侧保留独立的圆圈问号位置，悬停或用键盘聚焦即可阅读说明。按钮旁也提供相应帮助。收起不清空参数，有自定义值时显示提示。切换页面、语言和主题保留输入与侧栏状态；重启默认收起。正在部署时暂停外观切换，防止正在运行的任务界面被重建。

已部署应用页直接选择应用、查看状态和访问入口、启动/停止/重启；服务器页主要填写地址、用户名和密码，SSH 端口默认 22；备份页先选择备份、恢复或迁移，再从已保存列表选择应用和目标服务器并填写相应必要输入；AI 页主要填写接口地址、模型和密钥；设置页显示语言、主题和使用说明。多组件手工编辑、凭据存储方式、归档检查和诊断信息分别保留在高级区域。

Class 运行模式下，「设置 → 高级选项 → 界面调试」可以打开全部主页面，并单独预览服务器、AI、应用管理、补全输入、秘密输入、主机指纹、环境准备、数据库处理、风险确认、备份恢复、错误提示和文件选择弹窗。弹窗使用固定示例数据；扫描按钮返回示例应用，保存、部署、接管和真实 AI 调用均不会执行。主页面按钮仍跳转到当前工作区。预览跟随当前语言与主题；JAR 和 App 模式不显示此入口。

自动识别项目、试验适配器许可、多组件必需项和 AI 模型启用统一显示为文字后的左右开关；高级选项中的长说明可换行且只显示一次。数据库替换的三项确认也使用开关，默认全部关闭，仍需逐项确认开启并点击确定才会继续。开关支持鼠标和空格键操作，禁用状态与原有业务规则一致。

桌面端各页面及弹窗的按钮、输入框、下拉框和弹出菜单统一使用无静态描边表面，以底色、悬停、选中及颜色焦点反馈区分状态。普通和次要操作按钮使用与页面、卡片背景可区分的底色，可用时显示清晰文字，禁用时显示灰色文字和弱化底色。下拉框入口在首次显示时按初始选项确定宽度，选择、文字更新及列表刷新不会改变入口宽度；展开列表仍按当前内容留足显示空间。下拉框使用较宽的内边距、轻量箭头及带留白的选项列表，选中项以柔和底色和圆角高亮；配色随深浅主题切换，保留键盘选择、禁用状态与本地化显示。设置页的语言、外观和界面缩放选项使用统一圆角表面与独立底色，文字和控件随缩放调整，窄窗口中可展开查看完整选项。

全部静态界面文案、帮助及状态映射来自中英文消息表，协议枚举值与翻译显示分离。源码名称、网址、用户输入和其他动态内容不作为翻译键。

## 3. 产品总体工作方式

```text
用户选择源码或备份
        ↓
Windows 桌面静态校验与明确审阅
        ↓
窄应用门面编排确定性用例
        ↓
Apache SSHD 建立受信主机连接
        ↓
目标 Linux 上的固定 managed helper v10 协议
        ↓
候选构建/恢复、健康检查、提交或旧版本恢复
        ↓
桌面 SQLite 保存不含秘密的精确受管状态
```

产品不会把用户输入拼成任意 Shell。远端操作使用类型化 Java 契约和固定 helper 动词，SSH/SFTP 细节只存在于 Linux SSHD 实现模块。

## 5. 服务器管理

### 5.1 用户可执行的操作

1. 选择已保存服务器，或填写地址、用户名和密码新增；
2. 点击“保存并检查连接”；标识、SSH 端口和凭据存储方式在高级选项中调整；
3. 首次连接时人工核对主机指纹；
4. 采集发行版、版本、包架构、CPU、Java、Node、Python、容器、安全模块和防火墙事实；
5. 一键部署自动衔接受控环境准备；也可在服务器页高级区域单独检查；
6. 后续连接拒绝主机指纹静默变化。

服务器页和自动部署都会先确认系统工具及依赖的安装或更新，默认选中取消。DNF 9 会共同更新兼容的 OpenSSH 包，软件包脚本可能短暂重启 SSH；程序在安装后重新认证连接才能报告结果。

CentOS Stream 9/10 的 SELinux 未处于强制模式时，还会显示独立的系统变更确认框，默认选中取消。确认内容包括配置备份、文件标签修复、服务器重启及连接中断；批准后由程序完成准备、重连与强制模式登录验证，再继续安装工具。拒绝或关闭对话框不会执行对应变更；失败时保留准备状态以便再次确认后继续。该流程已接入，当前实机复核进度见[0.4 期验收](development/PHASE-0.4.md#acceptance)。

### 5.2 实现机制

- 非秘密连接资料进入桌面 SQLite；秘密值进入独立秘密存储；
- 首次主机指纹只有在用户确认后保存，后续指纹不一致直接拒绝；
- `SshdLinuxGateway` 只提供类型化会话，不公开任意 SSH 命令或 SFTP 路径；
- 环境准备使用按发行版固定生成的脚本，并在变更前后复核 SELinux/AppArmor 和防火墙状态；
- SELinux 状态变更仅在独立确认的系统准备阶段执行；普通安装阶段仍保持安全策略，CentOS 安装固定构建工具时仅在该事务使用已配置的官方 CRB 仓库，不永久启用仓库；
- 当前 helper 协议版本必须精确匹配，不做静默旧协议回退。

## 6. 源码与 Git 输入

### 6.1 本地源码

软件只读取用户选定的源码目录做静态分析和安全归档，不在 Windows 主机执行项目脚本、构建插件、依赖安装或用户二进制。

### 6.2 Git 源码

软件可以从明确仓库来源创建固定 Commit 的源码快照。部署身份绑定所选 Commit 和内容摘要，而不是部署时再次读取可能变化的分支头。

当前 1.1 默认静态部署页面要求填写逻辑项目名、无凭据仓库 URL 与本机 Git 可执行文件的绝对路径；引用可选仓库默认分支、指定分支、标签或完整提交。本地 `file:` 仓库还需明确允许。最终确认列出原 URL、引用、固定 Commit 及各组件归档摘要，并告知确认后保存本次来源项目记录；保存的项目行与正式发布执行关联。Git 准备未知时保留原任务供显式核对，不重新抓取仓库。SSH Git 仍待平台凭据与主机信任接线；本机 CLASS 验证不代表真实目标机部署已经验收。

### 6.3 实现机制

- `shared/source` 负责可重复源码快照、安全路径和归档；
- `shared/git` 只负责仓库来源和固定版本；
- 路径穿越、链接、特殊文件、超限成员和归档内容变化会停止流程；
- 源码归档只服务于目标机构建，不与应用数据备份格式混用。

## 7. 项目识别与类型化运行时

当前模型可以表达十四种恢复运行时：Spring Boot、普通 Java JAR、无依赖 Java 源码、Node.js、Python、静态站点、Docker/Podman 容器、Go、Rust、.NET、Kotlin、PHP、Ruby 和 CMake/C 服务。

软件根据锁文件、构建文件、入口、产物和声明端口等静态事实给出识别和支持结论。高级语言仍属于精确范围的试验适配，不应理解为支持该语言的所有框架。

实现上，每种运行时都有封闭类型，不使用任意“运行命令”字符串。构建参数、监听端口、健康检查、容器端口、卷和版本要求均经过对应领域类型校验。

### 工具链选择

项目声明、候选和实际使用的精确版本分别记录；软件按支持目录匹配、复用或准备工具链，不自动改源码、锁文件和应用目标。不同语言的识别范围、允许构建范围及实机覆盖不能混用，详见[0.4 期工具链](development/PHASE-0.4.md#toolchains)。

## 8. 配置与秘密

### 8.1 普通配置

- 普通配置使用不可变修订；
- 值类型为文本、整数或布尔；
- 配置作用域明确区分构建期和运行期；
- 类似密码、Token、Secret、Key 的键不得伪装成普通配置；
- 每个发布绑定实际使用的配置 SHA-256，后续修改产生新修订。

### 8.2 应用秘密

- 秘密使用“标识 + 正修订号”引用；
- 发布只保存精确引用，不保存秘密值；
- 1.1 默认静态部署页面可在开始发布前选择服务器、填写业务秘密标识与新的正修订号，并在独立原任务准入后输入应用秘密。保存成功后，运行审阅可从已有且记录原用途的修订中选择精确引用；高级输入仍可填写明确的 `标识:修订号`，但缺失或原用途未知的修订不能发布。关闭或锁定未答密码框会取消原任务；已确认的创建继续收尾，结果未知时保留原任务供显式核对，不自动重建秘密；
- 恢复归档中的秘密由独立备份密码加密；
- 解密值只存在于可清零缓冲区，使用完成立即清零；
- 同一标识的不同修订可以共存，不能用新值覆盖历史发布所需修订。

### 8.3 备份秘密加密

`secrets.enc` 使用独立备份密码，经 Argon2id（64 MiB、3 次、1 路）派生密钥，再用 AES-256-GCM 认证加密。随机盐和 nonce 写入公开信封，密码和派生密钥不写入归档。错误密码、密文篡改或载荷不完整使用同一失败关闭边界，不返回部分明文。

## 9. 单组件部署

### 9.1 操作流程

1. 在首页左侧选择源码目录或填写 Git 地址，右侧选择服务器；
2. 如需覆盖源码声明，展开高级选项调整；一般可以直接点击“一键部署”；
3. 仅在缺少信息、首次主机信任或高风险操作时回答弹窗；未配置 AI 不影响继续；
4. 查看持续日志，完成后复制访问网址或启动命令。

健康检查默认按项目识别；需要覆盖时可明确选择 HTTP、TCP、UDP、PROCESS 或 COMMAND；无端口 APP 使用进程稳定性或安装自检。源码侧的运行参数、DB 缺项和整应用健康代表组件会先补齐，再检查服务器；填写错误后在同一任务内修正并重新校验。运行期间输入和重复操作会锁定，外观切换需等当前操作完成。

### 9.2 实现机制

- 源码只上传到摘要绑定的远端候选工作区；
- 构建只发生在目标 Linux；
- 发布前保存旧发布快照；
- 配置和秘密修订封存在发布树之外的受管只读位置；
- 候选发布成功并通过健康检查后才成为当前版本；
- 任一步失败都尝试恢复旧发布并重新验证；恢复不可验证时返回 `MANUAL_RECOVERY_REQUIRED`；
- 成功后原子保存当前发布、完整运行时、配置、秘密引用、资源绑定和整应用图。

自动流程从源码声明或明确的 DB 清单识别数据库。无声明且无迁移标记时记录显式空范围；存在外部端点、冲突或缺项时补问，不静默改成服务器本地数据库。高级区域仍可手工提供已审阅连接及精确秘密引用。当前 1.1 默认部署页面已接源码声明 SQLite 的独立初始化确认与配置/资源发布；服务器型数据库准备仍属待完成范围。具体路径声明见下文。

### 9.3 DB 自动管理

PostgreSQL/MySQL/MariaDB/Redis 直接安装到受支持服务器系统。SQLite 使用应用文件，不创建数据库服务、端口、账号或密码。已安装且兼容的 PostgreSQL、MySQL、MariaDB 或 Redis 优先复用；停止运行也算已安装。多个实例让用户选择，缺少管理或应用连接凭据时补问。程序不会将 MySQL 项目改成 PostgreSQL，也不会因为版本较新就卸载。

版本不兼容时，用户必须先自行备份，确认停机准备，并明确同意卸载旧软件、安装目标版本。授权绑定当前服务器、实例及版本，执行前再次复核。程序不清空数据目录、不替用户迁移数据；进入人工恢复等待状态后，由用户按数据库支持的升级路径恢复，再重新检查继续。安装完成不等于数据恢复完成。

版本无法识别时显示冲突并允许处理后重检，不按“未安装”继续。如果多个现有实例使整组软件包替换无法安全隔离，先提示用户自行处理，再重检；不会要求一份执行时必定被拒绝的替换授权。

可在源码根目录提供非秘密声明 `windowstolinux-db.properties`，例如：

```properties
db=main,cache
db.main.engine=POSTGRESQL
db.main.version=>=16
db.main.database=demo
db.main.username=demo_app
db.main.environmentPrefix=DB
db.main.passwordEnvironment=DB_PASSWORD
db.main.initialize=schema.sql,data.sql
db.cache.engine=REDIS
db.cache.database=demo_cache
db.cache.username=demo_cache_app
db.cache.environmentPrefix=REDIS
db.cache.passwordEnvironment=REDIS_PASSWORD
```

`initialize` 按给定顺序执行。Spring Boot 的本地 JDBC/Redis 声明也可识别；明确声明 `spring.sql.init.mode=always` 时，唯一的 `schema.sql` 先于 `data.sql` 执行。多个同名入口或不能确定的初始化方式需补填。生成的密码进入现有秘密存储，声明文件中不得写入密码。普通服务通过受保护的凭据文件注入 `*_PASSWORD`，使用 `*_PASSWORD_FILE` 时注入真实凭据文件路径。

多个数据库分别绑定自己的初始化文件，不能把一个库的 SQL 复制执行到其他库。已明确指定入口的声明按各库执行；需要补问时可为不需要初始化的库留空，但存在结构变更时必须至少明确一个 SQL 入口。Redis 不接受 SQL 初始化或 JDBC 数据源声明。高级连接绑定也必须覆盖源码声明的 DB 类型和范围。

自动初始化只适用于本次创建、归属可证明且再次检查为空的应用库，使用应用级权限。执行记录绑定 SQL 内容；已完成任务重试只验证，不重复写入。初始化失败或状态变化时停止并要求人工处理，不自动清除失败记录或重放 SQL。已有库结构变更需独立确认。经校验的 Spring 初始化完成后关闭框架重复初始化、Flyway/Liquibase 和 JPA 自动建表入口；不提供任意迁移脚本执行器。

Redis 使用限定于应用前缀的账号，应用须按该前缀访问。隔离容器不能直接使用宿主 `127.0.0.1` 数据库，当前需在高级区域提供容器可访问的明确 DB 绑定。未知安装来源、无法确认的实例、残留配置或不支持的系统仓库版本会停止并说明问题。MongoDB 自动安装、Redis 完整备份和多数据库完整备份尚未提供；这些资源会被登记，完整备份入口明确拒绝，避免漏备后报告成功。

### 9.4 FHS 路径与 SQLite

每个受管组件使用自己的应用标识 `A`，默认安装根为 `/opt/windowstolinux/apps/A/`，部署配置在 `/etc/opt/windowstolinux/apps/A/`，文件和数据库在 `/var/opt/windowstolinux/apps/A/`。工具工作区及其他数据库引擎内部目录不变。新 helper 拒绝旧布局和旧备份，不自动搬迁、删除服务器数据或清空客户端数据库；该布局的实机验收使用重装后的专用服务器。

用户明确声明的存储和配置优先。绝对宿主路径只能在本应用安装根的严格子路径，不能指向应用根、其他应用、发布目录或控制文件；相对路径保留应用访问方式，实体放在安装根内 `persistent/` 的独立绑定目录。未确定、含变量或冲突的输入直接报错，不会被默认路径替换。该自定义规则属于产品允许的例外，默认结构遵循 FHS。

在组件源码根提供 `windowstolinux-storage.properties`，例如：

```properties
storage=uploads,settings
storage.uploads.kind=FILE
storage.uploads.location=DEFAULT
storage.uploads.access=uploads
storage.uploads.environment=UPLOADS_DIRECTORY
storage.uploads.mode=rw
storage.settings.kind=CONFIGURATION
storage.settings.location=DEFAULT
storage.settings.access=config/settings.json
storage.settings.environment=APP_SETTINGS_FILE
storage.settings.seed=config/settings.json
```

这些环境变量必须已经被应用支持。配置文件按种子内容摘要保存只读修订；运行时需要修改的设置应声明为 `FILE` 数据，而不是 `CONFIGURATION`。普通文件可用 `seed` 明确指定源码目录；后续部署不覆盖已有内容。若源码无法确定路径，应先补全声明或产品提示的 SQLite 输入，再重新部署。

SQLite 默认声明：

```properties
db=main
db.main.engine=SQLITE
db.main.path=DEFAULT
db.main.pathEnvironment=APP_DATABASE_FILE
# 可选的首次初始化输入
# db.main.seed=seed/application.db
# db.main.initialize=schema.sql
```

未指定 SQLite 文件路径时默认文件名为 `application.db`，位于 `/var/opt/windowstolinux/apps/A/databases/main/`。明确的 `db.main.path=data/shop.db` 使用安装根内稳定数据映射；Spring 的字面 `spring.datasource.url=jdbc:sqlite:...` 可识别并通过 `SPRING_DATASOURCE_URL` 交付。内存数据库不纳入持久化支持，SQLite 驱动仍由项目依赖提供。

容器保留镜像里的路径，例如 `db.main.path=/app/data/application.db`。未显式指定宿主位置时使用默认宿主数据库目录；可用 `db.main.hostLocation=CUSTOM` 和 `db.main.hostPath=/opt/windowstolinux/apps/A/state` 明确选择受限宿主位置。配置只读、容器根文件系统只读，SQLite 和文件使用受管 bind mount；宿主 `sqlite3` 负责初始化及一致性备份，业务镜像不需要该命令。镜像种子只导入一次。容器 SQLite 访问路径须有非根父目录，不能直接放在容器 `/`；与工作目录或文件绑定共用父目录时由受管只读视图或精确别名保留其余内容。

预检展示资源类型、路径来源、应用访问位置、宿主位置及读写模式。非法位置不静默改写，运行时写权限阻止未声明的越界持久写入。更新、回滚及发布清理保留持久目录。

### 9.5 构建身份与资源限制

部署流程由 root 管理服务器环境及项目。项目构建使用临时低权限身份；原生应用以每组件固定、不可登录、无管理权限的系统账号运行，容器应用使用明确的数字非 root UID/GID。运行账号随应用保留，构建临时账号按归属清理。源码、构建缓存和产物放入预留容量的构建卷，容量含文件系统元数据；空间或必要隔离能力不足时在上传前停止；构建启动时再次复核。临时账号、进程或挂载清理失败会单独报告，发布成功与清理完成分别展示。已有 Ubuntu 24 代表性部署、容器和 Yarn 生命周期记录；完整身份故障、数据库备份恢复与迁移矩阵仍未覆盖，详见[0.4 期验收](development/PHASE-0.4.md#acceptance)。

## 10. 多组件应用

首页自动识别多个项目目录并使用同一次源码快照。无法确定组件关系时弹窗补填，不任意选择依赖。高级区域可以进入手工编辑器调整组件及依赖；手工草稿仍要求每个组件显式审阅 DB 范围。软件在修改目标机前拒绝重复组件、端口冲突、未知依赖和依赖环。

部署顺序按依赖从前到后，停止和恢复顺序按依赖反向执行。每个组件有独立候选、快照、运行时和健康检查，整应用另有独立健康门。只有所有组件和整应用都成功时，SQLite 才原子记录整个新图；部分成功不会伪装成整应用成功。

## 11. 受管应用与生命周期

“已部署应用”页面可以查看软件已验证归属的应用，并执行：

- 刷新状态；
- 启动；
- 停止；
- 重启；
- 启用开机自启；
- 停用开机自启。

生命周期操作不接受任意 systemd 单元名或容器名，而是从已保存受管身份和运行时恢复上下文，再由目标机返回权威观测。桌面保存观测历史，但本地记录不能代替实时远端状态。

## 12. 完整备份

### 12.1 备份前置条件

完整远端备份要求：

- 已保存成功整应用图；
- 每个组件具有当前发布和完整已审阅运行时；
- 每个发布绑定精确普通配置和秘密引用；
- 文件与数据库范围已经明确审阅；
- 整应用健康检查已经独立保存；
- 应用最多包含一个受支持的数据库制品；
- 目标服务器资料和凭据仍与受管应用一致。

主备份操作自动检查已保存输入；高级区域也可单独执行该检查，它只读取桌面 SQLite，不连接服务器。即使结果完整，也只表示可以继续远端检查，不表示远端制品一定可创建。

创建备份前会确认一致性备份可能暂停应用写入并恢复原运行状态。恢复前会明确确认目标服务器、所选归档及替换已有受管发布的影响；取消确认不会启动操作。语言或主题切换会保留尚未提交的备份输入，操作结束后再允许切换。

### 12.2 备份内容

schema v6 归档可以包含：

- `manifest.json`：应用、组件、依赖、发布摘要、环境、数据库、健康和成员清单；
- 每组件发布树；
- 每组件精确普通配置、资源绑定、运行健康和用户访问 URL；
- 已审阅普通文件树；
- 受管容器宿主绑定目录；
- 经归属验证的 Podman OCI Archive，或恢复时所需已审阅源码；
- SQLite、PostgreSQL、MySQL 或 MariaDB 一致性数据库制品；
- AES-256-GCM 加密的精确秘密修订集合。

当前自动完整备份明确限制为零或一个受支持的 SQL 数据库；Redis 或多个数据库绑定会在远端备份前明确拒绝。SQLite 绑定保存精确文件名、存储选择、访问路径及所属组件；普通文件归档排除数据库及 WAL/SHM/journal，数据库通过 Backup API 单独取材并检查完整性。

### 12.3 远端一致性实现

1. 实时观察所有组件；
2. 按依赖逆序停止原先正在运行的组件；
3. 验证无写入者；
4. 使用 helper v10 创建严格 PAX TAR、宿主绑定目录、OCI 和数据库制品；
5. 每个制品流式下载到 Windows 受管工作区并独立复核大小、SHA-256 和格式；
6. 按依赖顺序恢复原来运行的组件；
7. 重新执行组件和整应用健康检查；
8. 清理精确远端操作目录；
9. 加密秘密并写入完整归档；
10. 在用户目标同目录写入私有临时文件，完整校验后无覆盖原子发布，并从最终路径再次独立校验。

远端制品生成成功、SFTP 传输成功或本地输入完整，任意一项都不能单独代表备份成功。

## 13. 本地归档检查与候选准备

用户可以在不连接服务器的情况下：

- 校验归档结构、成员数量、大小和 SHA-256；
- 分开查看内容完整性与可选 Ed25519 来源状态；
- 用独立备份密码认证 `secrets.enc`；
- 提取到新的隔离本地候选；
- 精确删除当前候选。

桌面一次只跟踪一个当前候选。删除授权绑定工作区签发对象和目录文件身份；重建对象、工作区外路径、链接或外部替换均不会被误删。应用重启后不扫描和猜测旧候选。

当前只接受 schema v6；schema v3/v4/v5 和旧激活配置明确返回版本不支持，不转换、不删除原归档。

## 14. 受管恢复

### 14.1 用户操作

1. 在备份页选择“恢复”任务和 schema v6 完整归档；
2. 从列表选择已保存目标服务器；
3. 输入独立备份密码；
4. 先解锁软件，业务操作自动使用本次会话的凭据权限；
5. 点击“恢复到目标端”，核对并确认目标、归档和覆盖影响；
6. 首次连接时核对主机指纹；
7. 查看远端恢复状态、本地接管状态和警告。

### 14.2 修改前检查

恢复在暂存远端输入前完成以下检查：

- 归档和全部成员再次完整校验；
- schema v6 发布、秘密、配置、资源、运行时和数据库身份完全一致；
- 目标主机 helper、sudo、tar、systemd、架构、发行版和类型化运行时能力满足要求；
- 正式端口无外部占用，或本地已有图证明是该目标拥有的同一应用；
- 目标受管根可写且至少具有两副本空间；
- 归属冲突和外部流量变更均为否；
- 数据库制品类型和版本身份可用于候选阶段。

服务器型数据库目标密码来自归档中的精确秘密修订；SQLite 不要求数据库账号或密码。前置阶段不假装目标已有该秘密；秘密暂存后，数据库候选恢复阶段再执行真实连接、工具和版本兼容检查。

### 14.3 候选端口混合策略

- 容器：每个已审阅宿主端口自动映射到 `127.0.0.1:49152-65535` 中实时确认空闲的不同候选端口；
- 静态站点、PHP、Ruby：只覆盖已有类型化监听端口；
- Spring Boot、普通 JAR、Java 源码、Node、Python、Go、Rust、.NET、Kotlin、CMake：不猜测监听参数，进入短停机切换；
- 临时端口不写入正式配置、发布身份、SQLite 或备份清单；
- 绑定竞争或启动失败立即停止，不通过换端口重试掩盖问题。

### 14.4 提交和恢复顺序

1. 在摘要候选目录暂存并回读精确文件；
2. 暂存配置和精确秘密修订；
3. 暂存并恢复候选数据库；
4. 启动可并行的回环候选并完成组件/整应用预检；
5. 建立短停写边界；
6. 保存旧发布并停止旧服务；
7. 先提交数据库候选，同时保留旧数据库；
8. 恢复正式端口和正式服务身份，按依赖顺序启动；
9. 在正式端口重新执行组件和整应用健康；
10. 全部成功后提交发布身份并清理候选；
11. 任一步失败时，按“停止新正式服务 → 回滚数据库 → 恢复旧发布 → 复核旧组件和整应用健康”的顺序恢复。

恢复终态包括：

- `SUCCEEDED`：远端正式端口和整应用健康成功；
- `FAILED_EXISTING_PRESERVED`：失败但旧发布已完整恢复并验证；
- `MANUAL_RECOVERY_REQUIRED`：数据库、发布或健康恢复无法完整证明，必须人工处理。

本地接管状态与远端状态分开：若同一应用的源图仍绑定另一台服务器，远端可成功但本地状态为 `DEFERRED_SOURCE_RETAINED`，避免静默覆盖仍需恢复的源端控制记录。

SQLite 先在独立候选数据库上验证组件和整应用健康，再停写提交。无法明确覆盖监听端口时，先停止旧应用，再以正式端口启动仍然隔离数据的候选；这不会提前提交候选数据库。原生服务通过 systemd 隔离映射重定向硬编码绝对路径，容器只挂候选数据。切换在目标文件系统内进行并保留原数据库及伴随文件；失败先确认候选和正式写入者退出，再回退数据库、配置和发布。无法确认停写时保留现场，返回人工恢复状态。

## 15. 双服务器离线迁移

### 15.1 用户操作

1. 在备份页选择“迁移”任务并从列表选择源应用；
2. 从列表选择不同的已保存目标服务器；
3. 输入独立备份归档密码；软件已解锁时不再重复输入主密码；
4. 阅读停写窗口说明并明确批准；
5. 点击“准备离线迁移”；
6. 等待结果进入“可人工切流”、安全失败或人工恢复状态；
7. 只有目标就绪后，才在软件之外人工切换 DNS、反向代理或负载均衡；
8. 完成生产观察并另行作出删除决定前，保留源端和最终备份。

未批准停写窗口时，产品不会打开 SSH 或执行任何远端操作。

### 15.2 实现机制

1. 创建完整初始备份，备份结束后恢复源端原运行状态；
2. 使用初始归档对目标执行只读恢复前置检查，不暂存配置、秘密、发布、文件或数据库；
3. 按依赖安全顺序停止源端全部组件，并确认整体为 `STOPPED`；
4. 在源端保持停止时创建完整最终备份；
5. 最终备份 SHA-256 生成唯一目标候选身份；
6. 复用第 14 节同一恢复链，在目标正式端口完成最终健康；
7. 成功后源端保持停止但不删除，外部流量保持不变；
8. 最终停写备份保留在 `data/backups`；
9. 任一失败都尝试清理目标候选并重新启动、验证源端；
10. 目标清理或源端恢复任一无法验证时进入 `MANUAL_RECOVERY_REQUIRED`。

迁移成功终态固定为 `READY_FOR_MANUAL_TRAFFIC_SWITCH`。软件不会自动修改 DNS、代理、负载均衡，也不会自动停用或删除源端。

### 15.3 当前接管限制

为避免同一个全局应用标识同时静默归属两台服务器，目标成功而源图仍保留时，桌面不会自动覆盖源图。本次迁移结果会明确显示延后接管状态；人工切流后的持久化接管流程仍需后续专门设计。在该流程完成前，应保留最终备份和源服务器，不要把“目标已健康”理解为“桌面已永久改绑目标”。

## 16. App 部署模式与模型用途

本节适用于桌面 App 的单组件、多组件一键部署。Web 尚未接入三模式、用途列表或 Agent 审批，继续使用自身配置和流程。

### 16.1 三档部署模式

“一键部署”同行最左侧的模式入口收起时只显示当前档位，入口宽度按当前语言的最长选项固定，切档时不伸缩；点击后弹出紧凑的说明及胶囊形三档滑块，可用鼠标或键盘选择。说明文字居中显示，统一预留两行高度；人工审核的较长说明按所需空间预留，切换三种模式时弹窗大小和位置保持不变，不再重复显示悬浮提示。滑轨包住圆形滑块，缩短行程及四周留白。拖动时滑块跟随指针，松开后平滑吸附；点击或键盘切档采用短缓动过渡，并遵守系统关闭动画的设置。切换模式后面板保持展开，焦点移到其他位置或点击面板外部时收起，也可按 Escape 主动收起。首次缺少已保存偏好时默认为**AI 辅助**；之后启动恢复已保存的模式和审批偏好，主题、语言切换保留当前选择。切换滑块或审批方式不会调用 AI；任务启动后冻结模式、审批策略、源码、目标及模型顺序，并锁定选择。

AI 辅助和 Agent 模式的审批下拉框保留“人工审核／自动审批／完全控制”文字，分别配以手掌、盾牌和橙色警示盾牌图标，当前选项与展开列表一致。人工审核的逐条审核提示仍可通过悬停阅读。

| 模式    | 行为                                                                                                                                | 模型要求                                         |
| ------- | ----------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------ |
| 静态    | 确定性分析、人工补齐、固定部署事务和真实健康验证；部署任务全程不调用 AI，包括失败分支                                               | 无                                               |
| AI 辅助 | 系统控制流程；在分析补参、部署前检查、执行失败三个节点提供辅助，可选择已登记的诊断、参数修正和恢复动作，不生成自由 Shell 或源码补丁 | 已启用且通过文字能力测试的部署模型及独立审批模型 |
| Agent   | AI 自行读取项目、推导组件依赖、生成命令并根据失败修正；独立模型审批；公共受管层完成发布与整应用健康验证                             | 可用部署模型及审批模型                           |

AI 辅助先运行标准识别，遇到类型歧义、参数缺失或失败时，只读浏览冻结源码并展示文件、行号和快照依据。可以从多个受支持候选中选择，所有建议均须标准校验。用户明确填写的值优先，冲突时请求澄清；密码、授权、资源归属、权限和对外暴露意图仍需用户确定。正常部署步骤由系统推进，并保留一次基于实际计划和服务器证据的部署前检查。已知失败后，只有有效参数修正或经验证的恢复变化才重试，最多两次；未知结果或没有新进展时停止。部署模型不可用时须明确同意人工继续，实际命令仍须独立审核，不能静默绕过。

自主 Agent 通过目录、搜索和分页文件读取理解项目，不要求先通过静态语言识别。它在任务所属 Linux 工作区执行自己生成的构建和诊断命令；构建输出独立可写，源码通过专用补丁修改。单组件和多组件均按校验后的依赖顺序执行，不能由模型文字声明部署成功。原生进程及容器最终都交给公共发布、健康与回滚流程。

### 16.2 必须经过的审批

两种 AI 模式的每一次实际远端命令或完整脚本都先进行静态审批：核对范围、参数、身份，并拒绝规则命中的极高危命令；静态拒绝后不发送给审批 AI。通过静态审批后，再经独立 AI 审批。固定工具生成的命令同样适用，阶段同意不能代替命令审核。

递归删除按目标范围检查，不一概禁止 `rm -rf`。删除 `/`、系统关键目录本身或其全量内容，以及明确切到这些目录后进行整体删除的命令，在静态层拒绝；规则同时检查明显的点路径及参数变体。指定普通目录的删除先核对任务范围，再进入 AI 审批判断其归属和影响，包括固定 helper 对自身候选目录的清理。静态检查不执行 Shell 展开，也不能代替 AI 审核或实际执行隔离。

审批策略决定哪些动作需要人工授权，授权策略决定相同类型及已核实范围的问题是否再次询问。两种策略都在部署中设置，启动后随原任务冻结。合法组合为七种，其他选项灰显并禁止选择；切换审批策略使草稿授权值失效时转为通用，已保存的非法组合拒绝读取而不自动改写。

| 审批策略 | 授权策略 | 静态及独立 AI 通过后的行为 |
| --- | --- | --- |
| 人工审核 | 逐条 | 每条实际命令申请人工授权，不另增加整流程交权提示 |
| 人工审核 | 通用 | 首次同类同范围动作询问，随后仅复用本次流程的人工作答 |
| 自动审批 | 逐条 | 开始时交权一次；普通动作执行，高危动作每次询问 |
| 自动审批 | 通用 | 开始时交权一次；普通动作执行，高危动作按同类同范围复用人工授权 |
| 自动审批 | 完全授权 | 不询问交权；普通动作执行，高危动作不执行，直接尝试新的低风险方案 |
| 完全控制 | 通用 | 开始时询问是否完整交给 AI；之后通过两门的动作直接执行 |
| 完全控制 | 完全授权 | 不询问交权；通过两门的动作直接执行 |

自动审批中用户未授权高危动作时，改提低风险方案；新方案仍重新经过静态和独立 AI 审核，不重复执行或再次索求同一被拒命令。找不到可行低风险方案时停止并说明原因。高危拒绝且尚未发送属于已知拒绝，不能伪装成执行成功或远端效果未知；实际已发送但效果不明仍按 UNKNOWN 原操作核对，不自动重放。

通用授权只复用人工问题，不能缓存 AI 审批或扩大目标；例如同一已核实候选范围内同级目录删除可复用人工授权，但每个实际删除请求仍单独经过 AI。命令、目标、身份、源码修订或关键证据变化后重新审核。源码修改只作用于本任务 Linux 副本，显示完整差异，本地原始项目和冻结快照不修改。补丁必须绑定修改前摘要，修订变化会使旧构建与批准失效。管理连接沿用 root，项目命令由隔离的非 root 身份执行。

缺少部署或审批模型、审批不可用或被拒绝时不能绕过。首次主机信任、凭据和缺失业务输入仍由用户提供。源码和日志仅按需提供给选定模型并过滤秘密；历史任务只保存非秘密摘要、修订和结果，不保存完整源码或原始提示词。

超时、输出限制或连接中断导致结果未知时，任务保留人工恢复状态；不得自动重放写操作。旧 `AGENT` 历史显示为旧版受限执行，不解释为新自主模式，也不自动续写。

### 16.3 全部模型与四种用途

AI 模型页默认显示全宽“全部模型”。打开右侧语言、审批、视觉或语音入口时，原列表收缩到左半侧，在同一页面展开右侧用途列表；关闭后恢复全宽，保留选中项和滚动位置。

- 左侧一直显示全部模型，已加入当前用途的模型带标记；左右箭头加入或移除用途关系，移除不删除模型。
- 全部模型拖动排序只改变展示。用途列表拖动或上下移动决定该用途的实际调用及接替顺序，每个用途独立启停。
- 同一模型可用于多个用途；部署与审批仍保持独立上下文、Skill 和权限。
- 用途修改为草稿，保存时原子提交成员、顺序和启用；取消或关闭丢弃草稿，失败保留草稿。切换用途前先保存或取消。
- 文字、视觉、文件语音、实时语音能力分别验证；相关协议地址、模型或凭据修改后需重新验证，无关协议及显示名不影响已有有效验证。API Key 保存在秘密存储。
- 部署和审批只走文字用途；图片识别只走视觉用途，无视觉模型时不影响纯文字部署。视觉识别不作为第三个自主执行 Agent。

本期只使用当前新建库结构，不提供旧开发库模型或凭据迁移。语音用途独立启用及排序，可使用已通过对应语音验证的模型；仅配置语音不影响已有文字部署。

### 16.4 接替、暂停与任务记录

每个用途同一时刻只调用一个模型，顺序只向后推进，不跨用途借用。部署模型可因技术错误、输出无效、明确无法处理或连续两轮没有新证据而接替；审批模型只因技术错误或输出无效接替，有效拒绝不会换模型寻找放行。

自主 Agent 全任务最多 80 轮决策；标准辅助动作循环保留 30 轮预算及最多两轮补证据。切换模型不重置预算。模型请求沿用 30 秒超时，新候选查询/清理有独立短超时，既有部署保留自身超时。运行中模型配置变化只影响新任务；暂停后可明确选择“采用新模型”，替换快照并撤销待执行审批。

暂停和取消在事务安全边界生效，不能只关闭 SSH 就宣称已取消。若发布已实际完成，随后收到取消仍报告发布成功。候选清理先核对 root 所有的任务标记，再使用既有 helper 停止所属构建进程和清理卷；不会清理正式发布、配置或业务数据目录。

“任务记录”保存非秘密策略、Skill 版本、审批、执行摘要、接替、实际调用数、可获得的 Token 用量、人工交互次数和耗时。没有用量的调用保持未知，不推算费用；不保存明文凭据、完整源码、原始提示词或原始模型响应。

AI 辅助模式下，已有数据库结构变更和 SQLite 首次初始化仍需用户确认业务意图；完全控制不会让 AI 代替用户授予数据变更权限。确认后，实际命令仍按所选三档策略审核。

App 重启将未完成记录标为中断，不自动续写。断线或日志缺失造成的未确认执行会阻断同服务器后续一键部署，不能创建新任务重放。“查询远端实际状态”可检查记录中的本任务候选和构建进程，查询不会清除未知结果：候选不存在不能证明发布、数据库和环境修改已恢复。本版没有通用的未知事务自动恢复/解锁功能，需要根据实际影响完成专门恢复核验。

自主方案必须显式声明组件及整应用健康条件；不猜补独立健康探针。首版自主交付支持原生进程、Docker/Podman、文件资源和非秘密运行配置；不从模型文本推断数据库凭据、秘密引用或未知绑定。既有标准部署及已支持备份继续使用原有明确契约，通用进程的新增备份适配未作为已支持格式声明。

所有 AI 命令功能固定使用上述三档，本地禁止、AI 拒绝或独立审核不可用均不得执行。阶段批准不代替命令批准，命令内容、目标、身份或证据改变必须重审。

本版真实模型接口及 AI 辅助/Agent Linux 部署验收尚未运行，不能用历史静态部署证据代替。当前本地验证及剩余边界见 [App 开发说明](development/PHASE-0.4.md#agent-modes)。

## 17. 诊断、错误与人工恢复

每个模块拥有自己的结构化失败类型，并通过最小公共失败契约向界面传递：错误码、阶段、用户消息、严重级别、建议恢复动作、操作标识和安全诊断。

界面不直接显示原始异常消息。诊断报告会脱敏并限制单份大小、总份数和写入位置。密码、Token、私钥、秘密值、第三方响应正文和未脱敏远端输出不得进入报告。

出现 `MANUAL_RECOVERY_REQUIRED` 时：

1. 不要删除源端、旧发布、旧数据库、候选目录或最终备份；
2. 记录操作标识、失败码、失败阶段和已经验证的恢复步骤；
3. 检查目标组件、正式端口、当前发布指针和数据库旧/新身份；
4. 在确认产品不能继续前，不使用任意命令替代产品路径并声称验收成功；
5. 根据诊断证据制定一次明确的人工恢复操作。

<a id="ssh-rescue"></a>

### 17.1 APP 网页控制台 SSH 救援

默认入口在“服务器”页选择已保存服务器，点击“SSH 网页控制台救援”；该入口不依赖正常 SSH 已连接或业务 Mod 已安装。普通“检查 SSH”明确失败且资源收尾后，结果区域提供“SSH 检查失败，直接救援”，绑定本次失败的原服务器；切换清单选中项不会改写目标，修改原服务器资料后须重新检查。取消、结果未知或尚未收尾时不显示可救援按钮。已有同服务器救援时重新打开原会话。普通检查仍只做认证；救援另执行固定只读回显以确认远端命令能力。三模式部署不在任务内部启动浏览器救援。认证失败先核对用户名及凭据，指纹冲突先完成身份核验，救援不会自动覆盖信任记录。

1. 在弹出的专用 Edge／Chrome 浏览器中登录云平台，选择正确服务器并进入 VNC 或 Web SSH 终端。Web SSH 无法登录时，改用可用的 VNC 等通道。
2. 停在空的 Shell 提示符，在救援窗口刷新终端列表、选择终端、填写服务器 ID，并勾选观察授权。终端文字或截图将发送给已启用模型；输入密码、验证码或进行人工操作前先点击“暂停 / 人工接管”。
3. 审阅每条具体命令、理由和预期结果后确认。可能修改系统或不属于固定只读集合的命令还需独立确认。切换普通窗口和标签页不要求保持前台聚焦；请勿同时手动操作同一终端。
4. 模型缺少配置或返回无效建议时救援暂停，可从救援窗口转到平台模型配置，然后继续并重新绑定。已发送模型请求的结果未知时保留原任务，先执行核对，不自动重发。没有可用视觉模型时显示“模型暂不支持视觉识别，请添加或启用支持视觉识别的模型。”网络、超时和凭据故障另行报告，不会降级到 OCR 或要求抄录终端。
5. SSH 身份、认证及只读执行验证通过后，浏览器停止操作。用户可重新发起所需检查，救援不会自动继续此前业务任务。已提交修改的结果仍不明时须先核查，不以 SSH 已连通推断原业务完成。

每轮最多 30 次诊断、15 分钟主动执行，等待确认不计入。关闭浏览器不等于取消服务器上已提交的命令；结果未知时必须先在服务器核对，不可直接重试。重新绑定要求再次确认目标和观察授权；APP 重启不自动恢复旧命令。结束救援会请求原任务协作取消，并清理专用浏览器与会话；清理未完成时任务仍保留占用。使用服务器页的原任务核对入口前，须手动确认旧终端命令已结束且不会继续运行；核对不重放命令。APP 重启后，如果上次已经确认并保存浏览器及驱动的完整清理结果，可以继续核对释放占用并记录中断；缺少确认记录时继续保留 UNKNOWN，即使主浏览器窗口已经消失也不推定全部清理完成。普通记录不保留截图、完整终端输出、登录 Cookie 或密码。

本功能仅在 APP 中提供，需有本机 Edge／Chrome 或预装对应的 Playwright Chromium；不会自动导航云平台。救援不限定 Linux 发行版，但当前真实厂商页面及 CentOS／Ubuntu／非 systemd 实机修复组合仍为 `RUNTIME-PENDING`，不扩大原部署范围。

## 20. 建议的首次使用顺序

1. 把软件安装或解压到当前用户可写目录；
2. 启动后确认 `data` 目录初始化成功；
3. 在服务器页保存一个专用测试服务器并核对 SSH 指纹；
4. 在首页选择最小示例源码和该服务器；
5. 点击“一键部署”，回答缺项或首次信任弹窗，等待日志和结果；
6. 在“已部署应用”中刷新状态并验证启动、停止和重启；
7. 明确审阅配置、秘密、文件/数据库绑定和整应用健康；
8. 创建完整备份，并另行保存一份不覆盖的备份副本；
9. 在专用目标服务器执行恢复实机验收；
10. 最后在两台专用服务器执行离线迁移验收，目标就绪后只做人工流量切换；
11. 只依据对应 helper 版本、夹具和环境的实际验证判断能力，不将代表样例或本地测试外推到生产全场景。

## 已部署应用、后台 APP 与一次性工具

应用列表保留所有成功部署的内容，包括已经停止的网站和执行结束的工具。分类依据经审阅的服务声明：为其他机器或外部用户提供 HTTP、HTTPS、TCP、UDP 服务（包括局域网）归为网站；其余为 APP。下载文件、连接数据库、内部通信和本机健康检查不会单独改变分类。反向代理后的业务服务仍需声明为 `EXTERNAL`。

| 运行内容           | 操作                                     | 使用入口                                  |
| ------------------ | ---------------------------------------- | ----------------------------------------- |
| 长期网站或网络服务 | 启动、停止、重启、自启动                 | HTTP(S) 网址，或 TCP/UDP 协议、地址、端口 |
| 长期后台 APP       | 启动、停止、重启、自启动                 | 配套客户端命令；没有客户端时显示管理命令  |
| 一次性 APP         | 查看、复制命令；不提供启停、重启或自启动 | 受管 helper 的按需运行命令                |

一次性工具显示“已安装可用”，不以持续存在进程作为成功条件。命令在目标 Linux 的终端运行，输入输出及退出码由业务程序返回；产品不提供内嵌终端、任务表单、定时任务或 GUI。详情、版本、备份恢复仍按适用能力提供。旧记录保留，但缺少新的运行声明时提示重新分析，不能依据旧网址自动推定网站类型。

在项目根目录添加 UTF-8 的 `windowstolinux-application.properties`，或在桌面/Web 的应用运行声明中补填相同内容。声明不会作为 Shell 执行；参数按 `arg.0`、`arg.1` 连续编号传递，空格、中文和 `$` 均是参数本身。入口相对发布源码根，工作目录默认发布源码根。省略 `command.entrypoint` 时使用该语言适配器已审阅的主入口。

```properties
version=1
mode=ON_DEMAND
command.entrypoint=cli/main.py
workingDirectory=
verification.entrypoint=cli/main.py
verification.arg.0=--self-test
expectedOutput=self-test-ok
health.timeout=10
inputs=source
input.source.hostPath=/srv/reports/input
input.source.accessPath=/inputs/source
```

`ON_DEMAND` 必须声明安装验证入口，部署只执行隔离数据上的自检，不能把正式业务任务当作验证。已有 SQLite 使用宿主备份工具复制到验证目录；不会覆盖正式数据库或重放任务。默认同一 APP 同时只运行一个受管任务，重复调用返回忙碌。

长期后台 APP 使用 `mode=DAEMON`，默认连续稳定运行 5 秒；可用 `health.mode=COMMAND` 和 `verification.*` 指定随包自检。配套客户端用 `client.entrypoint`、`client.arg.0` 等声明。没有运行声明时，即使未发现端口也要确认是否向外提供服务；默认建议本机 APP。有外部服务但协议或端口不明确时须补填，不能由访问网址推定。网络服务示例：

```properties
version=1
mode=DAEMON
endpoints=events
endpoint.events.protocol=UDP
endpoint.events.bind=0.0.0.0
endpoint.events.port=9000
endpoint.events.targetPort=9000
endpoint.events.exposure=EXTERNAL
health.mode=UDP
health.port=9000
health.requestHex=70696e67
health.responseHex=706f6e67
```

UDP 必须验证监听归属和预期响应；也可用随包 `verification.*` 探针代替十六进制请求/响应。TCP 和 UDP 分开判断端口冲突。所有健康结果只证明目标主机本地探测，不代表公网或局域网的防火墙、代理已经放通。HTTP(S) 端点可以声明 `endpoint.<标识>.url` 作为公开入口。

混合控制台项目可声明 `buildDirectory=cli`、`projectType=RUST_SERVICE`（或对应类型），以及配套 C/C++ 构建单元：

```properties
companions=worker
companion.worker.type=CMAKE_SERVICE
companion.worker.sourcePath=native
companion.worker.artifactPath=.w2l/bin/worker
companion.worker.environment=NATIVE_HELPER
```

主构建目录和配套构建关系必须写入源码声明后重新分析，界面补填不能绕过构建准入。配套单元必须通过受限 CMake 分析与构建，产物随主程序固定到同一发布版本，由主程序通过声明的环境变量调用，不创建独立服务。Python 标准库项目可在 `pyproject.toml` 明确声明 `dependencies = []`。这不改变各语言适配器现有的正式或试验支持等级。

不需要环境变量的 APP 可以使用空配置，不必添加无用的端口或占位变量。

原生常驻应用可声明最多 8 个同运行时工作进程，例如 PHP 页面和消费 SQLite 队列的 worker：

```properties
mode=DAEMON
workers=queue
worker.queue.entrypoint=worker.php
worker.queue.arg.0=--foreground
```

工作进程必须保持前台运行，入口为源码内常规文件，参数仍按连续编号传递。它们共享主服务的账号、工作目录、环境变量和存储；任一进程退出都会停止同组其他进程，再由现有 systemd 重启策略处理。部署、回滚和生命周期以整个应用为单位。`ON_DEMAND` 不接受工作进程，容器多进程由镜像入口管理。工作进程声明进入发布身份和持久化配置；未声明工作进程的既有运行格式保持不变。该扩展已通过 Ubuntu CSV 项目的真实队列处理、统一重启及持久化报告验收，范围见 [多语言记录](../test/multi-language/VERIFICATION.md)。

Composer PHP 项目可通过 `runtime.version` 明确版本，通过 `runtime.secondary` 指定 `router.php` 等源码内路由文件；HTTP 文档根仍为 `public`，依赖仍须有 Composer 锁文件。

必须随源码交付的样例日志可在应用声明中写明 `source.include=samples/events.log`。此字段接受最多 32 个逗号分隔的精确相对文件路径，不支持通配符；默认运行日志仍排除，显式声明也不能纳入密钥、环境秘密文件、排除目录或源码根以外的文件。

写入目录继续使用本说明书的 `/opt`、`/etc/opt`、`/var/opt` 及自定义路径规则。报告目录需在 `windowstolinux-storage.properties` 声明，SQLite 需在数据库声明中绑定；命令参数不能扩大写权限。外部输入仅只读绑定，不能覆盖系统目录、程序、配置或受管存储，不自动修改原文件权限、属主或安全标签。输入的内容不进入备份；恢复到另一主机时必须重新检查来源及可读权限。

更新、回滚、备份和恢复会暂停新任务并最多等待当前任务 30 秒，超时返回忙碌，不强杀任务。离线迁移的最终备份复用源端停写窗口；目标完成后源端数据保留，源端任务准入保持暂停，避免两端同时写入。失败且恢复验证通过后才恢复准入；不能证明完整恢复时报告人工恢复状态。

Ubuntu 24 原生常驻与按需代表性部署已通过八个多语言项目验证，详见 [多语言记录](../test/multi-language/VERIFICATION.md)；UDP、命令中断、容器执行、CentOS 及跨机矩阵仍为 `RUNTIME-PENDING`。

## APP 主密码与手动锁定

未设置主密码时，启动先显示主界面，再弹窗提示前往“设置 → 主密码与凭据”。可以点击“前往设置”直接打开设置页，或选择“稍后设置”继续浏览主界面。在设置页输入至少 8 个字符的主密码并重复确认，点击“设置主密码”后即可开始操作；设密前不接纳部署等业务任务。完成设密后，每次启动显示锁定主界面，点击左下角“解锁”输入主密码；服务器连接、部署、AI、备份和救援复用当前会话，不逐次索取主密码。

点击侧栏“锁定”或按 `Ctrl+Shift+L` 手动锁定。主窗口保持可见，可切换导航、设置分类和页面标签，页面内容不可点击、输入、滚动或拖拽，业务快捷键也不可用。已加载的非秘密内容保留，密码字段清空，业务从属窗口隐藏。左下角左侧显示“已锁定／未锁定”，右侧对应“解锁／锁定”；点击“解锁”打开紧凑主密码弹窗，支持重试和取消。首次进入尚未创建的 Mod 页面时，以锁定环境展示界面，需要授权的数据提示解锁后读取。已开始的后台任务继续运行；需要人工输入或批准时等待解锁，不会自动批准。任务完成不会自动解锁。锁定且有活动任务时，关闭窗口会聚焦左下角解锁入口，需先解锁处理任务，可以最小化；无活动任务时可以退出。

“设置”的安全区域支持修改主密码和切换凭据加密。两种变更都需要验证当前主密码，活动任务期间不可变更。修改密码仅重新保护原数据密钥，不改变业务秘密修订或模型验证。关闭加密前会提示明文风险；重新加密不能清除外部旧副本。没有自动锁定、账户登录、设备绑定或密码找回功能。

部署模式和审批选择会立即保存，首次缺失时采用“辅助部署 + 自动审批”。保存失败恢复原选择并提示；已存非法值提示错误，不自动覆盖。缺少已验证可用模型时需要先配置模型，不自动改为其他模式。任务使用创建时的模式和审批快照；自动审批仍保留高风险人工确认。

全新 APP 数据库格式是 v21，不导入旧数据库或旧凭据。遇到不兼容文件时程序拒绝打开并说明原因，不自动清空。备份归档密码与软件主密码互相独立。程序不主动持久化主密码或明文数据密钥，并尽力清除用后缓冲区；这不等于操作系统绝不把内存写入磁盘。

独立救援浏览器随锁定处理的范围、失败反馈与个人浏览器保护统一见 [Runtime.md：救援浏览器的锁定协作](Runtime.md#recovery-browser-privacy)。
