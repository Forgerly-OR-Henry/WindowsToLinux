## 身份与资源限制

新流程由 root 管理服务器环境及项目。项目构建使用临时低权限身份；原生应用以独立动态身份运行，容器应用使用明确的数字非 root UID/GID。本工具不创建永久项目管理账号。源码、构建缓存和产物放入预留容量的构建卷，容量含文件系统元数据；空间或必要隔离能力不足时在上传前停止；构建启动时再次复核。临时账号、进程或挂载清理失败会单独报告，发布成功与清理完成分别展示。已有 Ubuntu 24 代表性部署、容器和 Yarn 生命周期记录；完整身份故障、数据库备份恢复与迁移矩阵仍未覆盖，详见[四期验收](development/PHASE-4.md#acceptance)。

> [四期动态工具链](development/PHASE-4.md#toolchains) 已将全版本识别与允许构建的版本分开：构建证据保留项目声明、候选版本和实际使用版本。源码、锁文件和应用目标不被自动改写；本地门禁已通过，版本矩阵仍不代表全部实机通过，验证结果见所属功能验收章节。

## 1. 产品定位

WindowsToLinux 是面向个人和小型自托管场景的 Windows 桌面部署管理工具。用户提供本地源码或 Git 版本、目标 Linux 服务器和必要配置后，软件完成静态分析、服务器检查、目标机环境准备、受控传输、目标机构建、发布、健康检查、失败恢复、生命周期管理，以及版本化备份、恢复和离线迁移。

产品只管理能够验证 WindowsToLinux 归属的应用和资源，不是以下工具的替代品：

- 通用 SSH 终端或任意命令执行器；
- 通用服务器面板、systemd 管理器或容器管理器；
- 自动 DNS、负载均衡或外部流量切换平台；
- 会执行用户项目代码的 Windows 本机构建器；
- 自动删除外部数据库、用户源码、独立备份或非本软件资源的清理工具。

## 2. 一体化部署界面

左侧导航栏贯穿窗口内容区，顶部显示 WTL 图标和产品名，设置固定在底部；收起后保留图标。右侧顶部栏的左端显示当前页面标题和说明，切换部署、服务器、已部署应用、备份、AI 配置或设置时同步更新。

点击导航收放按钮时，栏宽平滑过渡，文字随之淡入淡出，导航项的上下位置保持稳定；折叠后品牌与导航图标居中。收放按钮下方始终显示左右留白的细分隔线，不再显示「工作区」文字。系统关闭窗口动画时直接切换。浅深主题共用圆角导航、柔和的选中背景、轻边框卡片和按钮反馈。

首页上方左侧选择本地源码目录，或填写 Git 地址；右侧选择已保存服务器，也可就地添加。两张等宽卡片之间以圆形向右箭头标明部署方向。点击“一键部署”后，程序自动识别单应用或多组件项目，补齐必要输入、检查服务器、准备环境与 DB、构建并启动，最后执行健康检查。Git 默认使用仓库默认分支，开始分析前固定到同一提交。

每次部署只选择一个项目和一台目标服务器。源码识别成功后，地址或目录显示在上方圆角选择区，下方输入框隐藏；两侧选定后均须先点击“清除”才能更换。已选源码不再接受新拖入或粘贴，清除服务器后刷新列表也不会自动重新选中。服务器环境摘要可通过悬停查看。

下方日志框持续显示当前动作和结果。只有部署及必要健康检查成功，才显示可复制的网址或服务器启动命令；网址可点击打开，多组件分别列出入口。取消、失败、回滚或等待人工处理时不显示成功交付信息。

主页面的“高级选项”入口位于顶部栏右侧并垂直居中，修改提示和帮助随入口一起显示；独立弹窗保留自己的入口。高级选项默认收起，展开后可修改当前页面的技术参数。长标签按侧栏宽度自动换行，行高随文字增长；每个参数右侧保留独立的圆圈问号位置，悬停或用键盘聚焦即可阅读说明。按钮旁也提供相应帮助。收起不清空参数，有自定义值时显示提示。切换页面、语言和主题保留输入与侧栏状态；重启默认收起。正在部署时暂停外观切换，防止正在运行的任务界面被重建。

已部署应用页直接选择应用、查看状态和访问入口、启动/停止/重启；服务器页主要填写地址、用户名和密码，SSH 端口默认 22；备份页先选择备份、恢复或迁移，再从已保存列表选择应用和目标服务器并填写相应必要输入；AI 页主要填写接口地址、模型和密钥；设置页显示语言、主题和使用说明。多组件手工编辑、凭据存储方式、归档检查和诊断信息分别保留在高级区域。

Class 运行模式下，「设置 → 高级选项 → 界面调试」可以打开全部主页面，并单独预览服务器、AI、应用管理、补全输入、秘密输入、主机指纹、环境准备、数据库处理、风险确认、备份恢复、错误提示和文件选择弹窗。弹窗使用固定示例数据；扫描按钮返回示例应用，保存、部署、接管和真实 AI 调用均不会执行。主页面按钮仍跳转到当前工作区。预览跟随当前语言与主题；JAR 和 App 模式不显示此入口。

自动识别项目、试验适配器许可、多组件必需项和 AI 模型启用统一显示为文字后的左右开关；高级选项中的长说明可换行且只显示一次。数据库替换的三项确认也使用开关，默认全部关闭，仍需逐项确认开启并点击确定才会继续。开关支持鼠标和空格键操作，禁用状态与原有业务规则一致。

全部静态界面文案、帮助及状态映射来自中英文消息表，协议枚举值与翻译显示分离。源码名称、网址、用户输入和其他动态内容不作为翻译键。

## 3. 产品总体工作方式

```text
用户选择源码或备份
        ↓
Windows 桌面静态校验与明确审阅
        ↓
窄应用门面编排确定性用例
        ↓
Apache SSHD 建立受信主机连接
        ↓
目标 Linux 上的固定 managed helper v7 协议
        ↓
候选构建/恢复、健康检查、提交或旧版本恢复
        ↓
桌面 SQLite 保存不含秘密的精确受管状态
```

产品不会把用户输入拼成任意 Shell。远端操作使用类型化 Java 契约和固定 helper 动词，SSH/SFTP 细节只存在于 Linux SSHD 实现模块。

## 4. 安装、运行与本地数据

### 4.1 运行模式

软件根据启动方式确定唯一数据基准目录，并在该目录下使用固定 `data` 子目录。CLASS/JAR 模式以 DB 模块的实际加载位置为准，APP 模式以启动器 EXE 为准：

| 模式 | 数据目录 |
| --- | --- |
| Maven/IDE CLASS | `src/app/db/data` |
| JAR | DB 模块 JAR（如 `DB.jar`）所在目录下的 `data` |
| jpackage APP | 启动器 EXE 所在目录下的 `data` |

软件不接受命令行、注册表、路径指针文件或界面参数覆盖数据目录，也不会失败后静默改用用户目录或临时目录。APP 模式应安装到当前用户可写的位置。

### 4.2 本地数据结构

```text
data/
├─ windowstolinux.db
├─ work/
├─ backups/
└─ error-logs/
```

- `windowstolinux.db`：服务器非秘密资料、应用图、当前发布、运行时、配置引用、资源绑定和操作历史；
- `work`：可重建的源码归档、备份取材和恢复候选工作区；
- `backups`：软件保留的正式备份，包括离线迁移的最终停写备份；
- `error-logs`：有大小和数量上限的 UTF-8 错误诊断报告。

实际部署应用的持久化文件、容器卷和数据库保留在目标服务器或对应数据库服务中；桌面端保存管理记录、操作工作文件和备份归档。

密码、API Key 和应用秘密值不以普通字段写入 SQLite。它们保存在 Windows Credential Manager 或由主密码保护的加密秘密存储中，SQLite 只保存不透明凭据键和精确秘密修订元数据。

## 5. 服务器管理

### 5.1 用户可执行的操作

1. 选择已保存服务器，或填写地址、用户名和密码新增；
2. 点击“保存并检查连接”；标识、SSH 端口和凭据存储方式在高级选项中调整；
3. 首次连接时人工核对主机指纹；
4. 采集发行版、版本、包架构、CPU、Java、Node、Python、容器、安全模块和防火墙事实；
5. 一键部署自动衔接受控环境准备；也可在服务器页高级区域单独检查；
6. 后续连接拒绝主机指纹静默变化。

服务器页和自动部署都会先确认系统工具及依赖的安装或更新，默认选中取消。DNF 9 会共同更新兼容的 OpenSSH 包，软件包脚本可能短暂重启 SSH；程序在安装后重新认证连接才能报告结果。

CentOS Stream 9/10 的 SELinux 未处于强制模式时，还会显示独立的系统变更确认框，默认选中取消。确认内容包括配置备份、文件标签修复、服务器重启及连接中断；批准后由程序完成准备、重连与强制模式登录验证，再继续安装工具。拒绝或关闭对话框不会执行对应变更；失败时保留准备状态以便再次确认后继续。该流程已接入，当前实机复核进度见[四期验收](development/PHASE-4.md#acceptance)。

### 5.2 实现机制

- 非秘密连接资料进入桌面 SQLite；秘密值进入独立秘密存储；
- 首次主机指纹只有在用户确认后保存，后续指纹不一致直接拒绝；
- `SshdLinuxGateway` 只提供类型化会话，不公开任意 SSH 命令或 SFTP 路径；
- 环境准备使用按发行版固定生成的脚本，并在变更前后复核 SELinux/AppArmor 和防火墙状态；
- SELinux 状态变更仅在独立确认的系统准备阶段执行；普通安装阶段仍保持安全策略，CentOS 安装固定构建工具时仅在该事务使用已配置的官方 CRB 仓库，不永久启用仓库；
- 当前 helper 协议版本必须精确匹配，不做静默旧协议回退。

## 6. 源码与 Git 输入

### 6.1 本地源码

软件只读取用户选定的源码目录做静态分析和安全归档，不在 Windows 主机执行项目脚本、构建插件、依赖安装或用户二进制。

### 6.2 Git 源码

软件可以从明确仓库来源创建固定 Commit 的源码快照。部署身份绑定所选 Commit 和内容摘要，而不是部署时再次读取可能变化的分支头。

### 6.3 实现机制

- `shared/source` 负责可重复源码快照、安全路径和归档；
- `shared/git` 只负责仓库来源和固定版本；
- 路径穿越、链接、特殊文件、超限成员和归档内容变化会停止流程；
- 源码归档只服务于目标机构建，不与应用数据备份格式混用。

## 7. 项目识别与类型化运行时

当前模型可以表达十四种恢复运行时：Spring Boot、普通 Java JAR、无依赖 Java 源码、Node.js、Python、静态站点、Docker/Podman 容器、Go、Rust、.NET、Kotlin、PHP、Ruby 和 CMake/C 服务。

软件根据锁文件、构建文件、入口、产物和声明端口等静态事实给出识别和支持结论。高级语言仍属于精确范围的试验适配，不应理解为支持该语言的所有框架。

实现上，每种运行时都有封闭类型，不使用任意“运行命令”字符串。构建参数、监听端口、健康检查、容器端口、卷和版本要求均经过对应领域类型校验。

## 8. 配置与秘密

### 8.1 普通配置

- 普通配置使用不可变修订；
- 值类型为文本、整数或布尔；
- 配置作用域明确区分构建期和运行期；
- 类似密码、Token、Secret、Key 的键不得伪装成普通配置；
- 每个发布绑定实际使用的配置 SHA-256，后续修改产生新修订。

### 8.2 应用秘密

- 秘密使用“标识 + 正修订号”引用；
- 发布只保存精确引用，不保存秘密值；
- 恢复归档中的秘密由独立备份密码加密；
- 解密值只存在于可清零缓冲区，使用完成立即清零；
- 同一标识的不同修订可以共存，不能用新值覆盖历史发布所需修订。

### 8.3 备份秘密加密

`secrets.enc` 使用独立备份密码，经 Argon2id（64 MiB、3 次、1 路）派生密钥，再用 AES-256-GCM 认证加密。随机盐和 nonce 写入公开信封，密码和派生密钥不写入归档。错误密码、密文篡改或载荷不完整使用同一失败关闭边界，不返回部分明文。

## 9. 单组件部署

### 9.1 操作流程

1. 在首页左侧选择源码目录或填写 Git 地址，右侧选择服务器；
2. 如需覆盖源码声明，展开高级选项调整；一般可以直接点击“一键部署”；
3. 仅在缺少信息、首次主机信任或高风险操作时回答弹窗；未配置 AI 不影响继续；
4. 查看持续日志，完成后复制访问网址或启动命令。

健康检查默认按项目识别；需要覆盖时可明确选择 HTTP 或 TCP，即使检查地址留空也保留该选择。源码侧的运行参数、DB 缺项和整应用健康代表组件会先补齐，再检查服务器；填写错误后在同一任务内修正并重新校验。运行期间输入和重复操作会锁定，外观切换需等当前操作完成。

### 9.2 实现机制

- 源码只上传到摘要绑定的远端候选工作区；
- 构建只发生在目标 Linux；
- 发布前保存旧发布快照；
- 配置和秘密修订封存在发布树之外的受管只读位置；
- 候选发布成功并通过健康检查后才成为当前版本；
- 任一步失败都尝试恢复旧发布并重新验证；恢复不可验证时返回 `MANUAL_RECOVERY_REQUIRED`；
- 成功后原子保存当前发布、完整运行时、配置、秘密引用、资源绑定和整应用图。

自动流程从源码声明或明确的 DB 清单识别数据库。无声明且无迁移标记时记录显式空范围；存在外部端点、冲突或缺项时补问，不静默改成服务器本地数据库。高级区域仍可手工提供已审阅连接及精确秘密引用。SQLite 物理映射尚未完成，不在新部署的 DB 选择器开放。

### 9.3 DB 自动管理

DB 直接安装到受支持服务器系统。已安装且兼容的 PostgreSQL、MySQL、MariaDB 或 Redis 优先复用；停止运行也算已安装。多个实例让用户选择，缺少管理或应用连接凭据时补问。程序不会将 MySQL 项目改成 PostgreSQL，也不会因为版本较新就卸载。

版本不兼容时，用户必须先自行备份，确认停机准备，并明确同意卸载旧软件、安装目标版本。授权绑定当前服务器、实例及版本，执行前再次复核。程序不清空数据目录、不替用户迁移数据；进入人工恢复等待状态后，由用户按数据库支持的升级路径恢复，再重新检查继续。安装完成不等于数据恢复完成。

版本无法识别时显示冲突并允许处理后重检，不按“未安装”继续。如果多个现有实例使整组软件包替换无法安全隔离，先提示用户自行处理，再重检；不会要求一份执行时必定被拒绝的替换授权。

可在源码根目录提供非秘密声明 `windowstolinux-db.properties`，例如：

```properties
db=main,cache
db.main.engine=POSTGRESQL
db.main.version=>=16
db.main.database=demo
db.main.username=demo_app
db.main.environmentPrefix=DB
db.main.passwordEnvironment=DB_PASSWORD
db.main.initialize=schema.sql,data.sql
db.cache.engine=REDIS
db.cache.database=demo_cache
db.cache.username=demo_cache_app
db.cache.environmentPrefix=REDIS
db.cache.passwordEnvironment=REDIS_PASSWORD
```

`initialize` 按给定顺序执行。Spring Boot 的本地 JDBC/Redis 声明也可识别；明确声明 `spring.sql.init.mode=always` 时，唯一的 `schema.sql` 先于 `data.sql` 执行。多个同名入口或不能确定的初始化方式需补填。生成的密码进入现有秘密存储，声明文件中不得写入密码。普通服务通过受保护的凭据文件注入 `*_PASSWORD`，使用 `*_PASSWORD_FILE` 时注入真实凭据文件路径。

多个数据库分别绑定自己的初始化文件，不能把一个库的 SQL 复制执行到其他库。已明确指定入口的声明按各库执行；需要补问时可为不需要初始化的库留空，但存在结构变更时必须至少明确一个 SQL 入口。Redis 不接受 SQL 初始化或 JDBC 数据源声明。高级连接绑定也必须覆盖源码声明的 DB 类型和范围。

自动初始化只适用于本次创建、归属可证明且再次检查为空的应用库，使用应用级权限。执行记录绑定 SQL 内容；已完成任务重试只验证，不重复写入。初始化失败或状态变化时停止并要求人工处理，不自动清除失败记录或重放 SQL。已有库结构变更需独立确认。经校验的 Spring 初始化完成后关闭框架重复初始化、Flyway/Liquibase 和 JPA 自动建表入口；本轮不提供任意迁移脚本执行器。

Redis 使用限定于应用前缀的账号，应用须按该前缀访问。隔离容器不能直接使用宿主 `127.0.0.1` 数据库，当前需在高级区域提供容器可访问的明确 DB 绑定。未知安装来源、无法确认的实例、残留配置或不支持的系统仓库版本会停止并说明问题。MongoDB 自动安装、Redis 完整备份和多数据库完整备份尚未提供；这些资源会被登记，完整备份入口明确拒绝，避免漏备后报告成功。

## 10. 多组件应用

首页自动识别多个项目目录并使用同一次源码快照。无法确定组件关系时弹窗补填，不任意选择依赖。高级区域可以进入手工编辑器调整组件及依赖；手工草稿仍要求每个组件显式审阅 DB 范围。软件在修改目标机前拒绝重复组件、端口冲突、未知依赖和依赖环。

部署顺序按依赖从前到后，停止和恢复顺序按依赖反向执行。每个组件有独立候选、快照、运行时和健康检查，整应用另有独立健康门。只有所有组件和整应用都成功时，SQLite 才原子记录整个新图；部分成功不会伪装成整应用成功。

## 11. 受管应用与生命周期

“已部署应用”页面可以查看软件已验证归属的应用，并执行：

- 刷新状态；
- 启动；
- 停止；
- 重启；
- 启用开机自启；
- 停用开机自启。

生命周期操作不接受任意 systemd 单元名或容器名，而是从已保存受管身份和运行时恢复上下文，再由目标机返回权威观测。桌面保存观测历史，但本地记录不能代替实时远端状态。

## 12. 完整备份

### 12.1 备份前置条件

完整远端备份要求：

- 已保存成功整应用图；
- 每个组件具有当前发布和完整已审阅运行时；
- 每个发布绑定精确普通配置和秘密引用；
- 文件与数据库范围已经明确审阅；
- 整应用健康检查已经独立保存；
- 应用最多包含一个受支持的数据库制品；
- 目标服务器资料和凭据仍与受管应用一致。

主备份操作自动检查已保存输入；高级区域也可单独执行该检查，它只读取桌面 SQLite，不连接服务器。即使结果完整，也只表示可以继续远端检查，不表示远端制品一定可创建。

创建备份前会确认一致性备份可能暂停应用写入并恢复原运行状态。恢复前会明确确认目标服务器、所选归档及替换已有受管发布的影响；取消确认不会启动操作。语言或主题切换会保留尚未提交的备份输入，操作结束后再允许切换。

### 12.2 备份内容

schema v4 归档可以包含：

- `manifest.json`：应用、组件、依赖、发布摘要、环境、数据库、健康和成员清单；
- 每组件发布树；
- 每组件精确普通配置、资源绑定、运行健康和用户访问 URL；
- 已审阅普通文件树；
- 受管容器命名卷；
- 经归属验证的 Podman OCI Archive，或恢复时所需已审阅源码；
- PostgreSQL、MySQL 或 MariaDB 一致性数据库导出；
- AES-256-GCM 加密的精确秘密修订集合。

当前自动完整备份明确限制为零或一个受支持的 SQL 数据库；Redis 或多个数据库绑定会在远端备份前明确拒绝。SQLite 连接模型和一致性适配器已经存在，但产品备份仍会因缺少已审阅的应用相对物理映射而在远端操作前拒绝。

### 12.3 远端一致性实现

1. 实时观察所有组件；
2. 按依赖逆序停止原先正在运行的组件；
3. 验证无写入者；
4. 使用 helper v7 创建严格 PAX TAR、命名卷、OCI 和数据库制品；
5. 每个制品流式下载到 Windows 受管工作区并独立复核大小、SHA-256 和格式；
6. 按依赖顺序恢复原来运行的组件；
7. 重新执行组件和整应用健康检查；
8. 清理精确远端操作目录；
9. 加密秘密并写入完整归档；
10. 在用户目标同目录写入私有临时文件，完整校验后无覆盖原子发布，并从最终路径再次独立校验。

远端制品生成成功、SFTP 传输成功或本地输入完整，任意一项都不能单独代表备份成功。

## 13. 本地归档检查与候选准备

用户可以在不连接服务器的情况下：

- 校验归档结构、成员数量、大小和 SHA-256；
- 分开查看内容完整性与可选 Ed25519 来源状态；
- 用独立备份密码认证 `secrets.enc`；
- 提取到新的隔离本地候选；
- 精确删除当前候选。

桌面一次只跟踪一个当前候选。删除授权绑定工作区签发对象和目录文件身份；重建对象、工作区外路径、链接或外部替换均不会被误删。应用重启后不扫描和猜测旧候选。

schema v3 可以检查、准备本地候选和做旧秘密标识认证，但由于缺少 schema v4 的精确发布及秘密修订绑定，不能自动远端激活。

## 14. 受管恢复

### 14.1 用户操作

1. 在备份页选择“恢复”任务和 schema v4 完整归档；
2. 从列表选择已保存目标服务器；
3. 输入独立备份密码；
4. 按所选凭据存储方式输入主密码；
5. 点击“恢复到目标端”，核对并确认目标、归档和覆盖影响；
6. 首次连接时核对主机指纹；
7. 查看远端恢复状态、本地接管状态和警告。

### 14.2 修改前检查

恢复在暂存远端输入前完成以下检查：

- 归档和全部成员再次完整校验；
- schema v4 发布、秘密、配置、资源、运行时和数据库身份完全一致；
- 目标主机 helper、sudo、tar、systemd、架构、发行版和类型化运行时能力满足要求；
- 正式端口无外部占用，或本地已有图证明是该目标拥有的同一应用；
- 目标受管根可写且至少具有两副本空间；
- 归属冲突和外部流量变更均为否；
- 数据库制品类型和版本身份可用于候选阶段。

数据库目标密码来自归档中的精确秘密修订。前置阶段不假装目标已有该秘密；秘密暂存后，数据库候选恢复阶段再执行真实连接、工具和版本兼容检查。

### 14.3 候选端口混合策略

- 容器：每个已审阅宿主端口自动映射到 `127.0.0.1:49152-65535` 中实时确认空闲的不同候选端口；
- 静态站点、PHP、Ruby：只覆盖已有类型化监听端口；
- Spring Boot、普通 JAR、Java 源码、Node、Python、Go、Rust、.NET、Kotlin、CMake：不猜测监听参数，进入短停机切换；
- 临时端口不写入正式配置、发布身份、SQLite 或备份清单；
- 绑定竞争或启动失败立即停止，不通过换端口重试掩盖问题。

### 14.4 提交和恢复顺序

1. 在摘要候选目录暂存并回读精确文件；
2. 暂存配置和精确秘密修订；
3. 暂存并恢复候选数据库；
4. 启动可并行的回环候选并完成组件/整应用预检；
5. 建立短停写边界；
6. 保存旧发布并停止旧服务；
7. 先提交数据库候选，同时保留旧数据库；
8. 恢复正式端口和正式服务身份，按依赖顺序启动；
9. 在正式端口重新执行组件和整应用健康；
10. 全部成功后提交发布身份并清理候选；
11. 任一步失败时，按“停止新正式服务 → 回滚数据库 → 恢复旧发布 → 复核旧组件和整应用健康”的顺序恢复。

恢复终态包括：

- `SUCCEEDED`：远端正式端口和整应用健康成功；
- `FAILED_EXISTING_PRESERVED`：失败但旧发布已完整恢复并验证；
- `MANUAL_RECOVERY_REQUIRED`：数据库、发布或健康恢复无法完整证明，必须人工处理。

本地接管状态与远端状态分开：若同一应用的源图仍绑定另一台服务器，远端可成功但本地状态为 `DEFERRED_SOURCE_RETAINED`，避免静默覆盖仍需恢复的源端控制记录。

当前 SQLite 物理恢复明确失败关闭，不会把数据库文件猜测复制到发布树。

## 15. 双服务器离线迁移

### 15.1 用户操作

1. 在备份页选择“迁移”任务并从列表选择源应用；
2. 从列表选择不同的已保存目标服务器；
3. 输入独立备份密码和凭据存储主密码；
4. 阅读停写窗口说明并明确批准；
5. 点击“准备离线迁移”；
6. 等待结果进入“可人工切流”、安全失败或人工恢复状态；
7. 只有目标就绪后，才在软件之外人工切换 DNS、反向代理或负载均衡；
8. 完成生产观察并另行作出删除决定前，保留源端和最终备份。

未批准停写窗口时，产品不会打开 SSH 或执行任何远端操作。

### 15.2 实现机制

1. 创建完整初始备份，备份结束后恢复源端原运行状态；
2. 使用初始归档对目标执行只读恢复前置检查，不暂存配置、秘密、发布、文件或数据库；
3. 按依赖安全顺序停止源端全部组件，并确认整体为 `STOPPED`；
4. 在源端保持停止时创建完整最终备份；
5. 最终备份 SHA-256 生成唯一目标候选身份；
6. 复用第 14 节同一恢复链，在目标正式端口完成最终健康；
7. 成功后源端保持停止但不删除，外部流量保持不变；
8. 最终停写备份保留在 `data/backups`；
9. 任一失败都尝试清理目标候选并重新启动、验证源端；
10. 目标清理或源端恢复任一无法验证时进入 `MANUAL_RECOVERY_REQUIRED`。

迁移成功终态固定为 `READY_FOR_MANUAL_TRAFFIC_SWITCH`。软件不会自动修改 DNS、代理、负载均衡，也不会自动停用或删除源端。

### 15.3 当前接管限制

为避免同一个全局应用标识同时静默归属两台服务器，目标成功而源图仍保留时，桌面不会自动覆盖源图。本次迁移结果会明确显示延后接管状态；人工切流后的持久化接管流程仍需后续专门设计。在该流程完成前，应保留最终备份和源服务器，不要把“目标已健康”理解为“桌面已永久改绑目标”。

## 16. 可选 AI 功能

AI 只用于对脱敏静态事实生成解释或建议，不参与确定性准入、部署、备份、恢复、迁移、回滚或安全结论。

- 可以配置命名的 OpenAI 兼容 Provider 和模型；
- 固定角色可绑定不同 Provider；
- Provider 失败不会静默切换到另一个 Provider；
- API Key 进入秘密存储；
- AI 不获得 SSH、文件写入、部署或生命周期工具；
- 未配置 AI 不影响核心功能；
- 自动部署缺项优先请求结构化建议，只自动采用唯一源码候选且校验通过的非秘密值；其他缺项合并到表单；
- 表单右侧可展开 AI 问答；未配置时可打开 AI 配置并保留表单，超时或错误建议退回人工填写；
- AI 不能代填密码、批准卸载或执行命令。

## 17. 诊断、错误与人工恢复

每个模块拥有自己的结构化失败类型，并通过最小公共失败契约向界面传递：错误码、阶段、用户消息、严重级别、建议恢复动作、操作标识和安全诊断。

界面不直接显示原始异常消息。诊断报告会脱敏并限制单份大小、总份数和写入位置。密码、Token、私钥、秘密值、第三方响应正文和未脱敏远端输出不得进入报告。

出现 `MANUAL_RECOVERY_REQUIRED` 时：

1. 不要删除源端、旧发布、旧数据库、候选目录或最终备份；
2. 记录操作标识、失败码、失败阶段和已经验证的恢复步骤；
3. 检查目标组件、正式端口、当前发布指针和数据库旧/新身份；
4. 在确认产品不能继续前，不使用任意命令替代产品路径并声称验收成功；
5. 根据诊断证据制定一次明确的人工恢复操作。

## 20. 建议的首次使用顺序

1. 把软件安装或解压到当前用户可写目录；
2. 启动后确认 `data` 目录初始化成功；
3. 在服务器页保存一个专用测试服务器并核对 SSH 指纹；
4. 在首页选择最小示例源码和该服务器；
5. 点击“一键部署”，回答缺项或首次信任弹窗，等待日志和结果；
6. 在“已部署应用”中刷新状态并验证启动、停止和重启；
7. 明确审阅配置、秘密、文件/数据库绑定和整应用健康；
8. 创建完整备份，并另行保存一份不覆盖的备份副本；
9. 在专用目标服务器执行恢复实机验收；
10. 最后在两台专用服务器执行离线迁移验收，目标就绪后只做人工流量切换；
11. 只依据对应 helper 版本、夹具和环境的实际验证判断能力，不将代表样例或本地测试外推到生产全场景。
