## 1. 本期目标与承接关系

四期为已受管应用增加数据库与数据一致性、版本化备份、恢复和离线跨服务器迁移，并完成供后续正式上线复用的 Windows 更新/卸载安全核心。生产更新/卸载执行器、官网和发布下载链已经明确移入六期，不再作为四期完成条件。备份能力服务于恢复和迁移，但“生成归档”“校验归档”“恢复文件”“运行验证”必须是不同状态。

本期在三期的生态和多组件基础上，追加一体化桌面部署、AI 缺项补全、原生数据库管理、动态工具链、临时构建与独立运行身份，以及模块职责和失败契约修正。生产官网、正式发布下载和 Windows 独立维护执行器仍归六期。

沿用现有 Java 21、Swing、FlatLaf、主题和中英文机制，将桌面工具改为面向新手的一体化自动程序。用户选择源码和服务器后，一次启动完成常规部署，不再逐步点击分析、检查、环境准备和发布。单应用与多组件共用首页及现有部署事务、失败恢复和持久化机制。本期不开发 Web 业务。

### 追加开发：FHS 目录与 SQLite（2026-09-19）

状态：FHS/SQLite 实现及本地完整门禁已通过；新布局实机矩阵全部为 `RUNTIME-PENDING`。以下规则对应本次实现，不将历史 helper v7 的验收外推到 v8。

- 程序发布根改为 `/opt/windowstolinux/apps/<受管标识>`，默认配置根为 `/etc/opt/windowstolinux/apps/<受管标识>`，默认文件与 SQLite 根为 `/var/opt/windowstolinux/apps/<受管标识>`。多组件保留现有独立受管标识。工具工作区、事务记录、备份暂存和服务器数据库内部目录保持原职责。
- 位置区分默认、自定义和未确定。自定义绝对位置必须是当前应用安装根的严格子路径，不能占用发布/管理目录；相对业务路径保持应用访问方式并映射到应用根内 `persistent`。越界、链接逃逸、冲突或无法确定时明确拒绝/补填，绝不回退默认目录。
- 路径计划由共享层形成，桌面和 Web 共用；资源绑定记录访问路径、实际目标、来源和权限，发布前展示并在远端执行前复核。默认配置只读，已有数据不被发布覆盖。
- 原生服务使用独立不可登录的固定服务账号及精确可写目录；取消动态 UID 和 `/var/lib/private` 依赖。容器保留内部路径，通过受控宿主目录 bind mount 落盘，宿主边界规则与原生一致；非 root、只读根和临时目录隔离保持。
- SQLite 作为文件数据库接入识别、清单、补填、原生与 Docker/Podman 部署；不要求端口或凭据。默认文件为 `application.db`，支持已审阅种子与初始化 SQL，已有数据库不重复初始化。
- SQLite 使用一致性备份 API 和完整性检查，普通文件归档排除数据库及伴随文件。候选恢复必须隔离正式数据，提交前停写，在目标文件系统内切换并保留原库，失败时验证回退。完整备份仍至多一个受支持数据库。
- 升级 helper、资源及备份格式，不迁移旧目录、不兼容旧路径、不转换旧备份；旧布局明确拒绝且不自动删除。保留客户端已有资料。
- 验证顺序：共享契约/序列化/helper 离线测试、相关 Java/Web 门禁、全量门禁，再在干净 Ubuntu 24/CentOS Stream 9 覆盖原生、Docker、Podman 和双机恢复迁移。未执行项目继续 `RUNTIME-PENDING`。

#### 外观与输入控件

- 浅深主题、Lucide 图标和圆角卡片共用外观；导航按部署、服务器、已部署应用、备份、AI 组织，设置置底。展开/收起宽度为 168/64，分隔线在动画期间保持显示。
- 主页面高级入口位于顶部栏右侧，按当前页面绑定展开、修改提示和帮助。通常扩展窗口宽度 320 像素，空间不足时使用独立浮窗；关闭后恢复工作区。最大化和普通还原尺寸分开保存，语言/主题重建保留偏好。
- 源码与目标采用等宽卡片及居中方向箭头。源码选中后在选择区显示地址并隐藏输入，拒绝直接替换；清除后才可重选。目标也只能选一台，清除后后台刷新不自动选中。卡片随内容等高，不用固定总高度压缩选择区。

- 服务器和应用搜索、筛选、操作按钮基础高度至少 36 像素并跟随缩放；最小窗口日志高度至少 200 像素。

#### CLASS 模式界面调试

“设置 → 高级选项 → 界面调试”仅在 `RUN_CLASS` 装配；JAR、APP 和未知模式不显示，不增加持久化开关。调试窗口可导航七个主页面并预览服务器、AI、应用、缺项、秘密、指纹、环境、数据库、风险、备份恢复和错误弹窗。

弹窗复用现有 UI 和消息目录，使用固定示例及隔离服务，不连接服务器、调用真实 AI 或写业务/凭据存储；主页面导航仍进入实际工作区。窗口跟随主题和语言，关闭或重建主窗口时回收。预览只验证界面，不作为远端功能验收。

### 3.2 一体化单应用与多组件部署

**涉及模块与分工：** `app/service.deployment.automatic` 统一编排；共享分析、计划、事务和远程执行复用已有类型化契约。

代码路径：[DesktopApplicationFacade.java](../../src/app/service/src/main/java/gold/debug/windowstolinux/app/service/DesktopApplicationFacade.java) 的 `deployAutomatically` → [AutomaticDeploymentUseCase.java](../../src/app/service/src/main/java/gold/debug/windowstolinux/app/service/deployment/automatic/AutomaticDeploymentUseCase.java)。获取服务器操作锁，固定本地/Git 快照，发现组件、补齐及校验输入，验证受信服务器，再选择单组件或整应用事务。自动准备数据库和环境仍受审阅与批准约束；最终状态来自事务结果。

环境准备与语言版本选择遵循[动态工具链](#toolchains)。单/多组件及 DB 参与流程传递相同的版本需求和解析结果；安装、源码或运行失败保留实际原因，不能统一改为版本不支持。

流程：固定源码快照 → 识别应用及组件 → 补齐信息 → 检查服务器 → 准备运行环境和数据库 → 构建、初始化、启动 → 健康检查 → 展示结果。

应用服务层新增统一编排入口；UI 仅收集输入和呈现进度。复用类型化分析器、部署计划、远端固定协议、失败恢复与受管持久化，不创建第二套部署引擎。项目清单、声明、已有运行时建议是识别入口、端口及组件关系的依据；多个候选或冲突不得任意选择。

点击“一键部署”授权本次常规环境准备和发布，首次主机信任及数据库替换等高风险操作另外询问。指纹变化继续拒绝。后台执行不得阻塞 Swing 事件线程；重复点击不能发起重复任务。任务期间固定输入，补齐后重新校验并继续同一次任务，取消停止后续步骤。

#### 缺项处理

1. 静态部署在服务层禁止 AI 调用，缺项由确定性表单补齐。
2. 半 AI 仅在固定节点请求结构化建议，只自动采纳唯一、有依据且校验通过的非秘密候选；不可用时由用户明确选择人工继续。
3. Agent 将分析、输入、环境、事务等类型化动作送入独立本地与 AI 审批边界，实际执行仍由原有服务承担。
4. 参数表单只收集缺项，不再在独立线程内展开隐式 AI 问答；模型测试仍可在配置页单独使用。
5. 失败、取消、未知结果和等待人工分别表达；失败不能显示成功入口。

最小接口：统一部署请求与结果、缺失字段与回答、结构化 AI 建议及问答、服务器列表、真实阶段进度通知。所有数据继续通过现有类型、路径、资源归属与秘密边界校验。

<a id="ai"></a>

### 3.3 AI 用途、缺项补全与确定性复核

`app/service/ai` 负责配置验证、用途路由和不可变任务快照，`shared/ai` 提供建议、部署决策、独立审批三种受限协议。静态任务不调用这些协议；半 AI 仅在固定分析、预检和失败节点调用建议协议。预检位于任何环境或数据库变更之前，并包含实际服务器观察、运行身份、健康约定、组件依赖、数据范围和配置摘要。

半 AI 只自动采用唯一且有证据的非秘密候选，剩余输入由表单补齐。网络或协议错误耗尽部署用途后，明确询问是否人工继续；用户拒绝即取消，不静默退回静态。失败解释使用实际失败阶段及有界脱敏诊断片段；不会执行模型提出的修复命令。敏感值、完整源码和完整原始上下文不进入请求或任务记录。

模型库采用 v18 的独立显示顺序、用途成员/顺序/启用和文字/视觉验证修订。AI 页面默认全宽库存，右侧用途入口在本页展开等宽双栏，左右箭头管理成员，拖动/上下按钮或 Alt+方向键排序。库存始终完整，显示顺序不参与调用；用途草稿保存时原子提交，取消丢弃，失败保留。修改端点、模型或凭据使相应测试失效，文字与视觉需分别通过。新密钥使用不可变引用，编辑不改变在途任务。

部署、审批、视觉按各自冻结顺序串行调用，不跨用途回退。旧常规/视觉分别迁入部署/视觉，审批留空；固定旧角色绑定只保留迁移数据，不控制 App 调用。有效拒绝不切换审批模型。Agent 的审批矩阵、预算、生命周期和未知结果限制见[三模式](#agent-modes)，用户操作见[产品手册](../PRODUCT-MANUAL.md#16-app-部署模式与模型用途)。

### 3.4 数据库识别、准备与管理

**涉及模块与分工：** `shared/analyze` 提取声明，`shared/model` 表达需求与审阅；`app/service` 补全认证、审批和保存绑定；`shared/linux-sshd.execution.protocol.database` 执行原生数据库协议。

现行入口：[AutomaticDatabaseUseCase.java](../../src/app/service/src/main/java/gold/debug/windowstolinux/app/service/deployment/automatic/AutomaticDatabaseUseCase.java)，由桌面门面调用并把 `NativeDatabaseException` 转为应用服务失败。凭据标识的 SHA-256 用作内部合法键段，外部秘密引用和修订保持原义。数据库安装/复用、版本替换与结构变化必须分别确认；数据库可准备不代表完整备份可用。

#### 结构与范围

DB 的模型、分析和远程契约仍使用 `ecosystem.db`；SSHD 固定执行实现归 `execution.protocol.database`，两个 native helper 片段归 `execution/protocol/helper/fragments/database/`。该规则替代早期四模块统一套包及 SSHD 根 `db` 布局，不调整其他共享模块或 `build.ecosystem`、`capability.ecosystem`。数据库仍不属于语言构建或桌面本地 SQLite 存储。以下分类适用于保留技术生态层的模块：

- `ecosystem.db.sql`：PostgreSQL、MySQL、MariaDB。
- `ecosystem.db.document`：文档型分类；本轮不实现 MongoDB 自动安装，也不创建空适配器。
- `ecosystem.db.other`：Redis。

分析、领域模型、Linux 契约和 SSHD 执行分别留在既有对应模块，遵循功能分组规范，不新增独立 Maven 模块。

#### 检测、安装与复用

默认直接安装到所选服务器系统，使用受支持发行版的固定适配，不默认使用容器。

| 服务器状态 | 行为 |
| --- | --- |
| 已有同类型且兼容版本 | 复用，不重新安装；缺少连接/管理凭据时弹窗 |
| 已安装但停止运行 | 检查现有实例，不认定为未安装 |
| 多个实例 | 弹窗选择复用目标 |
| 已有版本不兼容 | 暂停，展示现有版本、项目要求及替换影响 |
| 未安装所需类型 | 安装兼容版本，创建应用数据库/账号或 Redis 访问配置 |
| 类型冲突、来源或版本不明确 | 说明并询问，不静默替换 |

版本优先遵循项目声明。未声明时优先复用已安装兼容版本，否则使用适配器支持的系统仓库版本。不得自动替换数据库种类，不把较新版本简单视为不兼容。生成的凭据通过现有秘密存储保存，仅将引用注入配置；不得进入日志或 AI 上下文。

#### 用户批准旧版本替换

- 备份由用户自行完成。必须确认已备份、已做好停机准备并明确同意卸载旧版、安装目标版。
- 审批绑定服务器、实例及版本组合，执行前重新检查；事实变化使审批失效。
- 不自动清空旧数据目录，不自动恢复用户数据。需要恢复时等待用户恢复，再检查并继续部署。
- 替换软件包与恢复数据是不同状态，不得显示“安装完成”等于“数据恢复完成”。安装和升级受数据库支持路径限制：[PostgreSQL](https://www.postgresql.org/docs/current/upgrading.html)、[MySQL](https://dev.mysql.com/doc/refman/8.4/en/upgrade-paths.html)。

#### 新库初始化与已有库保护

- 只对本次创建、归属明确、可证明为空的应用库自动初始化。
- 支持明确选定的 SQL 初始化文件和受支持运行时中声明的初始化入口；无法确定入口时补问。
- 现有源码迁移标记全局拒绝改为结合目标库状态及初始化计划判断，不能简单移除安全检查。
- 初始化使用限定于应用库的权限，保存执行记录；失败重试不得重复初始化已有数据。
- 已有库结构变更需独立确认，不能冒充新库初始化。
- Redis、多数据库依赖均进入资源清单。现有备份无法覆盖时明确拒绝“完整备份”，不得遗漏资源后声称完整。

#### 职责与扩展接口

#### 单一支持目录

`shared/model` 使用独立、只读、类型化的纯 Java 工具链目录，按生态组织分支、发布类型、维护状态、安装方案标识和必要兼容约束，不增加配置解析依赖。它是构建支持范围唯一来源。分析器、领域运行时、脚本和 helper 不再分别维护版本白名单。

版本数据与行为分离：同一安装或构建适配器服务多个版本，不为每个版本创建类。上游改变命令参数、制品格式或兼容约束时，才增加对应生态的实际行为分支。目录只引用已实现方案，不接受任意脚本或命令模板。

最小契约：

- `ToolchainRequirement`：原始声明、来源、解析后的要求和用途。
- `ToolchainSupportCatalog`：允许使用的分支、候选选择及兼容约束。
- `ResolvedToolchainSet`：实际精确版本、可信安装位置、来源证据、目录修订标识。
- 环境准备契约接收需求并返回实际选择和重新探测结果。

版本解析及比较按生态处理，不能用一个 SemVer 正则替代 Java `8u`、Go 最低版本、Rust channel 等语义。数字排序不得使用字符串字典序。

#### 模块与远端边界

模型归 `shared/model`，声明解析归 `shared/analyze`，匹配及尝试编排归 `shared/deploy`，窄远程契约归 `shared/linux`，探测、安装及脚本归 `shared/linux-sshd`。工具链按实际功能组织；不新增 Maven 模块。具体目录同步 `File.md` 及架构门禁。

APT/DNF 和各发行版类负责系统依赖及操作系统差异。helper 使用准备阶段生成的可信受管工具链记录，继续检查固定动词、参数类型、路径、文件归属及不可变发布身份，不以放宽高权限边界实现扩展。

#### 识别、选择和兼容尝试

识别阶段保留所有合法版本声明，包括过旧、未来、非 LTS 和预发布版本；不受构建清单限制。复杂表达式无法确定时保留原文、来源和待补项，不执行项目脚本来猜版本，不让 AI 决定支持范围。

分别记录构建工具运行版本、编译目标、应用运行时。Java 需识别 `1.8`、`8u` 及正式主版本；Go 保留补丁要求并区分 `go` 最低版本和 `toolchain`；Rust 读取编译器、edition/MSRV；.NET 区分 SDK 和目标框架。原始声明不得被替代结果覆盖。

候选规则：

1. 要求在清单内且可满足时直接选择。
2. 清单外要求选择不低于声明的最近受支持分支；确认兼容性失败后最多再尝试一个更高分支。
3. 没有更高候选或兼容候选耗尽，返回版本不支持，并列出要求、尝试和原因。
4. 网络、权限、安装、源码错误和运行失败分别呈现，不统一改写为版本不支持；此类失败不触发无关版本轮试。

尝试只允许受控覆盖工具链选择，不修改源码、项目依赖锁文件、目标框架、字节码目标或语言标准，不进行自动代码迁移或依赖升级。防止 Wrapper、Gradle toolchain、rustup、Go 等在构建时隐式切换到清单外版本。

#### 准备、构建、运行和恢复

#### 安装与复用

优先复用已有发布锁定工具链，其次复用满足要求的受管或系统工具，缺失时从官方来源安装。JDK 使用 Temurin；Node、Go、Rust、Kotlin、.NET 使用官方发布；CMake、Ninja 与 C/C++ 系统编译器沿用发行版系统依赖。Python/PHP/Ruby 没有合适官方二进制时允许官方源码构建。

从官方元数据解析精确版本、制品及摘要；下载前固定身份，下载后校验。无可验证制品、系统依赖无法满足或需要未经审阅补丁时明确失败，不静默替换版本。安装采用独立受管前缀和原子完成标记，保留系统默认命令和库。历史工具链的私有依赖不得覆盖系统库。

准备具有有界超时、资源限制、真实阶段进度、并发安装互斥和取消清理；失败保留已存在的可用安装与应用，删除本次半成品。重复准备使用安装记录并重新核验工具版本。

#### 产品链路

本地输入校验 → 主机/发行版检查 → 合并组件需求 → 按需准备 → 重新探测 → 固定工具链构建 → 候选启动 → 健康检查 → 提交和保存绑定。

手工、自动、单应用、多组件及 DB 参与的流程复用同一解析结果。缺少可准备工具不再提前归为最终不支持。单独的服务器环境准备负责基础设施，项目语言工具按需求准备。

构建和服务启动使用相同解析结果及明确路径，多个应用可并存不同版本。JDK 8 适配实际支持的 javac/jar 参数，不套用新 JDK 的 `--release`、`jar --date`。Maven/Gradle、npm/pnpm/Yarn、pip/Poetry/uv/Pipenv、Composer/Bundler 按项目锁文件及选中运行时验证，不统一安装最新版。

构建成功后仍需验证启动、运行时依赖及健康检查；例如使用新 .NET SDK 编译旧目标，不代表旧目标能在 LTS 运行时运行。

#### 绑定与兼容

精确版本、可信来源及选择理由随发布保存，贯通重启、回滚、备份和恢复。目录更新不得重新解析或改写现有发布绑定。跨服务器恢复重新定位或准备工具链，不复制源服务器绝对路径语义。

当前使用 helper v9、桌面 SQLite v16、运行时与备份激活配置 v5、资源载荷 v2。旧运行时和资源格式明确拒绝，旧布局不迁移也不删除；客户端数据库不自动清空。

#### Kotlin 专属清理

本期已移除 Ubuntu 24.04 专属补装调用、强制 Kotlin 检查，以及固定 2.0.21 下载、摘要、路径和宽泛选择回退。并已接入按项目要求运行的通用 Kotlin 准备，不把旧特化搬到其他发行版类。

直接 kotlinc 路径选择对应编译器；Gradle Kotlin 路径按插件和 Wrapper 组合验证，不强制安装系统 kotlinc。JVM 目标单独检查编译器能力。保留历史实机记录并标明其背景，工具链准备不卸载服务器已有编译器。

#### 安装完整性与构建环境

- 官方 Java 身份使用 `version_data.openjdk_version`，仅规范稳定 `-LTS` 和 Java 8 别名，保留四段版本及构建号；不把供应商 semver 直接当 OpenJDK 版本，不放宽预发布准入。
- 受管根与 versions 目录先检查 root 归属、非链接及不可被其他用户写入，再规范为 0755。安装收尾和复用时，真实目录及可执行文件为 0755、公开普通文件为 0644、完成标记为 0444；不改秘密、下载目录或链接目标。
- `ToolchainBuildEnvironment` 在实际构建身份下核验绑定命令的解析路径及可执行性；Java 同时核验 java/javac/jar，禁止 PATH 静默回退。C/C++ 使用实际采集的系统编译器能力。
- 缺失的 Pipenv/Poetry/uv 在候选卷 `mutable/home` 的独立工具 venv 中从官方 PyPI 安装固定版本；只接受 wheel，不写系统 Python、不混入应用 `.venv`。工具引导解释器不足时明确拒绝，不偷偷升级项目解释器。固定版本及引导要求以当前 Renderer 为准。
- pnpm 使用冻结锁文件、hoisted/copy 部署依赖布局并禁止生命周期脚本；npm `.bin` 只转换已验证位于依赖树内的可执行链接，其他链接继续拒绝。uv 使用精确基础解释器与显式应用 venv，禁止下载或替换 Python；保留无链接封存检查。
- Kotlin Gradle 分发、锁及解压缓存位于候选 `mutable/home`，仅改 Wrapper 副本的本地分发位置并校验官方 URL/SHA-256。公共 JDK 初始化不重复写入已经匹配且冻结的 languageVersion；不匹配且不可调整时拒绝。

JVM 构建按用户资源上限生成堆、元空间、压缩类空间和代码缓存约束，避免默认虚拟内存预留使受限 javac/jar 无法启动。故障触发、修复及实机范围见[工具链验收](#acceptance-toolchains)。

<a id="isolation"></a>

### 3.6 构建隔离、运行身份与资源恢复

**涉及模块与分工：** `shared/deploy` 拒绝 root 构建请求并组织事务；SSHD 工作卷和运行协议实施边界；配置及持久化记录精确身份。

现行门禁：[ReviewedDeploymentService.java](../../src/shared/deploy/src/main/java/gold/debug/windowstolinux/shared/deploy/execution/transaction/ReviewedDeploymentService.java) 在远端修改前拒绝 `runAsRoot` 或非 root 管理连接。普通构建使用 DynamicUser；容器构建使用临时账号和受限 UID/GID 映射；普通运行与构建身份独立，容器应用显式使用非 root 用户。代表性部署已实测，完整资源攻击/UID 复用/故障注入矩阵仍未执行。

root 负责环境、发布和生命周期管理。普通构建使用 systemd 动态身份；容器 rootless 构建使用任务专属临时账号及 UID/GID 授权，完成后撤销。原生应用使用每组件固定、不可登录、无管理权限的系统账号；容器应用必须明确以非 root 身份运行。构建临时身份不持有 sudo、登录权限或永久应用归属，不删除用户已有账号。应用运行账号随其数据保留；数据库等系统包自带服务账号遵循其安装机制。

源码上传前预留固定容量 ext4 构建卷，挂载在既有候选 mutable 路径，缓存、日志、临时文件和容器构建存储均受限。收尾验证进程退出、制品封存、挂载和 loop 设备释放、临时账号与映射删除；失败隔离残留并明确报告。运行状态由本应用 FHS 数据目录或受限自定义目录承载，使用固定不可登录服务账号；秘密保持专属只读交付。旧布局明确拒绝，不迁移或删除数据。

当前代码版本为 helper v9、桌面 SQLite v16、运行时与备份激活配置 v5、资源载荷 v2；旧布局及旧载荷拒绝，不猜测缺失的路径绑定。SSH 标准指纹仅在已认证的同一公钥证据下迁移。工具链精确版本必须包含构建号。发布成功但清理失败须登记实际发布并报告待清理项。

旧容器迁移先验证停止，保存数据布局与权限快照，再按明确受管范围调整；失败恢复旧状态。保留已存在账号和用户数据，不能将“低权限构建”表述成能证明任意不可信代码绝对安全。

#### 容器构建与封存约束

- 容器源码在候选目录以局部 umask 022 解包并保留执行位，使明确非 root 用户可读；普通构建保持原掩码。容器容量由 root 预留的 ext4 卷约束，不要求项目用户遍历映射身份的引擎存储。
- Ubuntu 的用户命名空间预检只复用已加载的固定 rootlesskit/podman AppArmor 配置；缺失时继续探测或拒绝，不关闭安全模块或更改 sysctl。
- 容器引导保留 ProtectProc=invisible，开放引擎必需的非进程 proc 信息并保护内核接口；普通构建仍使用 ProcSubset=pid。引导权限上限仅为受信 setuid 映射工具提供所需能力，不设置 AmbientCapabilities；项目入口有效权限为零并禁止后续提权。设备仅额外开放 `/dev/net/tun rw`，不授予 mknod。
- 引擎 socket/runroot/exec-root 使用映射到候选卷的独占 `/tmp/wtl-engine`。RootlessKit 子命名空间只处理固定宿主运行路径的 copy-up 链接，不改宿主 `/run`；仅可信引擎 PATH 包含系统 sbin。
- 引擎就绪须实际响应有超时的 version 请求，最多 20 次；失败返回固定原因及末尾最多 4096 字节日志，受总输出限额约束，不重试项目构建。
- Podman 导出只流式移除精确指向清单内普通层文件的旧格式别名，随后仍执行无链接归档校验；构建、导入、发布及清理使用统一的精确候选标签。查询失败、错误归属和不明成员继续拒绝，清理不得删除发布标签。
- 封存重新设置 root 归属、文件权限并清除继承 ACL。候选与原发布摘要相同的回滚不能删除原发布。首次发布前允许尚未创建应用根和 releases，但已有目录仍校验归属及链接，同名容器或 Quadlet 冲突拒绝自动清理。引擎标签模板遵守原始转义规则，修复查询不改变标签值和归属检查。容器失败原因和两种引擎的独立实机结果见[隔离与容器验收](#acceptance-isolation)。

<a id="security"></a>

### 3.7 源码、网络与秘密处理

**涉及模块与分工：** `shared/source` 排除敏感源码，`shared/git` 管理子进程；`shared/ai` 限制模型输入输出，SSHD 校验传输、SQL 客户端和发布权限。

当前实现排除 `.env.*`、私钥和凭据类文件；源码仍需经安全快照与摘要校验，不能直接提交任意本地目录内容。Git 超时和中断需要终止子进程并清理本次工作区，清理失败保留原始失败及附加诊断。

SSH/AI 接收具有大小及时间边界；AI 仅接收必要脱敏事实。SQL 客户端、发布目录和秘密交付遵守各自的权限边界，不把密码写入普通日志或持久化配置。旧 SSH 指纹只在认证同一公钥后迁移成标准表示，不以格式变更绕过信任确认。

相关修复的本地记录及具体测试范围见[综合回归](#acceptance-local)；不能据此声称所有网络、数据库或攻击场景已实测。

原生 DB 客户端使用固定 `/usr/bin/python3 -I` 和可信工作目录；备份 SQL 客户端在动态低权限单元执行，禁用本地命令与文件导入，凭据按单元经 LoadCredential 交付。AI 在接收中限制 512 KiB；SSH 合并输出超限即失败并关闭通道。大脚本经标准输入和 `bash -s` 传输，安装命令组隔离其标准输入，避免 Linux 单参数上限及安装器误读后续脚本。

不可变配置按规范内容摘要及 SQLite 毫秒时间比较，避免键顺序或纳秒精度误判；仍拒绝实际内容和存储时间变化。成功应用登记后再保存首次观察，远端发布成功与本地登记失败分别报告。

<a id="lifecycle"></a>

### 3.8 生命周期、发布结果与连接收尾

**涉及模块与分工：** `shared/linux-sshd` 复核 unit、进程和控制组；`shared/deploy` 保留真实发布结果，服务层完成持久化；`app/main` 仅调整测试侧 NIO 收尾。

显式 STOP 在确认受管 unit 仍 loaded、MainPID 为 0 且控制组为空后，才可清除该 unit 的 failed 标记并重新查询。LoadState、控制组、停止结果或 reset-failed 查询失败都返回失败，不能把未知当成停止成功；不执行全局 reset-failed。

发布身份已经确认但版本保留或候选清理失败时，保持已发布事实并报告待清理项；不把成功发布隐去或伪装成已回滚。服务状态必须来自远端观测，SQLite 缓存不代替当前事实。

Windows NIO 修复仅针对验收用 SSH 服务的 accept/执行器关闭和异常归集，生产 SSH 客户端没有因此改动。原始失败和 suppressed 收尾失败同时保留。确切 Yarn 复验与本地 NIO 证据见[生命周期验收](#acceptance-lifecycle)。

### 3.9 模块职责、协议与失败契约

**涉及模块与分工：** `shared/linux` 只依赖 `shared/model`；deploy 负责配置投影；平台服务负责表单交互、凭据与持久化，纯运行时和配置解析分别复用 `shared/deploy/input`、`shared/config/input`；SSHD 的原生数据库归执行协议。

Linux 会话直接返回已有备份、恢复和数据库端口，移除重复转发。运行流程归 runtime，工具链构建诊断归 build。原生 DB Java 实现位于 `execution.protocol.database`，native helper 资源位于 `execution/protocol/helper/fragments/database/`；SSHD 不再使用根 db 或根 ecosystem 布局。

失败枚举登记、中英文消息和异常 `FailureCarrier` 保持一致，服务层显式转换六类原生 DB 原因。模块 POM、生产引用、包节点与规划标记由现有架构门禁核对。结构声明遇到代码冲突时以代码和适用实际行为修正文档，不倒改实现。

当前协议为 helper v9、桌面 SQLite v16、运行时及备份激活配置 v5、资源载荷 v2，备份 manifest schema v6。版本应分别读取各自定义，不能混为一个“项目 schema”。

<a id="backup"></a>

### 3.10 备份输入、归档格式与一致性

**涉及模块与分工：** `shared/backup` 定义归档和一致性；`app/db` 保存精确输入，`app/secret` 处理秘密，`app/windows` 管理材料及最终文件；服务层调用远程取材。

真实产品链：备份页 → 桌面门面 `createManagedBackup` → [RemoteBackupCreationUseCase.java](../../src/app/service/src/main/java/gold/debug/windowstolinux/app/service/backup/RemoteBackupCreationUseCase.java) → Linux 备份/数据库窄端口。当前 [BackupConfigurationCodec.java](../../src/shared/backup/src/main/java/gold/debug/windowstolinux/shared/backup/format/BackupConfigurationCodec.java) 写激活配置 v5，运行时编码器也为 v5。SQLite 保存受管物理绑定并使用独立一致性制品；多数据库超出归档单数据库范围，Redis 等管理能力不能推导为已有一致性备份。

#### 备份输入

备份开始前必须形成结构化数据清单：当前发布清单、普通配置快照、密钥引用元数据、持久化文件/卷、数据库类型与连接引用、运行身份、系统服务/容器定义、语言运行时、目标架构和恢复步骤。

未知路径、共享目录归属不明、外部数据库没有受支持导出方式或应用无法进入一致状态时，停止备份并说明缺失项；不能用直接复制伪装一致性备份。

桌面 SQLite v15 只从成功部署时仍持有的已审阅请求保存完整非秘密运行时定义、文件绑定、数据库绑定和独立整应用健康探针，并在同一成功事务中把实际使用的不可变普通配置修订及秘密引用与发布身份精确绑定。多组件文件绑定从 `ComponentDataPath` 形成稳定标识；发布时 helper 将其绑定到固定 Linux 受管根，逻辑源码路径只作为发布内符号链接位置，不会变成任意远端路径。数据库审阅支持 SQLite、PostgreSQL、MySQL 和 MariaDB：服务器数据库只保存端点、库名、用户名、TLS 要求和精确密码 `SecretReference`，绝不保存密码值。SQLite 保存文件名、默认/自定义宿主选择、应用访问路径、种子和初始化清单；所属组件与绑定共同确定物理位置，完整备份通过宿主工具生成一致性制品。数据库状态区分未知与显式空集合，绑定变化进入发布身份摘要。v10 及更旧整应用健康字段保持缺失；v9 及更旧资源字段保持缺失。

自动部署以源码声明、DB 清单、确定性校验和必要补填形成已审阅资源范围；已有数据库优先复用，替换和已有库结构修改分别明确确认。没有 DB 声明及迁移标记时记录显式空范围。高级手工单/多组件表单仍默认“尚未审阅”，必须明确选择无 DB 或连接绑定。Redis 增加非秘密资源序列化类型，但没有完整备份适配；Redis 或多数据库绑定均在远端备份前拒绝。语言/主题重建保留选择和引用，密码不进入普通状态；SQLite 物理映射仍未开放。

桌面 `BackupApplicationFacade` 先执行不连接服务器的受管输入准入检查：逐组件核对整应用图、当前发布、运行时、文件/数据库范围、精确配置、秘密绑定和应用级健康探针，并通过二次读取拒绝状态漂移。输入完整后，用户可选择目标归档并输入独立备份密码及凭据存储主密码；门面自动使用已保存服务器资料，不要求用户重填 SSH 参数。`persistedInputsComplete` 只表示允许继续远端检查，最终成功仍必须完成远端取材、原运行状态恢复、两级健康、归档校验和最终位置复验。

#### 数据库范围

- SQLite：停止写入并使用 SQLite 在线备份 API 或经过验证的一致副本；禁止在活跃写入时直接复制数据库文件。
- PostgreSQL：使用版本匹配的受控逻辑备份/恢复流程，记录服务器和工具版本。
- MySQL/MariaDB：使用版本匹配的一致性逻辑备份/恢复流程，记录事务和非事务表限制。
- 其他或外部托管数据库：默认只记录人工恢复要求，不宣称已备份；新增正式适配必须另行确认。

涉及数据库结构变化的发布必须在本期定义显式迁移前检查、备份点、执行证据和回滚兼容性。不可逆迁移没有经过验证的恢复路径时不得自动发布。

#### 包结构

备份以单个版本化归档交付，至少包含：

```text
manifest.json          # 格式版本、应用/组件、来源、架构、文件清单和算法
releases/              # 需要保留的发布产物或可重建源码信息
config/                # 普通配置快照
data/                  # 受管持久化文件/卷导出
database/              # 受支持数据库的一致性导出
runtime/               # 运行时、unit/容器定义和能力清单
secrets.enc            # 用户选择包含秘密时的独立认证加密成员
```

- `manifest.json` 使用明确 schema 版本，未知必需字段或未知重大版本时拒绝恢复。
- 每个成员记录大小和 SHA-256 等内容摘要，用于损坏检测和传输校验。
- 普通摘要可以被攻击者连同内容一起重算，因此不得把“摘要匹配”描述为可信来源证明。
- 归档若提供独立数字签名，才可以在签名密钥可信的前提下声明来源验证；没有签名时界面只显示完整性检查结果。

#### 备份秘密

- 默认排除所有原始秘密，只保留不可用于解密的引用元数据。
- 用户选择包含秘密时，必须设置独立备份密码；平台主密码、Windows Credential Manager 和 Web 主密钥不能代替或被导出。
- 使用带独立随机盐和记录参数的 Argon2id 派生备份密钥，以 AES-256-GCM 等认证加密保护 `secrets.enc`。
- 密码、派生密钥和可等价恢复的材料不进入归档、平台数据库、日志或任务事件。
- 旧密码错误、认证标签失败或参数不支持时停止秘密恢复，不返回部分明文。
- 桌面和 Web 通过同一 `shared/backup` 格式交换加密成员，密码输入与凭据解析由平台服务组织，备份密码派生和解密由 `shared/backup.crypto` 共用。

`shared/backup.crypto` 使用严格规范二进制明文载荷保存最多 64 个唯一“秘密标识 + 正修订号”精确引用；相同标识的不同修订可同时存在，重复的精确引用或非规范顺序会被拒绝。秘密值不进入不可清零字符串，认证后仍会严格检查格式、UTF-8、长度、顺序、精确唯一性和尾随字节。service 对 schema v6 只在全部解码成功且精确引用集合与 manifest 完全一致时返回一个整体可关闭的 `ResolvedSecretRevision` 文档；旧备份格式直接拒绝。错误密码、认证失败、格式错误、缺少成员或引用不一致均不返回部分秘密，并清零密码、关闭部分修订、清理本次候选。

桌面备份页面现可显式选择“验证密码并准备”：密码输入框立即清空，字符数组由 service 在成功或失败后清零；UI 后台任务只读取已认证修订数量，并在回到 Swing 事件线程前关闭整个秘密文档。页面只接收不含秘密的候选及数量，`BackupPageState` 不保存密码、解码修订或秘密引用。该结果只证明所选本地归档的密码与完整加密成员匹配，不代表秘密已传输或远端恢复已执行。

#### 归档安全

创建和恢复必须限制成员数、单成员/总解压大小、路径长度和压缩比，并拒绝绝对路径、`..` 穿越、越界符号/硬链接、特殊设备、重复覆盖和大小不符。先在受管候选目录完整校验，再允许进入恢复流程。

桌面当前通过独立 `BackupApplicationFacade` 提供不会连接服务器的本地产品入口：完整校验所选归档，或重新校验后在平台持有的 `work/restore-candidates` 下创建新的摘要绑定隔离候选，并可删除页面当前持有的精确候选。候选根在安全提取前必须不存在；工作区签发不可伪造尝试并绑定父目录创建时文件身份，删除前重新核对工作区、精确父子关系、目录类型和身份，重建对象、工作区外路径或外部替换均失败关闭且保留内容。页面一次只跟踪一个当前候选，删除失败保留身份以供重试，语言或主题重建携带同一内存删除授权；应用重启后不猜测或扫描旧目录。界面明确本地准备或删除都不等于远端恢复或激活。

完整归档产品入口先在同服务器互斥锁下权威观察全部组件，只停止原本运行的组件；随后按依赖顺序收集发布树、普通文件与容器宿主绑定目录 PAX TAR、Docker/Podman OCI Archive 和固定数据库逻辑制品。两个容器引擎均要求可验证的 OCI 导出与显式目标导入；能力缺失时拒绝，不在恢复阶段以 root 重建项目。无论取材成功或失败，入口都会恢复原本运行的组件并执行逐组件和整应用健康；无法证明恢复时返回 `MANUAL_RECOVERY_REQUIRED`。`app/windows.workspace` 在固定工作根保存本次成员，再由用户目标同目录临时文件完成写入、完整校验、无覆盖原子移动和最终路径独立复验；目标已存在、成员摘要不一致或外部替换均失败关闭且不越界删除。

```text
查询受管身份和实时状态
→ 生成数据/数据库/秘密清单
→ 选择并展示一致性策略及停机影响
→ 停止写入或进入经过验证的一致性模式
→ 导出数据库和文件
→ 创建归档、摘要和可选加密秘密
→ 在独立位置重新读取并校验
→ 恢复应用原运行状态
```

- 同服务器重装前必须确认至少一个已完整读取校验的副本位于本机之外或另一服务器。
- 备份失败时恢复原运行状态；恢复失败进入人工处理并保留中间证据。
- “备份创建完成”不等于“恢复演练通过”，界面分别显示创建、完整性、解密可用性和恢复验证状态。

配置编码证据边界：历史 `2.25.0-managed-restore-migration`（2026-08-22）同时存在 v2/v3 两种记述，准确引入版本未核实；当前写入 v4 不证明该历史批次的格式版本。该不确定性不改变现行恢复准入规则。

### 3.11 受管恢复与离线迁移

**涉及模块与分工：** `shared/backup` 定义状态机，`shared/deploy` 处理候选和正式提交；`app/service` 连接备份、秘密、数据库、远端恢复与本地接管。

桌面 `restoreManagedBackup` 已调用 [ManagedRestoreUseCase.java](../../src/app/service/src/main/java/gold/debug/windowstolinux/app/service/backup/ManagedRestoreUseCase.java)；离线迁移由 [ManagedOfflineMigrationUseCase.java](../../src/app/service/src/main/java/gold/debug/windowstolinux/app/service/backup/ManagedOfflineMigrationUseCase.java) 组织初始备份、明确停写批准、最终备份和目标恢复。成功后等待人工切流，保留源端，不自动删除或切换流量。真实数据库恢复与双服务器迁移仍为 RUNTIME-PENDING。

#### 前置检查

恢复前校验格式、摘要/签名状态、备份密码、目标发行版/架构、运行时、数据库版本、端口、路径、空间和现有受管应用冲突。源码型备份优先在目标机重新推导环境并构建；二进制恢复必须展示兼容性结论。

#### 候选恢复

- 所有内容先进入新的受管候选目录和临时数据库/命名空间，不能直接覆盖当前成功版本。
- 数据库和文件恢复完成后启动候选，执行组件健康和整体业务健康。
- 只有全部验证成功才提交当前指针；失败则删除明确归属的候选或保留诊断，不破坏现有版本。
- 明确不兼容的二进制不提供强行启动；跨发行版/主版本的未知兼容只能在用户确认后作为试验候选。

当前平台无关实现使用同一操作标识依次记录前置检查、文件暂存、候选数据库、组件健康、整体健康、提交和恢复证据。schema v6 保存源发行版/版本、14 种封闭运行时、依赖顺序、定义成员引用、组件探针和整应用健康门，并要求每个组件携带发布 SHA-256 与精确秘密修订；应用级 `releaseSetSha256` 由固定域、组件数量和依赖顺序中的“组件标识 + 发布 SHA-256”按长度分隔计算，应用秘密集合必须等于组件引用并集。恢复适配器把这些身份交给 deploy，deploy 独立重算摘要与并集后才接受请求。未知运行类型、额外命令字段、乱序依赖、错误摘要、非规范秘密引用或缺失定义成员直接拒绝。schema v3/v4/v5 在读取时明确拒绝；schema v6 声明秘密却排除固定唯一 `secrets.enc` 时不能自动激活。平台无关恢复模型区分源码与二进制兼容策略；当前桌面受管恢复上传归档中的精确制品，不将该模型能力宣传为已接通任意源码跨架构重建。二进制恢复要求架构精确一致，其他差异仍受目标预检约束。数据库恢复一旦开始，即使适配器尚未返回成功证据也执行幂等候选清理；文件清理或现有发布复核不完整时终态固定为 `MANUAL_RECOVERY_REQUIRED`。

当前具体实现已将 schema v6 归档成员、配置文档 v5 及精确激活身份单向映射到 deploy 和 Linux 恢复契约；SSHD 只创建摘要派生候选目录，经 SFTP 上传精确成员，并再次回读逐项核验大小和 SHA-256，暂存过程不寻址当前发布。目标预检在任何写入前检查受管冲突、能力、空间、架构、数据库工具/版本与端口策略。容器以及静态站点、PHP、Ruby 的显式监听端口可在 `49152-65535` 分配回环候选端口；其余运行时使整应用采用短停机，不允许用新旧混合图冒充健康。秘密、配置和制品暂存后才执行数据库实际连接及候选恢复；候选两级健康仅是提交前预检，正式提交恢复正式端口和服务身份后再次执行组件与整应用健康。任一失败必须清理候选并验证旧发布恢复，否则进入 `MANUAL_RECOVERY_REQUIRED`。远端正式健康后才登记目标秘密和本地整应用图，并单独报告本地接管是否完成或延后。以上为产品组合实现，当前 helper v9 的真实 Linux 和数据库执行仍为 `RUNTIME-PENDING`。

迁移采用明确停写窗口，不声称在线无损切换：

```text
预检查目标机并完成初始传输/构建
→ 用户确认停机窗口
→ 停止源应用写入并确认静止
→ 生成最终数据库和文件一致性增量/快照
→ 校验并恢复到目标候选
→ 启动目标并执行整体健康验证
→ 用户手动切换 DNS、代理或其他外部流量
→ 用户确认目标业务正常后结束
```

- 系统不自动接管 DNS、域名、负载均衡或云安全组。
- 目标验证失败时停止目标候选并重新启动、验证源应用。
- 外部流量切换后失败时，界面给出回切步骤，但必须由用户确认外部状态后执行源端恢复。
- 未得到用户确认不得自动删除源端应用、数据或旧版本。
- 迁移结果分别记录源停止、最终同步、目标恢复、运行验证和外部切换状态。

桌面双服务器产品用例把目标归属、能力、端口、兼容性和两副本空间检查置于任何目标写入之前；先从仍运行的源端创建完整初始备份，只有用户明确批准停写窗口后才停止源应用并证明无活跃写入，再创建最终停写完整归档。最终归档摘要绑定目标候选并复用同一受管恢复链。目标正式健康完成后只返回 `READY_FOR_MANUAL_TRAFFIC_SWITCH`：源端保持停止但不删除，最终归档保存在 `data/backups`，系统不修改 DNS、代理或其他外部流量。源端整应用图仍作为权威归属保留时，目标本地接管明确标记 `DEFERRED_SOURCE_RETAINED`，不制造两个“当前”图。任何失败都分别验证目标候选清理和源端恢复；未批准停写时不建立 SSH 会话或执行远端操作。以上为产品组合静态实现，真实双服务器执行仍为 `RUNTIME-PENDING`。

### 3.12 桌面更新与卸载安全核心

**涉及模块与分工：** `app/windows` 验证更新、回滚与受管卸载请求；`app/secret` 删除精确凭据；外部执行器与生产产品入口归六期。

#### 更新来源和签名

- 更新元数据和安装包必须通过固定发布信任根验证数字签名与版本，不接受仅有 HTTPS 或摘要的未签名包。
- 禁止降级、未知签名、过期/撤销发布和架构不匹配；紧急回退必须使用同样签名且经用户确认。
- 下载先进入受管临时目录并完整校验，不能覆盖正在运行的程序。

#### 受控替换

```text
停止接收新任务
→ 等待任务进入安全终态或可恢复状态
→ 备份应用 data/SQLite 和版本信息
→ 主程序退出
→ 独立更新器替换程序文件
→ 执行版本化数据库迁移并启动健康检查
→ 成功提交；失败则恢复旧程序和旧数据库
```

更新器不接触明文秘密或实现另一套加密逻辑。`data` 固定位置和用户选择的凭据存储模式升级前后保持一致。数据库回滚必须使用升级前备份，不能尝试让旧程序读取已失败迁移的新结构。

当前安全核心使用严格三段式版本、固定架构、签名有效期、撤销集合和 Ed25519 公钥策略验证已暂存包；摘要只证明内容绑定，只有固定信任根签名通过才产生更新验证证据。等版本和未批准降级拒绝；紧急回退同时需要签名清单标记与用户明确批准。事务已拆分为主进程 `prepare` 和独立更新器 `apply`：前者只停收任务并成对备份程序/SQLite，后者只有在验证更新器身份、主进程退出和交接真实性后才允许替换。主进程交接已可编码为严格有界、版本化、用途隔离且经 HMAC-SHA256 认证的文档；认证通过前不解析领域载荷，错误密钥、篡改、截断、跨用途重放和认证后畸形载荷均失败关闭。编解码器不持有调用方密钥；数据库迁移或新版本健康失败仍必须同时恢复旧程序与迁移前 SQLite。仓库未嵌入测试私钥或伪造生产公钥。生产信任材料、官网/发布下载、独立执行器和实际产品接线属于六期，详细方案在六期实施前另行确定。

- 每次卸载都要求用户明确选择“保留数据与凭据”或“删除本应用数据与凭据”，不设置默认选项。
- 删除前停止本应用任务并校验 jpackage 安装根、固定 `data` 目录、受管标记和专用 Credential Manager 命名空间。
- 不删除用户项目源码、下载到其他位置的备份、目标 Linux 应用或其他程序数据。
- 删除失败时列出未删除的准确项目，不用“卸载成功”掩盖残留。

当前卸载核心的请求使用可空显式决定而非默认枚举；未选择时不调用任何平台端口。凭据范围固定为唯一 `WindowsToLinux/*`，请求不能改为任意子命名空间。`app/secret` 已用固定 P/Invoke 实现单键删除和命名空间枚举删除：只删除符合应用生成规则的键，命名空间内其他目标作为精确残留返回。主进程 `prepare` 仍只验证决定并停止本应用任务；其交接使用与更新不同的认证用途，防止合法更新文档被卸载路径重放。生产独立卸载器及产品接线属于六期；当前不宣称产品卸载可用。


<a id="system-preparation"></a>

### 3.13 系统准备与发行版安全

**涉及模块与分工：** `model.server.security` 表达计划与状态，`linux.distro` 定义窄端口，`linux-sshd.distro.dnf` 实现固定脚本，部署环境用例与 UI 执行确认和阶段恢复。

- 静态、半 AI 和独立环境准备的系统包确认默认取消，说明目标、官方包管理、DNF 9 的 SSH 兼容更新和连接中断。普通安装批准不包含 SELinux 变更或整机重启；拒绝后不安装、不发布。Agent 模式将这些风险确认接入统一的本地、AI 与按策略人工审批，不能重复弹出旧确认或扩大已授权范围。
- CentOS Stream 9/10 非 Enforcing 时单独确认 SELinux、标签修复及重启。计划绑定服务器、启动标识、配置摘要和阶段；拒绝、关闭、事实漂移或指纹变化均停止。
- 固定脚本保存原配置，先 Permissive 重启并修复标签，编排最多等待 15 分钟；标签服务成功且审计无未解决 AVC 后设置 180 秒回退，再尝试 Enforcing。新 SSH 认证成功才提交并撤销回退；失败保留阶段，不生成宽泛策略或关闭防火墙。
- 原配置及非秘密阶段仅保存在 root 所有的 `/var/lib/windowstolinux/system-preparation/selinux/`；临时计时器使用 `RemainAfterElapse=no` 和收集策略。审计显式使用 `ausearch --input-logs`，避免读取 SSH 标准输入而误报无记录。
- DNF 9 固定事务同时选择 openssh、openssh-server、openssh-clients，安装后检查 sshd 配置和动态库；环境服务关闭旧连接，重新认证及采集能力后才返回结果。连接失败最多三次、间隔 250 ms，不重放部署动作，凭据或指纹拒绝立即停止。
- 只有明确 CentOS 9/10 的包事务临时启用已有官方 CRB，不永久改变仓库。其他发行版走自己的准备实现。能力探测只读，UFW 状态以工具自身输出为准，权限不足或未知输出返回 unknown。
- SELinux 平台用只读临时文件系统覆盖 `/run/systemd`，只读保留需要的 dynamic-uid/userdb 查询目录，隐藏实际控制、日志及通知接口；其他平台保留原隔离集合。类型化普通服务通过 `/usr/bin/env` 进入发行版普通服务域，不给 init_t 增加 execmem 权限。主机 Enforcing 不等于应用具有专属 SELinux 策略。

代表性 CentOS 部署已有证据，但全新 Disabled 系统的最终版本无人工干预初始化尚未复验，详见[系统准备验收](#acceptance-system)。

### 3.15 应用清单与外部接管

- SQLite v14 独立保存外部登记及显示覆盖。列表按成功发布时间倒序、同时间按稳定键排序；缺原发布时间的外部应用显示接管时间。受管应用分类来自经审阅的对外服务声明，名称与适用入口可覆盖，分类变更须重新分析；外部登记的显示分类由用户审阅。类型与服务器可组合筛选。
- 固定 Python 扫描经受信 SSH 流式执行，只取必要元数据。systemd 覆盖已安装及已加载的停止服务，Docker 使用 `container ls --all --no-trunc` 和字段化 inspect；权限不足、部分失败、运行时缺失与空结果分别报告。
- systemd 身份绑定 unit/drop-in 的路径、文件身份和摘要，Docker 绑定完整容器 ID；接管和每次操作前均复核。重新扫描并明确选择后可原子替换变化的本地登记，同一身份不会重复导入。
- 外部对象仅开放状态、访问入口、启动、停止和重启，保留原配置；不自动开放受管更新、回滚、备份和自启。带受管标记却缺少原记录的对象必须恢复原始归属，不能走外部操作绕过门禁；模板、屏蔽或无法稳定读取的服务不授予生命周期操作。

本地协议与界面检查见[桌面验收](#acceptance-desktop)；外部 systemd/Docker 的真实现场接管仍待验收。

#### 身份隔离专项方法

当前方案由 root 登录管理、临时身份构建、独立低权限身份运行。当前命令不再传入 managed.root-build 或 managed.target.root-build；旧参数为 true 时验收入口拒绝。身份检查必须读取实际进程与 systemd 属性，不能仅检查请求值。新增验收必须覆盖限容卷写满、临时 UID 复用隔离、取消/断连/重启清理、容器存储、动态数据权限及旧部署回滚。历史结果保留适用版本与环境；已执行项目以[实际覆盖矩阵](#acceptance-matrix)及对应版本证据为准。

##### 身份隔离专项实机矩阵

下列是完整身份与故障注入矩阵。现有代表性记录已验证正常部署、实际非 root UID、起停与健康失败回滚，以及遇到的构建失败和候选清理；矩阵中的取消/断连、重启/崩溃、资源耗尽、跨应用 UID 复用、OCI 备份恢复和旧数据迁移仍为 `RUNTIME-PENDING`，必须在授权的专用服务器上逐项执行。普通测试中的请求参数断言、模拟命令和历史 root 构建记录不能替代这些证据。

| 场景 | 必须保存的证据与成功条件 |
| --- | --- |
| 正常、构建失败、超时、取消及 SSH 断连 | 固定入口报告的 BUILD_UID/BUILD_ENGINE；完整控制组进程退出；候选卷卸载、loop 解绑、临时账号与 subuid/subgid 撤销。清理失败必须保留 root 记录与明确拒绝原因。 |
| 服务器重启与中途崩溃 | 在卷分配、账号创建、映射授予和封存等阶段重启；恢复单元只处理 helper 自有候选。无法确认归属的账号必须隔离报告，不能删除用户已有账号。 |
| 硬限制与管理入口 | 写满源码、缓存、临时文件、日志和镜像层；子进程大量输出、占用内存或派生进程；尝试提权、扩容、写宿主机路径或连接管理 socket。能力不足须在上传前拒绝，超限须失败并完整收尾。 |

| 发布与清理结果 | 单组件和多组件分别注入保留/清理失败；已发布的真实身份仍登记成功并显示待清理警告。健康或最终归属/运行状态不满足时不得提交成功。 |

现有单语言及共享多组件验收夹具包含成功后的实际运行 UID 和原生身份检查；新布局验收应断言固定服务账号及 DynamicUser=no；上述故障注入、复用、重启及数据库矩阵仍需逐项采集实机证据。

##### 完整备份与受管恢复桌面入口

通过桌面“备份”页面执行，禁止用测试代码、直接 SSH 或 helper 命令代替：

### App 三种部署模式与独立审批 Agent

App 默认静态，半 AI 为固定分析/预检/失败节点，Agent 为一个部署决策端口、一个独立审批端口与串行受控执行端口。Web 尚未同步这些界面、配置及编排；不增加 Maven 模块或 Agent 框架。

实现分工：`app/ui/ai` 持有全宽库存及内联用途草稿；`app/service/ai` 负责修订验证、冻结顺序与凭据引用、单模型请求及接替；`app/db` 的 v18/v19 负责用途和任务事件。`shared/model/agent` 是纯数据，`shared/ai` 是严格 JSON 协议及版本化 Skill，`shared/deploy/agent` 协调本地/AI/人工审批与预算，`app/service/deployment/automatic` 接入既有单/多组件事务。`DeploymentRemoteTaskScope` 仅将当前工作线程的候选意图送入注入日志端口，Web 未打开该作用域时保留既有候选行为。

本地验证绑定任务、服务器/账户、源码内容摘要、计划修订、明确参数及事实。审批结果绑定规范 SHA-256；执行前重新核对，秘密通过既有精确引用解析。审批模型没有执行工具。人工复审逐条确认，自动审批只确认允许的高危动作，完全控制自动执行已经两层批准的动作。人工复审需要逐条审核指令，会明显增加工作量，一般不建议开启；仅建议用于极高价值的服务器。

Agent 缺少已启用且通过当前文字能力验证的部署/审批模型，在模型调用和远端副作用之前停止；审批拒绝不能通过换模型绕过。预算为 30 轮、连续两轮无新事实触发接替、补证据两轮；模型切换、暂停恢复和显式更新模型均不重置预算。旧请求同步结束后才发下一请求。模型提示和日志片段均是证据，不是授权来源。

事务仍负责构建、实际健康、发布及适用恢复。受管服务诊断/重启只开放当前目标和冻结归属；候选查询/清理只接受本任务创建前记录的应用和源码身份。helper 新增 `candidate-create-task`、`candidate-query-task`、`candidate-cleanup-task`，root 所有的 `.agent-task` 将清理绑定任务；清理沿用进程停止、容器构建清理和卷清理。参数不接受自由 Shell 或任意路径。查询 20 秒、额外清理 2 分钟；既有部署超时不变。

暂停/取消等待事务安全边界；提交成功优先于迟到的取消请求。未知执行以及缺少结果的持久化派发意图阻断同服务器新一键部署。重启不自动续写；历史中的只读查询不会仅凭候选缺失解除未知状态。本版没有通用未知发布/数据库/环境事务的自动恢复和解除阻断流程，该场景需专门人工恢复核验。视觉用途已配置并接入独立识别路由，首版纯文本部署 Agent 不主动采集屏幕或启动浏览器救援。

验证分层：本地模拟模型、SQLite 迁移、Swing 状态、审批矩阵和候选 helper 替身用于代码回归；真实模型接口与真实 Linux 半 AI/Agent 单/多组件部署仍为 **RUNTIME-PENDING**。任务日志记录实际调用、已报告 Token、人工交互与耗时，未返回用量不估算。历史静态实机结果不算新模式验收。
