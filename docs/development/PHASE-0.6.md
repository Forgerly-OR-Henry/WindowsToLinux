## 1. 本期目标与承接关系

0.6 期面向正式上线。0.5 期只验证与桌面 App 主要业务能力对等的 Web 功能，不建设官网主页，也不完成登录认证等上线安全能力。0.6 期在 0.5 期功能稳定后，再统一完成公开网站、生产安全和正式发布维护能力。

0.5 期运行基础已改为 Spring Boot / Spring MVC、MyBatis-Plus 与 SQLite，使用 YAML 和外置依赖 JAR。0.6 期沿用模块边界，但 0.5 期的固定内部主体、回环监听和结构预留不等于生产授权。

历史方案曾确认 0.6 期支持多用户。0.5 期先按本期方向建立用户、工作区与资源归属结构，并预留认证、授权、审计和发布目录及表；只实现 0.5 期功能。0.6 期开始前重新检查届时的 `File.md`、0.5 期实现和实际上线条件，再确定登录方式、权限策略、公开页面、部署拓扑、下载协议、执行器和生产验收细节。

- 0.4 期保留已经实现并通过静态测试的更新/卸载安全核心，不删除、不伪装成当前可用产品入口。
- 0.5 期专注 Web 功能开发，只用于内部测试；不做官网主页、登录认证、公开部署、正式下载或正式更新。
- 0.6 期开始前先根据 0.5 期实际实现重新设计上线方案，避免现在预设细节造成返工。
- 官网公开内容、受保护服务、下载发布和桌面维护之间必须保持职责分离，但具体是否同域、同进程或同部署暂不决定。
- 正式更新仍必须使用可信签名并具有失败回滚；发布私钥不得进入客户端、Git 或普通服务运行目录。
- 正式卸载仍不得删除用户源码、独立备份、目标 Linux 应用或其他程序数据。

## 3. 功能方向

本节保留当时的能力方向与原因；其中多用户执行服务台方向已被替代，不把历史需求重新确认为现行需求。

<a id="website"></a>

### 3.1 公开官网

**涉及模块与分工：** 官网公开内容与受保护服务入口分离，前端具体栏目待定。

**公开官网**：官网式主页、产品介绍、使用说明、文档和服务入口；具体栏目与信息架构后定。

<a id="security"></a>

### 3.2 上线认证与安全

**涉及模块与分工：** `web/auth` 承接认证目标，生产会话、权限和部署边界需正式设计。

**上线认证与安全**：为 0.5 期内部 Web 功能增加多用户身份认证、工作区成员与角色授权、访问控制和浏览器安全；登录方式与部署范围后定。所有资源、凭据、文件、后台任务和事件必须校验服务端主体及工作区，客户端提交的用户或工作区 ID 不构成权限证明。

0.5 期已确认的结构预留：`auth` 下的 `identity`、`authorization`、`csrf`、`initialization`、`login`、`ratelimit`、`session`；`service`/`api` 下的 `account`、`workspace`、`audit`、`release`；前端 `features` 下的 `account`、`workspace`、`website`、`release`；`secret/password` 只保留密码学职责说明。数据库表及约束见[0.5 期实施约定](PHASE-0.5.md#features)。0.5 期固定内部主体不是生产账号，0.6 期迁移必须显式处理其数据归属，不自动开放给首个注册用户。

<a id="release"></a>

### 3.3 正式发布与下载

**涉及模块与分工：** 发布、下载与制品职责需在现有 Web 和桌面边界下明确。

**正式发布与下载**：提供首次安装、版本说明和正式软件包下载所需的发布链；服务形态、接口和托管方式后定。

<a id="maintenance"></a>

### 3.4 Windows 生产更新与卸载

**涉及模块与分工：** 复用 0.4 期安全核心，通过独立执行器及桌面入口完成正式操作。

**Windows 正式更新与卸载**：在 0.4 期已完成的签名验证、回滚、认证交接和受管删除核心上，补齐生产执行器及产品入口。

<a id="production-acceptance"></a>

### 3.5 生产验收

**涉及模块与分工：** 覆盖公开页面、认证、下载和桌面维护的真实环境验证。

**生产验收**：覆盖公开页面、认证、下载、更新、回滚和卸载的真实上线环境验证；精确矩阵后定。

<a id="implementation"></a>

## 4. 实施顺序与依赖

1. 完成 0.5 期 Web 功能及内部测试。
2. 复核届时产品形态和正式上线需求。
3. 先批准 0.6 期详细设计，再建设官网与生产认证。
4. 建设正式发布下载链并接通 Windows 更新/卸载。
5. 完成真实上线环境的安全、更新、回滚和卸载验收。

<a id="acceptance"></a>

## 5. 验收标准与验证记录

0.6 期只有在详细方案另行批准并实际实现后，才可以根据届时验收标准判断完成。当前方向文档本身不证明以下任何能力已经可用：

- 公开官网或公网 Web 服务；
- 登录、账号、会话或权限；
- 官方下载、在线更新或正式发布；
- Windows 生产更新/卸载执行器；
- 正式上线安全或运行证据。

本期没有已执行的生产验收。0.4 期安全核心的静态证据不证明生产更新、卸载或官网已经可用。

<a id="remaining"></a>

## 6. 剩余事项与后续边界

以下问题现在明确保留，在实施前另行确定：

- 官网与 Web 服务台的信息架构、域名、路由和部署关系；
- 多用户的登录方式、管理员初始化、会话生命周期和具体角色权限策略（用户、工作区、成员与资源归属结构已在 0.5 期预留）；
- Web 的公网部署、反向代理、HTTPS、主密钥和安全审计方案；
- 正式发布清单、下载接口、制品组成、更新通道和版本兼容规则；
- 生产签名密钥的生成、保管、轮换和撤销流程；
- Windows 独立更新/卸载执行器的打包、身份、交接和恢复细节；
- Web 自身升级方式，以及桌面与 Web 是否共享发布服务；
- 正式上线环境、支持平台、故障注入和验收矩阵。

这些是旧方案当时的未决事项；后续需求以 1.1 主文档为准，不自动继续实施旧方案。未决定前不得创建伪生产密钥、临时线上接口或不可执行的产品壳。
