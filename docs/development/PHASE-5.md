## 1. 本期目标与承接关系

五期只提供内部测试使用的单实例 Web 功能服务台。浏览器可以提交源码/Git、服务器、分析、部署、受管生命周期、备份和迁移任务，并在关闭页面后继续执行。Web 服务台复用 `shared` 的业务规则，但本期不实现登录、管理员初始化、会话、CSRF、公开网络部署或其他正式上线认证能力。

五期完成的是与桌面 App 主要业务能力对等的内部功能区，而不是可上线网站。公开官网首页、产品介绍、公开文档导航、正式下载入口、登录认证和服务入口外壳统一在六期建设；届时官网可以把五期服务台作为最重要的受保护功能入口。

Web 后端可以读取上传或 Git 快照做静态分析，但不得在 Web 主机安装用户项目依赖、运行用户项目脚本或构建。用户项目仍只在目标 Linux 构建。WindowsToLinux Web 自身的前端/后端发布构建属于产品发布流程，不属于用户项目构建。

<a id="runtime"></a>

### 3.1 内部运行边界

**涉及模块与分工：** `web/main` 负责启动与单实例，`web/db` 和 `web/file` 使用隔离测试位置。

- 后端必须以明确的内部测试模式启动，固定只绑定 `127.0.0.1`；五期不提供监听公网、局域网所有地址、反向代理或正式服务安装模式。
- 无登录状态下直接进入功能服务台，因此只能在开发机或受控自动化测试进程中使用；启动页和控制台持续显示“内部测试，禁止上线”。
- 单实例后端独占临时或专用测试 SQLite 和受管工作目录，不支持多个后端共享数据库或目录。
- SQLite、上传工作区和备份统一派生于专用数据根；主密钥单独存放，不读取桌面正在使用的数据目录。日志默认输出控制台。
- 后端启动时验证单实例锁、目录、数据库 schema 和磁盘下限；失败即停止，不回退到任意临时目录。
- 即使只用于内部测试，也禁止宽松 CORS、JSONP、跨站表单副作用和浏览器直连 SSH。状态修改只接受同源 JSON 请求及固定自定义请求头，避免普通网页向回环服务发起简单跨站请求；这不构成正式认证。

五期没有安全上线形态。需要远程浏览器、局域网共享、HTTPS、反向代理、登录、用户身份或正式服务安装时，必须等待六期。

#### 启动、配置与数据根

运行基础为 JDK 21、Spring Boot 4.1.1、Spring MVC、MyBatis-Plus 3.5.17 和 SQLite；Vue 与 API 由单进程提供。配置使用 `application.yml`，`WebMain` 或 `java -jar web.jar` 无参启动，无必填环境变量。入口见 [README](../../README.md#运行-web-内部服务台)。YAML 中 `w2l.mode` 固定为 `internal-test`。

数据根只配置 `w2l.storage.root: db.data`：CLASS 锚定 Web DB 模块，JAR 锚定实际外置 DB JAR 的父目录；`db.data/abc` 拼接子目录，绝对路径直接使用。未知来源、嵌套 JAR、逃逸、APP 及旧 `db/data` 写法拒绝，不按 CWD 猜测。主库固定为 `windowstolinuxweb.db`，`files/`、`backups/`、归属标记与实例锁不能分别配置。数据根移动不自动搬迁旧库，密钥规则见[测试凭据](#secrets)。

`web/main` 的 Maven 构建负责 npm ci、TypeScript、Vite 和静态资源入包，产物为 `web.jar + lib`。Spring 管理依赖装配与关闭；HTTP 使用 Controller/Filter，Web JSON 使用 Jackson 3，共享与桌面现有 Jackson 2 编解码器保持独立职责。

<a id="api"></a>

### 3.2 接口与业务复用

**涉及模块与分工：** `web/api` 提供接口和 SSE，`web/service` 组织用例并调用共享业务。

内部 API 使用 `/api/v1/` 前缀；本期请求契约见 [OpenAPI 3.1](../../src/web/api/src/main/resources/openapi.json)。浏览器使用相同源的 HTTP 与 SSE：

- 服务器、AI、上传/Git、分析、部署、受管应用、生命周期、备份、恢复、迁移、设置和任务查询；不包含认证、会话或管理员接口。
- 分析、部署、生命周期修改、备份、恢复和迁移提交后返回任务 ID；后台执行，SSE 只传输结构化脱敏事件。
- 只读状态刷新必须查询目标服务器并返回观测时间和未知/异常状态，不能只返回数据库缓存。
- 状态改变只能使用 POST/PUT/PATCH/DELETE；GET/HEAD/OPTIONS 必须只读且无副作用。
- 错误返回稳定错误标识、用户可执行说明和关联 ID，不返回异常堆栈、SQL、内部路径、命令全文或秘密。

禁止提供任意 Shell、浏览器直连 SSH/SFTP、原始凭据回读、任意文件路径、任意 systemd/容器操作，以及由客户端覆盖任务状态或标记成功的接口。

纯运行时解析和默认值计算归 `shared/deploy/input`，普通配置文本解析归 `shared/config/input`，数据库审阅枚举归 `shared/model/deployment`，桌面与 Web 共用；平台持久化、凭据和交互各自负责。可移植备份秘密格式由 `shared/backup.crypto` 共用。

HTTP JSON 上限 1 MiB；64 个在途请求、4 个上传、8 个 SSE。修改要求精确 Origin、`X-W2L-Client: web` 与正确 Content-Type。运行策略和配额由 YAML 绑定，协议字段和归档校验仍由共享契约定义。

<a id="source"></a>

### 3.3 上传、Git 与工作区

**涉及模块与分工：** `web/file` 处理上传及目录，`shared/git` 和 `shared/source` 复用安全快照。

#### 上传

- 浏览器只可读取用户主动选择的文件/目录，不能扫描访问者电脑。
- 服务端采用流式上传，限制单文件、单项目、单备份、总空间、成员数量、并发数和保留时间，不把完整大文件读入 Java 堆。
- ZIP/`tar.gz` 解压拒绝绝对路径、穿越、越界链接、特殊文件、重复覆盖、压缩炸弹和超限路径。
- 上传完成前不可进入分析；失败/过期临时目录只有在无有效任务/恢复点引用并通过归属标记后才能清理。

#### 静态分析与目标机构建

- 上传/Git 快照在 Web 工作区只做静态读取、归档和摘要；禁止执行 Hook、Wrapper、包管理器、项目二进制或构建脚本。
- 后端将已校验源码发送到目标 Linux，或让目标机取得同一固定 Commit，并复核摘要后构建。
- Web 主机不能作为用户项目的“临时构建机”或失败回退构建位置。

#### 配额与归属清理

- 源码：单文件 128 MiB、单项目 1 GiB、总空间 4 GiB、最多 10,000 成员、相对路径 240 字符；压缩和解压材料均计入。Git 使用无凭据 HTTPS，取材持续监测空间并支持中断。
- 备份：归档和解压材料分别最多 4 GiB，单工作区 8 GiB，总空间 16 GiB；创建前和流式写入中都检查空间。含秘密的备份使用独立密码与共用 Argon2id/AES-GCM 格式。
- 启动保留 READY 源码，清理过期 24 小时的未完成源码及具有精确归属但未登记的备份临时目录；不删除无归属文件。当前列表有界，历史分页与管理型清理界面未实现。

<a id="tasks"></a>

### 3.4 持久化任务

**涉及模块与分工：** `web/task` 负责状态机与事件，`web/db` 保存任务和恢复事实。

任务至少包含：等待、分析中、等待用户决定、执行中、正在取消、已取消、成功、失败、被系统中断、需要重新验证。

- 浏览器断开不取消任务；SSE 断线后可以按事件序号继续，最终状态也可普通查询。
- 同一目标服务器上的修改任务互斥；只读任务仅在资源限制内并行。
- 后端重启后扫描未终结任务。只有具有幂等证据和安全恢复点的步骤可继续，其余进入“需要重新验证”。
- 等待用户决定具有过期时间；过期安全停止。取消是受控状态迁移，不直接杀死到未知状态。
- 任务保存经审阅输入、目标、结果、结构化步骤/事件和失败代码；成功应用保存精确发布身份与不可变配置修订。步骤输入/结果摘要和远端版本列已预留；本期不会据此自动续跑，重启统一要求重新验证。秘密以加密引用传递。
- API/SSE 客户端无权直接修改任务状态、步骤游标或成功结果。

任务最多 32 个活跃、4 个执行器；决定 30 分钟过期，单任务进度最多 10,000 条。启动时全部未完成任务及未确认应用进入重新验证。

#### 数据归属与六期结构预留

业务访问使用 MyBatis-Plus Mapper 和 Spring 事务，保持复合键、外键、乐观并发及事件原子性。Web SQLite 有 26 张表，五期使用服务端固定的 `internal` 用户和工作区，浏览器不能覆盖归属。业务查询、文件、凭据、任务和事件均绑定工作区及用户；资源保存 `workspace_id`、`created_by` 和时间，关联采用工作区复合外键，唯一约束按工作区定义。

六期身份结构包括 `users`、`workspaces`、`workspace_members`、`roles`、`permissions`、`role_permissions`、`member_roles`、`user_credentials`、`auth_sessions`；审计及发布预留 `audit_events`、`release_channels`、`releases`、`release_artifacts`。工作区外键和成员状态检查已执行，但密码、会话、角色授权、审计及发布业务尚未启用。发布表不存签名私钥，目录预留不提供空控制器或伪登录。

<a id="secrets"></a>

### 3.5 内部测试凭据

**涉及模块与分工：** `web/secret` 管理测试密钥，业务接口只返回非秘密元数据。

- 五期不保存管理员账号或密码。`web/secret` 只为内部功能测试处理 SSH/AI/应用/备份相关凭据（Git 仅无凭据 HTTPS），不承担上线认证。
- 主密钥首次随机生成于 `w2l.secrets.directory`，Windows 限制当前用户 ACL、POSIX 限制目录 700/文件 600；后续启动复用。数据根的 `.master-key-id` 只保存非秘密 UUID，保证移动数据根或分发目录后仍能关联原密钥。密钥不进入 SQLite、普通备份、YAML、日志、事件或 HTTP。
- 保存后只向浏览器返回名称、非敏感元数据、已配置状态和更新时间，永不回传原始值。
- 已有数据库对应主密钥缺失、损坏或认证失败时停止启动；必须恢复匹配的原密钥，禁止生成新值覆盖原数据。
- 桌面与 Web 不同时打开同一个 SQLite 或工作目录。迁移配置使用经过验证的导入/导出，不共享正在使用的数据文件。
- 不得因为五期没有登录而把秘密改为明文落库、返回浏览器、写入 URL 或输出到测试报告；这些数据边界属于业务安全，不是可后置的登录功能。

<a id="frontend"></a>

### 3.6 前端功能

**涉及模块与分工：** `web/frontend` 只经 HTTP/SSE 访问后端，不直接调用数据库或 SSH。

`web/frontend` 使用 Vue 3、TypeScript、Vite，单元测试使用 Vitest，关键流程使用 Playwright。前端只通过 HTTP/SSE 使用 `web/api`，不依赖 Java 模块或直接访问数据库、文件、SSH。

内部测试功能入口覆盖部署、已部署应用、服务器、AI、备份/迁移、任务和设置，但不建设大型专业运维控制台。页面必须区分浏览器电脑、Web 主机和目标 Linux，说明动作影响、失败原因和下一步，不展示原始异常或用隐藏失败制造简单感。

五期前端直接进入服务台功能路由，不实现初始化、登录或账号页面；根路径只在回环内部测试模式显示服务台和醒目的非生产警告，不制作官网式公开首页、产品营销页面、公开下载页或发布版本页。

七个功能页面已接通 API；服务端和真实传输协议通过本地 HTTP、临时 SQLite 与假远端测试验证。浏览器测试既包括接口夹具回归，也包括连接真实本地 Spring Boot 的构建后页面；均不代表真实 Linux 或 AI 提供商联调完成。

界面采用可折叠左侧导航、源码与目标卡片、应用卡片、AI 模型排序及默认收起的高级参数，保存输入和任务状态。公开网站、账号、工作区与发布的前端目录仅预留职责，详见[六期](PHASE-6.md#security)。

<a id="migration"></a>

### 3.7 Web 自身迁移测试

**涉及模块与分工：** Web 组合层复用共享备份与迁移契约，测试自身运行数据的导入与恢复。

五期提供可运行的 `web.jar + lib` 内部测试分发目录，不建设正式签名发布、镜像或自动更新器；本地构建验证数据库迁移和失败回滚顺序：

```text
停止接收新修改任务
→ 等待任务进入安全状态
→ 备份 SQLite、应用数据和版本信息
→ 测试人员替换本地测试构建
→ 新版本执行迁移前检查和版本化数据库迁移
→ 启动健康检查
→ 成功后展示持久化任务，未完成任务要求重新验证；失败由测试人员切回旧构建并恢复旧数据库
```

测试必须保留可操作的回滚证据和步骤，但不能在运行进程内覆盖自身。数据库迁移失败时停止启动，不让旧程序读取已迁移失败的数据结构。正式签名包、人工上线升级和发布下载属于六期。

#### 冷备份与失败回滚

本地构建升级前，停止 Java 进程并确认退出，再把**完整专用数据目录**冷复制到独立备份位置，另外保存完整旧分发目录和独立密钥目录。使用新构建与相同密钥启动并检查 `/api/v1/health`、设置和任务。如果迁移或健康检查失败，停止新进程，保留失败目录供诊断，把冷备份恢复到空的专用数据位置，切回完整旧分发目录后重启。不要只复制活动中的 SQLite 文件，也不要让旧构建读取新版本 schema。HTTP 集成测试验证冷复制、较新 schema 启动拒绝、旧副本恢复及错误密钥拒绝；此操作不构成正式发布或镜像升级能力。

## 4. 功能依赖与实现约束
