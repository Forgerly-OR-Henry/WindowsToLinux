# WindowsToLinux 运行与行为约定

- 职责：维护运行数据目录、部署与恢复行为、数据库、安全及已知验证边界；源码模块、包结构和命名以 [File.md](File.md) 为准。
- 状态：1.1 改造进行中。默认入口已切换 H2 平台启动、安全外壳、常驻模型配置/能力验证及服务器配置/SSH 认证检查；保存与连接分开，认证检查不发送远端命令。未结束检查保留任务占用，可显式清理并记录中断，不自动重连。官方部署 Mod 已迁完整 helper 协议包、固定安装/探测适配及借用原任务会话的受控工具准备/构建入口，本机合同和审批已验证；该入口要求调用方已确认上传原候选，实际目标机安装、正式上传/发布/健康/回滚及页面尚未验收。本文后续部署、备份和 SQLite 行为主要记录待迁移的 0.x 业务实现，不能视为已全部接入新入口。1.1 数据库契约见 [Mod.md](Mod.md#mod-database)，进度见 [1.1 开发文档](development/PHASE-1.1.md)。
- 当前平台连接与传输设置使用 H2 `desktop_preference` 独立键，默认连接 30 秒、无进展 300 秒，支持 1～86400 整数秒；两项原子保存，新操作读取当前值，运行中的传输及其停滞重试保持原快照。缺失键用默认值，损坏值报错；命令超时仍取请求自身设置。
- 当前平台授权默认通用授权，使用独立键 `platform_authorization_mode`；保存只影响随后由宿主启动控件提交的流程。具体授权绑定原任务、业务含义及实际目标，流程结束即失效，普通任务与显式恢复仍逐次确认。AI 审批及业务冲突选择保持独立；官方部署 Mod 接线仍待完成。
- Mod → 已下载可选择当前已发布业务/设置页，明确打开后聚焦实际页面；页面按原作用域惰性创建、缓存及关闭。用户手动固定的 Mod ID＋页面 ID 按顺序保存在 H2 `desktop_preference` 的 `mod_navigation_pins` 键；不包含版本或作者对象，不因启用或恢复偏好自动打开。停用完成、页面撤销或锁定时隐藏入口；同一身份重新发布或解锁后恢复原偏好。固定写入在后台复用原平台事务与安全准入，失败后只读刷新，不自动重试修改；损坏偏好报错并保留，不能当作空偏好覆盖。
- 当前凭据模块直接依赖 `appapi` 和 `app/db`，错误采用公开 `Problem` 并保留原八个事件码、诊断身份；H2 事务桥保留原错误，写入不确定性判定不因异常继承变化而绕过。SSH 公开出口不携带内部存储 cause，凭据损坏时不发起网络认证。UI 优先使用事件对应的中英文说明，未登记事件使用脱敏后的安全诊断，不通过旧报告写入器重建身份。凭据测试已迁为 H2；`app/db` 的旧传递依赖及后台日志生产方仍待整体迁移。
- 当前 CLASS 发现基础校验显式工作区、生成描述、主/从输出、私有 JAR、当前输入摘要及编译标记；缺失或过期输出拒绝，重复 ID 的全部来源拒绝，不加载旧包替代。发现本身不执行作者代码；真实上下文测试已使用发现结果完成页面、任务及停止。默认 CLASS 入口已接发现和已选版本的启动协调；Maven 构建自动生成已接通，官方业务 Mod 仍待完成。
- `PlatformModCatalog` 已把有效 CLASS 发现结果接入 H2 登记：首次默认未启用且只初始化一次单选，新版本和重新编译保留用户选择、修订及运行诊断。实际编译输出、资源、私有库和描述参与摘要；加载前可重新核验。待执行意图、未知任务、跨 Mod 占用或旧运行未收尾时拒绝替换构建依据；无变化重扫仍可返回原构建。登记失败按来源反馈，独立来源继续，无法确认的存储不自动重试。真实组合已覆盖发现→登记→意图→重开→CLASS 会话→归档；入口注册可在锁定时进行，新业务仍需解锁。默认窗口已调用此登记链路；默认 Mod → 已下载页已接登记事实查询及明确意图操作，JAR/APP 原包管理已接独立页面，CLASS 继续使用源码来源。
- 当前依赖计划只读取明确传入的启用选择，拒绝兼容性、缺失依赖、循环及导出包冲突，保留独立有效部分的依赖优先顺序；不自动补启依赖或更换版本。真实加载器绑定核验原提供方及清单快照，未声明的额外提供方不暴露类型。默认协调器先完成计划，再逐一确认提供方实际启动及原意图归档；提供方失败时不构造依赖者，独立部分仍可运行。
- 当前 `PlatformRuntime.modSession` 将真实上下文、加载器和 H2 实际状态绑定到原会话：作者构造前提交 STARTING 和 Schema 使用标记，启动及发布成功后提交 RUNNING；停止先封闭任务准入，原资源全部关闭后才提交 STOPPED 或启动失败。最终写入失败仍保留原会话，重试只补未完成步骤，不重复已成功的作者停止。运行记录不改写启用开关、选择版本、修订或重启停用确认；恢复上下文不覆盖普通运行状态。默认 CLASS 协调已复用此入口；加载前拒绝可登记当前 FAILED，但不会把尚未执行的 Schema 标为已使用，也不覆盖旧启动的 UNKNOWN。
- 当前 `PlatformRuntime.modIntents` 已接开关/版本请求、精确连带确认和整组撤销的持久后端；审阅后目录、修订、运行状态或 Schema 代次变化均要求重新审阅。接纳请求只写目标意图及 WAIT_RESTART，兼容切换也封闭原及目标依赖者的新任务，已有任务继续；范围无法验证时拒绝新 Mod 任务。撤销未执行请求的摘要与旧执行行移除在同一事务中，失败整组保留，不重放未知提交。兼容版本读取 Maven 生成的实际 appapi 身份；数据准备只登记复用/首次初始化/明确来源的唯一迁移路径，不提前执行迁移。
- `ModRestartLedger` 已支持无数据及精确 READY 复用意图的新 boot 执行：旧会话必须已确认关闭，原任务/跨 Mod 占用和其他维护必须收尾；实际生命周期记录本次 RUNNING 后才归档成功，已关闭的 FAILED 才归档失败。停用确认、固定 ID 摘要和执行行移除共用事务，失败保留原操作；补写摘要不再调用作者。数据库重开把未完成 APPLYING 标为 UNKNOWN，普通启用也拒绝覆盖旧 STARTING/RUNNING/STOPPING/UNKNOWN。默认 CLASS 协调已调用该账本；首次初始化、已确认跨版本迁移及其归档已接通；明确失败重试后端见下文；已下载页已接这些明确操作；原包界面、安装事务、静态代码准入、未登记安装撤销及已安装单版本/整 Mod 删除已接通；同版本重装及明确旧程序恢复已接默认窗口；安装版已复用同一启动/停止与数据维护图，业务迁移仍待完成。
- 首次 Schema 初始化在独立准备加载器执行：预先登记 PREPARING 与原作用域，作者建表后使用 SELECT-only 身份做作者验证和实际约束复核；原连接、临时用户和加载器全部释放后才提交 READY 并进入业务。失败保留目标，收尾或归档失败仅重试原资源/元数据；重开后的未决准备转 UNKNOWN，不自动重建。校验摘要是结构与作者验证凭据，不代替迁移来源的数据核验。
- 跨版本迁移沿原请求的精确来源代次及清单链逐步执行：中间输出使用操作专属临时 Schema，最后一条迁移建立正式目标，不调用首次初始化。平台核对每步来源及最终原来源的实际结构/数据摘要，再经目标作者验证、约束复核及原资源释放提交 READY；成功或已核实失败仅清理本次已确认创建的中间结果，来源与最终目标保留。H2 原生摘要不生成 SQL 导出文件或原始数据日志，但引擎的大结果可能使用自身临时存储，关闭结果集/连接后释放。SELECT-only 并不阻止所有序列副作用；检测到来源变化时保留 UNKNOWN，不自动修复或重跑。完整边界见 [数据准备](Mod.md#schema-upgrade)。
- `PlatformRuntime.reconcileModSchema` 已提供解锁后的明确中断核对入口，沿默认来源模式图加载原版本验证器，核对原来源指纹、目标代次及未使用状态；不调用 initialize/migrate。原准备和单独 RECONCILE 记录保持关联；旧连接、临时身份及有创建证明的中间结果释放后，已证明的 READY/FAILED 与固定摘要同事务保存。核对不改开关或版本选择，不在当前会话启用业务；数据 READY 后留到下次正常启动。无法确定、旧临时用户权限漂移或连接泄漏均保留原记录，收尾重试不再调用验证器；新核对入口不接管同一 boot 的原迁移对象。默认已下载页已接明确核对，操作结果与业务运行分别显示。
- `PlatformRuntime.reviewModSchemaRetry` / `retryModSchema` 已支持当前会话的明确首次失败重试：审阅固定实际 CLASS 构建、失败代次和确认来源，接纳时重新核对选择、空闲、引用及真实 H2 会话。独立 MIGRATE 操作先登记新代次，再在来源检查后移除原失败残留，复用原初始化/迁移执行器；仅从未 READY、从未交付业务的 FAILED 目标可重建。无其他数据时可重做首次初始化，有保留数据时必须确认精确来源及唯一迁移链。开关、版本和修订不变，不排队、不自动重试，不在当前会话启动业务；数据 READY 后待下次正常启动。
- 重试清理与归档失败保留原对象，只补原释放/元数据，不再执行作者代码。重开后，重置确认之前的原失败残留可依据原记录核对为 FAILED；新目标存在时仍须证明创建和只读验证，无法证明的保持 UNKNOWN。H2 2.5.250 的会话表用户名会大写，实际会话查询统一大小写后检查，不能仅凭原作用域计数为零释放旧用户或失败目标。默认已下载页已接明确重试及原操作继续收尾。
- `PlatformModsPane` 复用原 `PlatformModIntents` 的串行审阅/提交/撤销和 Runtime 的核对/重试，所有持久访问与迁移均在后台。管理快照分别携带已存开关、单选版本、实际运行、原安全诊断、数据代次及未决操作；不暴露 SQL 或恢复正文。来源预选当前实际运行版，否则按语义发布版本降序，不按字符串或 Schema 排序；共享 Schema 的版本分别展示，仍须确认来源和最终影响。
- Mod 操作确认列出所有修改、连带停用与新任务阻断范围；取消不落库，状态改变拒绝旧确认，撤销恢复整个原组。界面锁定清空可见事实并使旧确认失效，解锁后重新读取；关闭页面不取消已接纳的运行时维护。物理收尾失败保留原重试句柄，继续收尾不再调用作者。页面当前覆盖 CLASS 登记、意图/数据维护及已发布页面的打开/固定。JAR/APP 另由实际 Runtime 提供原包安装服务，主窗口挂载 Mod → 原始包；CLASS 该页仅说明源码加载，不扫描原包或回退至安装目录。
- `ModOriginalsPane` 在解锁后的初次装配、进入页面和明确刷新时调用原服务扫描；搜索只筛选已扫描文件，不监听文件系统或自动安装。列表保留已安装、冲突及无效原包，独立列出原包已不在场的未完成安装。解压/原包删除先后台审阅，再确认具体文件和效果；锁定清空观察、销毁确认并撤销旧代次，已接纳运行时操作继续自行收尾。安装结果刷新已下载事实，单独删除原包不重置已下载页未保存草稿。刷新失败保留旧观察和原因，但禁用修改直至重读成功。
- JAR/APP 已下载页已接同版本重装、原操作继续及明确恢复旧程序。持久停用确认与关闭草稿分开，修复前展示来源、旧文件及留存选择；无匹配原包时可选择外部文件。保留操作期间封闭选择草稿和重复维护，恢复确认使用原操作版本；原包页按 REINSTALL 路由核对而不重新安装。所有来源选择/确认均受窗口锁定代次约束，结果区分修复成功、原包清理未确认、原恢复失败终态和 UNKNOWN。已以实际 Swing/H2/Windows 临时安装验证，安装版已接同一实际启动图，CLASS 不出现安装目录重装按钮。
- JAR/APP 已下载页提供独立的单版本和整 Mod 删除。确认前复核停用修订、重启确认、实际停止及任务/日志占用，展示实际文件和数据影响；默认保留原包。整 Mod 清理按原身份处理全部登记版本、所属 Schema、专属数据、精确日志类别与固定导航，保留共享资源和专属目录外的独立备份。未知阶段和文件占用继续原范围；即使所有者登记已注销，原 DELETE_MOD 仍在已下载页显示并允许明确核对。CLASS 不提供安装目录卸载；安装版启动图已接真实停用确认。

- 原包占用以原 INSTALL/REINSTALL 及 DELETE_VERSION/DELETE_MOD 记录核对路径与 Windows 身份；不可解析的来源证据仍展示并阻止原包删除，不把坏记录当无占用。人工删除原包审阅仅绑定普通文件的原生身份、长度和修改时间，不要求损坏包成功解析；提交前重新检查且与维护准入共用平台行锁。此路径不卸载版本或清理数据库，也不把文件删除后的事务异常解释为未发生删除；界面只刷新，不重放。
- `PlatformModPrograms` 将 CLASS 当前构建与安装版登记程序接入同一生命周期。JAR/APP 只加载实际程序根 `mod/<ID>/<version>` 下已登记且 READY 的精确所选版本，重验清单、来源类型、完整内容摘要和静态代码准入，不要求保留原包；损坏程序不回退到别的版本，未登记目录不自动接管。数据初始化、明确失败重试及原验证器维护复用原账本和依赖加载器。运行时开放用户操作前捕获已关闭修订；本次启动只给仍未改变、无运行及保留占用的原关闭状态确认停用，首次未启用安装也可在下次启动后维护，本次新安装不能借用旧快照。已选版本的启用/禁用仍按原重启请求执行。本机隔离安装目录验证不代表 S7 发行物验收。
- 默认 CLASS 协调只接受与实际 APP/DB 同根的明示 `wtl.workspace`。原选定版本缺失或构建变化时拒绝，不从旧登记回退；原开关及单选仍保留。锁定不阻止入口注册，但新任务仍需解锁。窗口底部显示启动数量和问题，问题详情在锁定时不可打开，已打开的从属窗口随安全锁遮挡。退出先封闭新任务，再逆依赖顺序停止；停止失败不越过使用方关闭提供方，原对象可继续未完成清理。成功启动的归档失败时先补原摘要，再停止作者；旧 UNKNOWN 不被本次失败登记覆盖。
- 普通 Mod 新任务在同一准入事务中核对自身及直接、间接提供方的当前 boot、实际 RUNNING、选择版本、清单与版本范围；提供方失效后拒绝新任务。已接纳工作继续遵守原句柄和逐调用检查，不被此新准入规则自动取消。
- 当前跨 Mod 服务工厂已支持按真实 CLASS 身份注册/发现和同步调用；提供方使用原任务的服务器与凭据范围，每次调用独立保留其 Mod/Schema。失败或实际资源未关闭时保持原任务 UNKNOWN，原版本显式恢复不重放业务调用；普通与恢复图隔离。回环 SSH/SFTP 已验证，完整 ModContext 及 CLASS 自动启停已接通，详见 [跨 Mod 服务](Mod.md#89-mod入口上下文和跨-mod-服务)。
- 当前公开日志适配器按登记类别写 H2，日常保留 100 条；默认“数据库管理”页可查看和清理到 10 条，并显示数据库与应急文件的实际计数，未知数量不显示为零。数据库失败才写固定应急文件，下次启动或刷新按原 ID 回填；损坏记录、未确认替换及归属冲突保留待核对。DEBUG 仅本次启动有效，普通日志失败不改写业务结果。平台任务结束摘要已接同事务归档；旧业务日志生产方尚未全部迁入，详见 [日志实现边界](Mod.md#database-log-management)。
- 平台任务在已知业务结果和实际资源释放后，以创建时固定的摘要 ID 写入 `app/platform_task` 类别，并在同一事务移除资源行及执行行；摘要失败或引用阻止删除则整体回滚。原宿主凭据保留 FINISHING，显式核对只补归档；跨启动只处理已持久化的已知收尾，普通未结束任务仍为 UNKNOWN。完成后的句柄不依赖已删除的执行行，重复关闭已结束资源句柄保持幂等；清理日志不重建任务或旧摘要。该接线解除已完成任务对 Mod 删除的永久阻塞；通用任务恢复页面仍待装配。
- 当前受管辅助进程工厂已绑定原任务和持久 PROCESS 占用：创建前登记，PID/系统启动时间提交后才握手；超时、取消及错帧不重放请求，STOPPED 不等于实际退出。原有子进程仍存活时保持占用，每 30 秒更新停止阻塞，不强杀；重启核对不向复用 PID 的进程发信号。stderr 已接统一脱敏日志，非零退出与已确认业务结果分开。完整 ModContext 已接入这些能力，CLASS 自动停止已接原资源检查，完整恢复界面仍待迁移，协议及保守恢复范围见 [辅助进程](Mod.md#810-辅助进程消息协议)。

  1.1 模型配置使用 `platform.ai.probe.v1` 宿主任务：只对用户明确提交的单个端点和模型发送通用文字或图片挑战；不发送部署分析资料、不自动加入用途。端点仅接受远端 HTTPS 或本机回环 HTTP，禁用重定向。随机文字回显/三块颜色顺序用于检查当前请求是否被处理，不表示已全面认证模型质量。成功后在同一 H2 凭据事务重新核对原配置和上限，保存凭据、能力修订及输出上限；并发变化拒绝旧结果，保存应答不确定保留 UNKNOWN。已有模型留空 API Key 沿用原引用，不重新写密钥或使另一项能力无故失效。新模型凭据引用由宿主生成。

原任务在锁定后可完成已接纳的验证和保存；新的配置操作仍要求解锁。中断核对保留原任务/版本，清理实际 HTTP 资源并记录中断，不重放或声称原提交一定回滚；用户须重新读取配置。前次独占启动只可释放该稳定协议可识别的进程内资源，不把任意未知占用视作已消失。

## 1. 本地化与诊断行为

1. SSH、systemd、HTTP、第三方 Provider 和远端命令返回的原始技术内容不得直接成为用户消息或部署事件。已知低层文本只可用于模块内分类；跨边界后仅保留受控安全诊断，未知异常的原始消息不得写入 UI 或诊断报告。
2. AI 提示模板使用英文编写，只发送经过既有边界脱敏的结构化事实；调用时显式传入受限响应语言，当前桌面语言为 `zh-CN` 时请求 Simplified Chinese，为 `en` 时请求 English。
3. 桌面端目前只支持 `en` 与 `zh-CN`。没有已保存偏好时，中文系统语言使用 `zh-CN`，其他系统语言使用 `en`；用户明确选择后，以持久化偏好为准，运行期间不跟随系统语言自动变化。

## 2. 错误恢复与验证边界

1. 自动恢复仅适用于幂等、可验证、可回滚行为，包括有界重试、候选清理、事务回滚、部署回滚、重连和状态复核。认证失败、权限不足、主机指纹拒绝、协议不兼容、完整性失败、数据库损坏、较新 schema、未知远端状态、回滚/清理不可验证和 JVM 致命错误不得冒险自动修复。
2. 恢复结果必须记录为 `NOT_REQUIRED`、`NOT_ATTEMPTED`、`SUCCEEDED`、`FAILED` 或 `UNVERIFIED`。回滚或清理无法验证时部署终态固定为 `MANUAL_RECOVERY_REQUIRED`；不得以异常被捕获、命令已发出或重连成功冒充业务恢复成功。
3. SSH 连接与只读能力采集最多重试 3 次、固定间隔 250 ms；认证、主机指纹拒绝、协议不兼容和线程中断不重试，中断必须恢复线程标记。Git 瞬时网络失败最多重新创建临时工作区重试 2 次、固定间隔 500 ms；每次失败都先完成可验证清理，工具缺失、引用无效、完整性失败和中断不重试。
4. SQLite 连接必须设置 5 秒 `busy_timeout`，启动执行 `quick_check`，事务保证提交或回滚。锁定允许有界等待；损坏、较新 schema、磁盘不可用或回滚失败必须明确停止并请求处理，不自动修复数据库，也不修改现有 schema 作为错误治理手段。
5. 固定数据目录下的 `data/error-logs/` 保存 UTF-8 文本报告：单份最多 256 KiB，最多保留 50 份，启动和写入后清理最旧文件；临时文件完整写入后使用原子移动发布。报告写入失败不得递归生成新报告。
6. 报告只包含结构化字段、安全诊断、异常类名和栈帧；不得包含未知异常原始消息、密码、私钥、API Key、秘密配置、源码正文或未脱敏第三方响应。UI 展示本地化消息、错误码、operationId、安全摘要、恢复结果和报告位置；平台支持时可打开错误日志目录，否则保留可复制路径。
7. `VirtualMachineError`、`LinkageError` 等致命 JVM 错误只做尽力记录后退出，不承诺继续运行。建议型 AI 失败只生成 `ai.*` 描述并保留确定性分析结果，不获得执行授权。App Agent 的独立决策与审批协议只在登记的事务边界选择后续动作；本地验证、实际执行及回滚仍由确定性代码负责，模型拒绝或未知结果不能被错误分类绕过。
8. 故障注入至少覆盖数据库锁定/损坏/回滚失败、目录不可写、归档中断/清理失败、Git 工具缺失/超时、SSH 瞬时断线/认证失败、健康失败回滚、回滚不可验证、AI 不可用、报告截断/轮转/脱敏、启动失败和未知 UI 异常。局部测试只证明本地错误语义；真实 Linux 修改路径仍必须通过现有产品入口验收。
9. `shared/backup` 的归档、加密、恢复和离线迁移使用共用失败契约与窄端口。当前 manifest 为 schema v6，激活配置 v5、运行时持久化 v5、资源载荷 v2、helper v10；桌面数据库 schema 与这些协议版本独立。旧归档不转换且拒绝读取，不伪造缺失路径、发布或秘密绑定。组件发布 SHA-256、精确秘密修订、应用 `releaseSetSha256` 和秘密并集必须一致；秘密值只在整体认证后交接可清零载荷。Jackson/Commons Compress 只处理严格有界的本地编码与归档，不决定宿主路径；远端操作通过 `linux.protocol`，`linux-sshd` 不反向依赖 `backup`。本地归档先完整复验，再无覆盖原子发布并独立回读。恢复重新解析经审阅存储绑定，具体 FHS/SQLite 规则见 [Linux 受管数据](#linux-storage)。能显式覆盖监听端口的组件可使用回环候选端口，其他 SQLite 应用先停旧图，再启动访问独立数据的同端口候选；不猜测监听参数。SQLite 在候选健康后提交，服务器数据库沿用整应用短停写提交；正式端口仍需二次组件及整应用健康。失败先停写，再回退数据库、配置和发布；停写或回退无法证明则保留现场并返回人工恢复。离线迁移复用完整备份与恢复，保留源图，只返回等待人工流量切换；远端成功与本地接管状态分别记录。Web 使用相同规则，不另写恢复实现。
10. `app/windows.update` 只在软件包大小/SHA-256、Ed25519 固定信任根、签名有效期、撤销状态、版本策略和架构全部通过后返回验证证据；等版本和未批准降级必须拒绝，紧急回退同时需要签名清单标记与用户批准。主进程只允许停收任务、成对备份程序/SQLite 并形成不可变交接；更新和卸载交接必须使用严格版本化、有界、用途隔离且经 HMAC-SHA256 认证的跨进程文档，认证通过前不得重建路径、决定或更新证据，错误密钥、篡改、截断、跨用途重放和认证后畸形载荷均失败关闭。编解码器不持有调用方密钥；密钥安全交付、交接文件位置/ACL 和一次性消费由生产独立执行器规格负责，不得把测试密钥或当前 JVM 内存传递冒充生产接线。替换、迁移、健康和成对回滚只允许在独立更新器验证自身身份、主进程退出和交接真实性后执行。`app/windows.uninstall` 不设置数据决定默认值；凭据范围固定为唯一 `WindowsToLinux/*`，不得由调用方缩窄、扩大或改名。外部执行器验证自身身份、主进程退出和交接真实性后还必须重新验证 jpackage、安装/数据标记及该固定命名空间，再按所选范围删除并报告精确残留。`app/secret` 的 Credential Manager 适配只删除符合应用生成键规则的目标，命名空间内其他目标报告为残留；源码、独立备份和远端应用不进入卸载端口能力。
11. 0.5 期现有 Web 仅用于回环内部测试，无登录、管理员初始化、会话、CSRF 或公开部署能力，不得作为可上线服务。0.6 期未实施的生产服务台与账号方向已由 1.1 工程取代；新官网只记录介绍、教学、公开下载和投稿收集方向，详情见 1.1 主文档。

## 3. 桌面端数据目录

桌面应用不允许自定义 `data` 位置，也不使用注册表、命令行参数或路径指针文件覆盖默认位置。`main` 根据运行模式解析唯一数据目录：

| 运行模式 | `data` 目录                                          |
| -------- | ---------------------------------------------------- |
| CLASS    | `src/app/db/data`，与 `src/app/db/target` 同级。     |
| JAR      | DB 模块 JAR 文件（如 `DB.jar`）所在目录下的 `data`。 |
| APP      | `jpackage` 启动器 EXE 所在目录下的 `data`。          |

- `jpackage` 安装包启用按当前用户安装和安装目录选择，避免默认安装到普通用户不可写的 `Program Files`。
- CLASS/JAR 模式固定使用 `app/db/persistence/connection/PlatformDatabase` 类作为代码源锚点，不依据主入口模块的位置或固定 JAR 文件名猜测数据目录。该类仍属于同一个 `app/db` Maven 模块，移包不改变代码源或数据根；Schema 所有者口令仍按原已编码数据库用户名派生。
- CLASS 模式优先依据 DB 模块的 Maven `target/classes`/`target/test-classes` 定位模块；JetBrains 等 IDE 输出不在模块内时，只有验证工作区中的 `windowstolinux-app-db` POM 后才解析到 `src/app/db`，不会直接把工作目录当作数据基准目录。
- 应用启动时必须验证解析出的 `data` 目录可以创建和写入；验证失败则停止启动并提示用户重新安装到可写目录。
- 不得静默回退到用户目录、临时目录或其他位置，避免同一安装出现多个不一致的数据副本。
- APP 模式下数据始终跟随 EXE 安装目录；升级和卸载时按 0.4 期文档定义的规则处理。

  1.1 默认启动仅打开 `platform.mv.db` 与 `db-access.bin`，使用 H2 2.5.250 和 Windows 当前用户 DPAPI；缺失配对、身份错误或材料损坏时拒绝打开，不覆盖重建。首次安全设置后可解锁，再次启动保持锁定。正常退出等待凭据操作、持久化非终态任务及物理连接释放；UNKNOWN 不视作已完成。平台子目录职责见 [Mod 数据布局](Mod.md#mod-database)。

程序目录独立定位：JAR 使用 main.jar 所在目录，数据仍按 db.jar；APP 使用 EXE 目录。CLASS 程序根须是经 DB 模块 POM 和 main 模块位置验证的工作区，主模块输出须位于该工作区内；不从无关工作目录加载 Mod。

以下为保留的 0.x 数据布局。新默认入口不读取或改写 `windowstolinux.db`，也不预建旧业务的 backups 目录；此处记录仍待业务 Mod 迁移的原结构：

```text
<resolved-data>/
├─ windowstolinux.db
├─ work/
├─ backups/
└─ error-logs/
```

- `windowstolinux.db`：服务器非秘密资料、应用图、当前发布、运行时、配置引用、资源绑定和操作历史；
- `work`：可重建的源码归档、备份取材和恢复候选工作区；
- `backups`：软件保留的正式备份，包括离线迁移的最终停写备份；
- `error-logs`：有大小和数量上限的 UTF-8 错误诊断报告。

- `main` 只能从 `RunModeResolver` 已解析的唯一 `data` 根派生这些固定子项；不得写死 `/var/lib`、Windows 盘符、用户目录或临时目录，也不得新增覆盖入口或静默回退。
- 桌面 SQLite 保存文件绑定和数据库绑定等管理记录；分析得到的逻辑 `ComponentDataPath` 作为经审阅元数据保存，不得直接拼成桌面物理路径。数据库连接保存非秘密信息和精确 `SecretReference`，不保存密码值。
- 实际部署应用的持久化文件、容器卷和数据库保留在目标服务器或对应数据库服务中。桌面端通过 `work` 收集、验证和暂存备份及恢复材料，通过备份归档保存时间点副本。

<a id="linux-storage"></a>

### 3.1 Linux 受管数据与取材目录

受管应用标识记为 `A`；多组件继续使用各组件现有独立标识。`ManagedStorageLocation` 和 `ManagedStoragePlan` 为桌面、Web、原生及容器提供同一份路径契约。

| 内容                 | 默认宿主位置                                                                                 |
| -------------------- | -------------------------------------------------------------------------------------------- |
| 程序、版本及当前入口 | `/opt/windowstolinux/apps/A/{releases/<摘要>,current}`                                       |
| 部署环境及秘密配置   | `/etc/opt/windowstolinux/apps/A/` 下的不可变修订                                             |
| 显式配置文件         | `/etc/opt/windowstolinux/apps/A/files/<绑定>/revisions/<内容摘要>/value`                     |
| 普通文件             | `/var/opt/windowstolinux/apps/A/files/<绑定>/`                                               |
| SQLite               | `/var/opt/windowstolinux/apps/A/databases/<数据库标识>/application.db`；显式文件名按声明保存 |
| 自定义相对路径的实体 | 安装根内 `persistent/{configuration,files,databases}/<绑定>/`                                |

- 默认、明确自定义和未确定分别保存。未确定、变量未解析、冲突、越界及异常文件一律报错，不回退默认位置。自定义绝对位置必须位于本应用安装根的严格子路径，排除 `releases`、`current`、`persistent` 和控制目录；自定义配置通过安装根内的不可变修订映射到声明的访问位置。
- `windowstolinux-storage.properties` 声明配置和文件的资源类型、应用访问位置、环境变量接入、宿主选择、读写模式及可选种子；SQLite 在 `windowstolinux-db.properties` 声明。创建目录不等于完成接入，默认位置必须交付到应用已经支持的环境变量或明确访问路径。配置模板只在明确声明时复制。
- 客户端和 helper v10 均校验应用归属、路径组件、物理父目录、符号链接、硬链接和特殊文件；远端只允许自身创建并记录的精确映射。执行前再次验证，现有未受管目录不能自动接管。原生服务使用固定不可登录的独立系统账号，程序和配置 root 持有，只向已声明数据开放写入；系统保护和临时目录隔离保持生效。
- Docker/Podman 使用经过校验的宿主 bind mount，保留镜像内访问路径，配置只读、根文件系统只读、临时写入使用 tmpfs。SQLite 使用独立宿主目录和容器内精确别名；必要时从验证后的镜像生成只读目录视图，避免遮住程序文件。镜像种子只在首次创建时导入，现有数据不重新播种；未声明的引擎卷或额外挂载拒绝。
- SQLite 使用宿主 `sqlite3` 一致性备份和完整性检查，业务镜像不需要包含该工具。种子及初始化 SQL 仅在目标数据库首次创建时使用；已有数据库不覆盖、不重跑初始化。应用驱动由项目依赖提供。
- 完整备份仍至多包含一个受支持数据库。整应用停写后收集发布、文件、配置、OCI 和数据库制品；普通文件归档排除 SQLite 文件及 WAL/SHM/journal、受管别名和可重建的容器视图，数据库单独保存为一致性制品。
- 恢复按审阅绑定重建路径。原生候选使用独立账号和 systemd 路径映射，容器只挂候选目录；硬编码绝对路径不能访问正式数据库。SQLite 候选健康通过后停写，在目标文件系统暂存并切换，保留原文件和伴随文件；失败先确认进程停止，再恢复旧数据库、配置和发布并检查健康。无法证明完整则返回人工恢复状态。
- 旧 `/var/lib/windowstolinux/{apps,configurations,data,secrets}` 布局明确拒绝，不迁移、不删除。旧 helper、旧运行时/资源载荷及旧备份格式明确拒绝，不自动清空桌面或 Web 本地数据。新的默认布局遵循 FHS `/opt` 配套规则；允许用户在安装根内自定义持久位置是本产品例外。
- 部署工具的候选工作区、事务记录、身份登记和 `/var/lib/windowstolinux/backups/` 暂存仍归工具管理。构建临时身份及限容卷不改变；数据库服务器内部数据目录、Docker/Podman 引擎数据根不在迁移范围。
- 新布局真实 Ubuntu 24、CentOS Stream 9、原生/Docker/Podman 及双服务器恢复矩阵均为 `RUNTIME-PENDING`；旧 helper 的实机记录不作为新布局证据。

## 4. Git 项目准备边界

Git 项目进入分析和部署流程前，由 `git` 模块统一准备：

```text
deploy 提交 Git 来源和目标版本
→ git 解析并拉取仓库
→ git 将分支或 Tag 固定为具体 Commit
→ git 通过 source 生成并校验规范化源码快照
→ git 返回源码快照和版本信息
→ deploy 将项目快照交给 analyze
```

- `git` 只负责取得确定版本的项目源码，不执行仓库内脚本或构建命令。
- `git` 通过 `source` 复用源码快照、归档和安全校验规则，不复制对应实现。
- `analyze` 只读取准备好的项目快照，不自行连接 Git 仓库。
- `deploy` 负责编排 Git 准备、项目分析和后续部署步骤。

## 5. 环境部署边界

环境准备由分析、部署决策、Linux 公共契约和 SSHD 实现四类职责协作完成：

```text
linux-sshd 通过 linux 契约采集服务器已有环境
→ analyze 比较项目需求与服务器事实
→ deploy 生成环境准备计划并处理风险确认
→ linux-sshd 通过 linux 契约执行受控安装和配置操作
→ deploy 验证结果并决定继续、停止或恢复
```

- `analyze` 决定项目**需要什么环境**，输出结构化环境需求和不兼容项。
- `linux` 定义**服务器有什么环境**以及**允许怎样执行 Linux 操作**的类型化契约、请求和结果。
- `linux-sshd` 使用 Apache SSHD 实现环境采集、受控传输、安装、配置和复核，不开放原始 SSH 通道或 SFTP；自主命令经受管任务沙箱与公共审批边界执行。
- `deploy` 决定**是否安装、按什么顺序安装、何时确认以及失败后怎么办**。

因此，环境部署的业务流程归 `deploy`，公共远程能力边界归 `linux`，具体 Linux 安装、配置和检查动作归 `linux-sshd`。

### 5.1 系统准备与安全策略

- 发行版准备只在明确批准下执行固定安装和系统前置操作，能力采集保持只读。系统包安装与 SELinux/重启分别确认；普通安装授权不能替代系统变更授权。
- CentOS Stream 9/10 的 SELinux 计划绑定服务器、启动标识、配置摘要和阶段。原始配置及非秘密进度只放入 `/var/lib/windowstolinux/system-preparation/selinux/`，不保存源码、应用数据或凭据；恢复和新指纹认证规则见[0.4 期系统准备](development/PHASE-0.4.md#system-preparation)。
- DNF 9 固定包事务同时更新官方 OpenSSH 包并检查 sshd，服务层须经新 SSH 认证重新采集能力。CRB 只在明确 CentOS 9/10 的事务中临时启用既有仓库，不增加仓库或永久改配置。
- SELinux 下的 systemd 隔离使用只读临时 `/run/systemd` 并仅映射必要身份查询目录；类型化服务经 `/usr/bin/env` 使用发行版普通服务域。审计明确读取日志，不关闭隔离、不放宽策略；Enforcing 不等于应用专属 SELinux 策略。Ubuntu 和其他系统保持各自适用实现。

### 5.2 构建、运行与恢复身份

管理、临时构建和运行身份分别表达；构建不使用 deployer 或运行服务的固定 UID。workspace helper 负责限容卷、身份记录和清理，build 负责构建编排，公共脚本归 generation.script，容器构建归 build.workload；运行身份分别归 runtime.systemd 和 runtime.container。

运行服务使用每组件固定系统账号；不再依赖 `/var/lib/private` 或动态运行 UID。候选使用单独账号与隔离映射，只有已声明的数据目录可写。清理核验进程、挂载、身份归属及关联数据，不删除仍持有应用数据的账号。详见 [Linux 受管数据](#linux-storage)与[0.4 期 FHS/SQLite](development/PHASE-0.4.md#fhs-sqlite)。

## 6. 受管应用生命周期边界

部署成功后，启动、停止、重启、状态刷新和开机自启管理继续复用既有模块：

```text
平台端 service 提交受管应用和生命周期动作
→ deploy 校验应用标识、资源归属、动作语义和影响范围
→ linux-sshd 通过 linux 契约查询目标服务器上的实际运行与自启状态
→ linux-sshd 通过 linux 契约执行经过校验的 systemd、Docker 或 Podman 动作
→ deploy 执行健康检查、停止确认或自启状态复核
→ 平台端 service 记录结果并更新界面
```

- `model` 表达受管应用标识、运行方式、实际运行状态、开机自启状态、生命周期动作及结果，不包含执行逻辑。
- `linux` 只定义经过校验的资源查询和生命周期动作契约；`linux-sshd` 负责具体远程执行，不通过同名服务、容器或目录自行推断资源归属。
- `deploy` 统一处理单组件生命周期语义和安全校验；0.3 期多组件操作仍由它依据组件依赖图编排，不新增独立生命周期模块。
- `app/service` 或 `web/service` 提交用例并展示结果，平台 `db` 只保存受管标识和最后观测值；目标服务器实时查询结果才是运行与自启状态的事实来源。
- `web/task` 在 0.5 期把生命周期修改作为持久化任务调度，并与同一服务器上的部署、恢复、迁移等修改任务互斥。
- 启动不改变开机自启，停止不关闭开机自启，重启保留原有开机自启设置；单独修改自启状态也不得静默改变当前运行状态。
- 启动和重启后必须执行健康检查，停止后必须确认目标已经停止，自启变更后必须复核 systemd 单元或受控容器自启单元、策略的实际状态。
- 原生 systemd 观察必须保留 ActiveState、SubState、Result、ExecMainCode、ExecMainStatus 和 MainPID；failed 及失败重启等待显示 ERROR，信息缺失或查询失败显示 UNKNOWN。旧 helper 必须提示先准备环境，容器观察规则不变。ERROR 只允许刷新、停止和关闭自启，确认 STOP 后再 START，仍执行归属和依赖保护。
- 只有明确 STOP 才能在 MainPID=0、控制组无进程且读取成功后，按需 reset-failed 当前归属单元并复核 inactive；停止前后结果与退出码进入现有 observation evidence。刷新不得清理失败，不允许全局 reset-failed 或把 Yarn 129 统一视为成功退出。
- 回环 SSH 服务器夹具只存在于测试源码，显式跟踪包含重挂起在内的 accept 回调，并在关闭执行器前有界排空；后台未处理异常必须导致测试失败，原始断言为主因、收尾失败为 suppressed，最终恢复原处理器。生产 SSH 客户端保持同一会话边界，Maven 模块现为 31 个 POM。
- 资源丢失、标识不匹配、检测到外部修改或无法连接时必须返回明确的未知或异常结果，不得猜测执行、自动重建或标记成功。
- 完整受管生命周期只用于可验证归属的 WindowsToLinux 应用。经用户扫描选择并绑定实际身份的外部 systemd/Docker 对象仅开放状态、入口、启动、停止和重启，保留原配置，不开放受管更新、回滚、备份或自启；每次操作复核身份，不能作为任意服务器管理入口。

## 7. 备份、恢复与迁移边界

备份、恢复和跨服务器迁移由 `backup` 统一编排：

```text
平台端 service 提交备份、恢复或迁移请求
→ backup 生成版本化清单和受控计划
→ linux-sshd 通过 linux 契约采集或传输远程应用数据
→ backup 创建或校验备份包并准备候选恢复
→ deploy 启动候选版本、执行健康检查并安全切换
→ backup 返回完整性、兼容性、恢复或迁移结果
```

- `backup` 负责备份格式、清单、校验、恢复计划、兼容性结果和跨服务器迁移流程，不管理桌面或 Web 主机上的固定存储目录。
- `app/windows` 或 `web/file` 只向 `backup` 提供经过边界校验的输入、输出或工作位置，不解释备份内容，不执行远程 SFTP。
- `app/secret` 或 `web/secret` 管理平台凭据；可移植备份密码派生和秘密信封由 `shared/backup.crypto` 共用，平台服务提供受控秘密修订并负责及时清零。归档成员保持加密，不把平台主密钥写入备份。
- `linux` 定义远程采集、传输和受控 Linux 操作契约，`linux-sshd` 负责具体实现，`deploy` 负责候选版本的启动、健康检查和切换；三者不重复实现备份包格式。

## 8. 业务与消息契约

1. 英文基准消息与简体中文映射的消息键集合、每个键的命名参数完全一致。

3. 原始 SSH、systemd、HTTP、第三方响应和远端命令输出不得为适配界面语言而翻译或改写，也不得与本地化用户摘要混为同一字段。
4. 除 `Messages_zh_CN.properties` 外，`src/**/src/main` 下的 Java 字符串、字符和文本块以及非 Java 文本资源不得包含汉字；中英双语 Java 注释、文档、测试和专门验证中文翻译的夹具不受此限制。
5. `app/ui/deployment` 只收集 `contract.definition` 中声明的表单输入并通过现有服务门面提交；运行时、配置、秘密引用、数据库范围和 Git 引用由服务用例解析，UI 只展示门面暴露的纯数据结果；标准表单不得接受自由 Shell 或任意主机挂载；Agent 界面展示实际命令及源码差异，经公共审批后执行，不接收数据库密码明文或未审阅秘密文本。标准单/多组件部署必须明确区分数据库范围“尚未审阅”“已审阅且为空”和一个或多个已审阅的服务器 DB 绑定；尚未审阅时不得进入部署。标准模式的项目类型、运行时字段和容器选项改变后，必须重新进行静态源码分析；自主 Agent 重新校验有文件证据的通用交付描述，不调用静态分析；桌面页面状态切换外观或语言时必须保留这些尚未提交的表单值。
6. 类型化部署分析必须把确定的源码元数据作为可审阅的 `DeploymentRuntimeAssessment` 返回，而非由桌面表单写死语言版本、入口、产物目录、端口或卷。仅在值唯一、受支持、边界安全且具有 `AnalysisEvidence` 时才可回填；范围、冲突、任意脚本和文档文字只能作为未解决的用户输入，绝不转换为命令。
7. 本地目录和 Git 来源都必须在 `app/service/source` 汇合为同一 `ReviewedSourcePreparation`，并以归档摘要绑定 `SourceRevision`。网络 Git 来源必须使用无凭据 URI、允许主机、固定 Commit 和受控工作目录；桌面 UI 不得调用 Git 进程、数据库或秘密存储实现。
8. 用户可见和持久化语义统一使用“发布身份摘要”（`release_sha256`）；“制品”仅指构建中待验证的文件。SQLite 结构、事务、历史保护及凭据关联统一见[数据库入口](#数据库入口)与[事务及历史保护](#事务及历史保护)，本节不另行复制数据库契约。
9. `DeploymentSupportProfile` 是标准部署的语言、框架、支持等级与真实验收目标范围声明；自主 Agent 不受此类型目录约束。`RECOGNITION_PREVIEW` 只能由 `analyze` 读取有界路径和固定元数据，必须使用 `NONE_PREVIEW`，不得创建源码归档、部署适配器、远端构建渲染器、helper 参数或生命周期入口。标准分析中的 Shell 文件只作为识别证据，不直接转换成命令；自主 Agent 生成命令另经独立审批及受限执行。
10. 标准部署中每个可进入计划的源码路径必须产生一个精确 `DeploymentArchitectureType`，由 `DeploymentProjectType × DeploymentBuildToolType` 唯一标识；分析注册表、构建 Renderer 注册表、主机生态工具版本和运行时能力判断必须对该身份闭合，禁止恢复宽泛构建工具身份或以参数化 Renderer 隐藏架构差异。新增身份在逐目标产品入口证据完成前保持试验适配或 `RUNTIME-PENDING`。

### APP 网页控制台救援边界

默认桌面的“任务与恢复”页经内部 `contract.spi.TaskManagement` 访问中央任务，由 `PlatformTaskManagement` 核对当前安全状态并调用原句柄协作取消或原任务核对。任务清单及操作在后台执行，取消不强制终止或提前释放资源；精确宿主救援身份走 `PlatformRecoveryService` 的旧命令确认，元数据归档路径不调用业务恢复。任务页锁定/关闭时清空当前数据并销毁确认，旧代次的异步结果不能重新显示。已知结果归档后从清单移除，摘要进入既有数据库管理页。默认启动已装配原版本 Mod 恢复图；明确核对结束后调用原图清理，失败保留会话或已核验收尾凭据，退出时重试原清理。缺少登记不会放开原占用。

恢复图依据现由 `PlatformTaskAdmission` 在原准入事务捕获，`TaskLedger` 与任务行原子保存至既有 `recovery_json`。格式 2 固定原 Mod 与全部传递提供方的版本、内容摘要及数据代次；不保存源码、参数、返回值或凭据，也不新增资源申请。格式 1 保持原宿主/旧任务语义并明确返回“无原图”；格式及原任务/Schema 申请不一致时拒绝执行，不能用当前登记重建旧事实。`PlatformModRecovery` 在普通启动准备前校验完整原图及 `service.v1` 记录；共享提供方合并成一个恢复组，身份冲突或代码变化时整组保持阻断。只有原版本 RECOVERY 会话登记任务核对，页面隐藏、服务与普通图隔离、新业务提交拒绝；独立普通部分继续。原组全部任务结束后逆序停止。当前启动保留普通启用阻断，用户下一次手动重启才使用所选版本。

`ModRecoveryLedger` 复用 `mod_operation` 的 RECONCILE 类型，为组内每个成员保存固定操作/摘要身份、完整原图及旧运行凭据；`mode=MOD_SESSION` 与 Schema 核对区分，阶段固定为 RECOVERING → VERIFIED。记录先于作者构造，并在原任务归档后继续存在。会话实际释放后保存 FINISHING/VERIFIED/SUCCEEDED，随后原子写摘要、确认精确旧运行状态和删除操作行；仅归档失败时跨启动补元数据，不重新启动作者或重做任务。未应用 WAIT_RESTART 意图保留，恢复不提前应用开关、单选或迁移。

`PlaywrightDriver` 保留创建返回的原连接和原 `Process`，不把依赖的 `close()` 返回视为驱动已退出。关闭被接受后仅等待原进程；仍存活时保留工作线程、隐私登记和任务占用，后续收尾不重新创建驱动。即使进程已退出，连接清理异常也不能被忽略。该适配针对固定 Playwright 1.58.0：其公共 API 不提供进程对象，因此在创建前核验内部 `driverProcess` 字段结构和访问能力，再取得原对象；依赖升级须重验这个边界。创建中途失败且无法取得原对象时保留未确认状态，不推定资源已释放。

`app/linux/recovery` 独占 Playwright Java 1.58.0 对象、终端契约与安全 Problem，并在专用线程处理页面事件和终端输入；不接管个人浏览器配置。`app/windows/window` 仅提供所属子进程窗口隐私适配，不持有 Playwright。关闭先封闭新调用；等待超时保留同一个清理任务和工作线程，后续关闭继续观察原任务。实际浏览器进程、工作线程及隐私登记全部释放后才报告完成。`TaskBrowserSession` 已连接原中央任务：创建前持久登记 `browser.v1`，实际 PID/系统启动时间提交后才允许终端使用；完整清理后先记录 `browser.closed.v1`，再释放占用，失败保留原对象和记录。关闭检查点保留原创建事实，只允许原物理启动、原任务和原资源身份确认，不能退回创建状态；检查点或释放失败可在原对象重试。

跨启动核对原救援任务时，只有明确关闭检查点允许释放浏览器占用；STARTING/STARTED、格式不合法或其他未确认资源使整次核对保留 UNKNOWN，不先释放其中已关闭的部分。仅凭主 PID 消失或启动时间不同不足以证明驱动等资源全部退出。核对仍要求用户确认旧终端动作已结束，只记录中断，不重放模型请求、浏览器命令或 SSH 业务。已通过真实浏览器关闭/H2 故障注入及数据库重开验证；重开测试使用受控持久状态，不代表真实 JVM 崩溃或远端修复验收。

默认 `DesktopMain` 的服务器页已装配独立救援：`platform.ssh.rescue.v1` 使用 `@platform`、实际宿主版本及完整 SERVER 占用，浏览器、模型和 SSH 都属于原中央任务，不创建旧独立执行器。固定 SSH 复核先验证保存的主机指纹和认证，再执行宿主固定回显（15 秒、1024 字节）；只有该平台任务类型可以调用此入口，不改变公开 Mod 命令审批。原控制器直接在中央回调运行、使用同一任务 UUID 记录状态和动作摘要，取消不强制中断线程。认证、主机身份及非连接错误停止本轮；只有明确连接失败可触发只读再查。未确认终端命令不重放，原任务核对要求用户确认旧动作已结束。

救援临时状态与事件现在随原中央任务收尾：业务结论和实际资源确认后，在同一 H2 事务写入固定 `browser_recovery` 摘要、清理 `browser_recovery_event/task`，并提交平台任务摘要及执行清理。救援摘要 ID 按 `WTL-BROWSER-ARCHIVE-1:` 与原持久 `archive_log_id` 确定性派生；记录原协议、服务器、最后观察状态/事件、命令 SHA-256、事件及提交次数，不保存命令或终端正文。任一步失败整体回滚，原任务保留 FINISHING；补归档不再探测 SSH 或调用作者恢复。原状态记录不被日志清理直接删除，迟到回调不能重建已结束记录。没有原中央任务、协议/服务器不匹配的记录保留，不能仅凭 RECOVERED 字样自行清理。

救援状态机、预算、动作确认、探测分类及核心快照现归 `app/linux/recovery`，只接收无凭据的救援端点和公开 `Problem`，不引用 service、db 或旧 shared 失败类型。该模块直接依赖既有 `app/ai` 的协议。`app/service/recovery` 负责中央任务、配置、模型、持久记录与 UI 值转换；剩余旧入口通过 `RecoveryProbeAdapter` 转换旧 SSH 失败，保留事件码和诊断身份，不把旧异常带回核心。`SshRecoveryApplicationFacade`、`SshRecoverySession` 与服务层 `RecoverySnapshot` 仍是 UI 契约，视图不直接引用 Linux 实现。

救援固定提示、建议影响分类和严格 JSON 解析归 `app/ai/recovery`；旧 `shared/ai/recovery` 网络客户端继续复用该协议，待整体入口切换后移除。新 `PlatformRecoveryModels` 经原平台任务及实际 AiService 分别调用视觉/语言用途，不使用审批模型生成建议；宿主输出上限为 2048 Token，并按各候选模型已配置上限取较小值，每次调用期限为 60 秒。普通 Mod 显式 AiRequest 的超限拒绝规则不变。完整响应结构不合格不另换模型；发送后结果未知保留原任务，不请求下一条建议。该模型适配已接默认救援入口。模型仅生成观察和建议，不执行命令；`shared/linux` 与 `shared/deploy` 不引用 Windows。

桌面模型用途以 `AiPurposeType` 明确划分部署、审批和视觉；`AiCapabilityType` 区分文字/图像测试。显示排序与用途调用顺序分离，任务持有精确配置快照。视觉识别只返回受控观察，部署和审批保持独立上下文。APP SQLite v21 用 `ai_model` 保存用途、独立顺序和能力修订，任务及事件表保存非秘密历史。三模式自动部署不接入浏览器救援，独立救援继续要求用户逐项授权。

## 10. 共享备份采集与结构化救援错误

`shared/backup/execution/collection/BackupCollectionService` 统一准入、原始运行状态观察、依赖顺序停机、发布和资源及数据库采集、运行恢复、健康复核及远端清理。`contract/definition` 的输入携带已审阅绑定、维护标记归属及整应用健康契约；`contract/spi` 由各端提供私有素材输出、配额、取消和进度。桌面及 Web 保留原有整应用健康来源，不从组件配置推导新规则。

取消仅终止采集，必要恢复完成后才向调用者返回取消。恢复无法验证时报告人工恢复状态并保留远端素材与维护标记。只释放本次持有的维护标记；外层迁移持有的标记不在采集步骤释放。原始失败、恢复失败与各项清理失败均保留。

平台 SSH 探测携带原始 `Problem`；只有明确连接失败进入重试，认证、主机指纹、凭据、中断及其他失败分别处理。剩余旧 SSH 入口的 `FailureDescriptor` 在服务边界转换。`RecoverySnapshot` 分开表达生命周期与可选失败原因，UI 展示安全消息、事件码和诊断身份，刷新不重复写旧诊断报告。浏览器、观察、持久化记录及清理错误保留原结构化证据；数据库和诊断报告不记录终端内容、命令正文或模型响应。

Web JSON 编解码由 `persistence/serialization/WebJsonCodec` 承担；`contract/validation/WebRequestValidator` 处理字段及非秘密输入校验；`interaction/WebTaskInteractionService` 转换确认、输入与进度交互。任务接口仍位于 `contract`，HTTP 与任务协议不变。桌面 AI 门面公开全部模型展示顺序、各用途成员/启用/顺序、独立能力验证及冻结调用链；当前用途配置与顺序由持久化约束和对应测试保护；SQLite 初始化及不兼容结构处理见[数据库入口](#数据库入口)。

### App 部署模式及 Agent 边界

- App 服务层统一分流静态、AI 辅助、自主 Agent，并负责凭据、数据库和 Swing 交互适配；默认仍为 AI 辅助。当前 Web 不提供自主 Agent 界面。
- `standard/deploy/assistance` 独立维护只读分析、参数建议、部署前检查及失败恢复协议，不依赖 `shared/agent`，不新增 Maven 模块。标准程序推进正常步骤；辅助模型只在歧义、缺项、冲突或失败时分析，并在失败后选择登记恢复工具。静态流程不创建模型会话，辅助流程不接受自由命令、自定义健康命令或源码补丁。
- `agent` 串行读取源码、检查远端、提出组件依赖方案、生成命令、读取实际结果并修正；不调用静态分析兜底。成功需要受管发布、全部组件健康及方案中显式声明的整应用健康探针证据。
- `deploy/approval` 在实际远端命令边界执行本地验证和独立 AI 审批。**人工审核**逐串确认；**自动审批**仅高危需确认；**完全控制**在 AI 通过后执行。完整脚本为一次审核单元，命令、目标、身份或证据变化后重新审核。
- Linux 任务源码只通过专用补丁接口修改。人工审核逐行确认；自动审批首次获得任务授权，后续高危再次确认；完全控制不需人工确认。修改前摘要、差异、独立审批和执行结果绑定同一修订；修订变化使旧构建和批准失效。
- 管理连接沿用 root 身份；项目命令在 helper 隔离的临时非 root 身份下执行，运行服务使用受管独立身份。
- 本地原项目与冻结快照只读；构建输出单独可写。选定模型仅收到按需读取且过滤秘密的文本；持久日志只记录非秘密摘要、状态及修订，不保存完整源码、提示词或秘密。
- APP 全新数据库 schema 21 保存现行任务执行语义，不导入旧任务。运行描述格式 7 支持通用进程，兼容既有版本的明确字段；helper 协议为 10。
- 未知写入结果禁止自动重放；无法证明恢复的任务保留人工恢复状态。真实模型、Linux 权限及端到端可靠性仍为 `RUNTIME-PENDING`，历史验收不能替代新模式验收。

### AI 命令审批长期规则

今后所有涉及 AI 命令执行的新增或调整功能，统一使用“人工审核、自动审批、完全控制”三档，名称及语义不得另行定义。

- **人工审核**：每条实际命令或完整脚本均须用户审核通过后执行。
- **自动审批**：只有高危命令需要用户审核。
- **完全控制**：AI 审核通过后直接执行，无须人工确认。

三档均须通过本地校验和独立 AI 审核。AI 拒绝、审核不可用或本地禁止时不得执行。阶段批准不能代替实际命令批准；命令内容、目标、执行身份或相关证据变化后重新审核。保留现有枚举和持久化值，不因文案或内部类名调整改变历史含义。公共审批归 `shared/deploy/approval`；Agent 专属源码补丁授权归 `shared/agent`。

### 辅助分析与恢复边界

- `SourceReadPort` 只公开快照修订校验、目录分页、字面搜索和分页读取。分析会话不持有原始路径、SSH、凭据、写入、补丁或部署执行端口；公共 `SourceBrowser` 负责边界、秘密排除、脱敏及读取上限。
- `AssistedAnalysisSession` 最多读取 12 页、累计 48000 个字符；建议仅引用本轮实际读取或搜索证据，目录列表不能作为参数依据。源码修订变化即拒绝旧结果。源码及日志中的指令均视为不可信数据。
- 多个受支持类型可由 AI 结合证据选择，入口、构建输出、版本、依赖、端口及既有健康参数继续进入标准契约校验。业务意图、凭据、数据授权、资源归属、权限及外部暴露范围须由用户确定。用户显式值发生冲突时先展示建议依据，再请求澄清。已有数据库结构变更及 SQLite 首次初始化的业务授权仍由用户确认；这不代替后续实际命令的三档审批，完全控制也不允许模型补造数据授权。
- 单组件及多组件共用修正策略。正常路径不调用模型选择固定步骤；已验证计划和实际服务器证据进行一次部署前检查，相关事实改变后重查。失败后只允许有证据的参数修正或已验证环境变化触发新计划；最多两次修正后重试，分析、预检、失败解释及恢复共用 30 次模型决策额度，模型接替不重置。
- 结果未知、恢复无法验证、预算耗尽、没有新进展或人工接管时停止自动继续。多组件始终复核依赖图和整应用健康门槛，不通过削弱健康条件制造成功。

## 11. APP 数据库与安全

本节描述 APP 的当前实现。Web 尚未同步，shared 协议、运行时格式和备份格式保持原语义。

> 下文描述当前 SQLite 实现；尚未实施的 1.1 数据库设计统一见 [Mod.md](Mod.md#mod-database)。

### 数据库入口

`DesktopPersistence.open` 先检查完整性，再由 `DesktopSchemaInitializer` 创建空库或验证 v21 的完整结构定义、版本与外键。其他版本、缺表、多表、改列及异常定义拒绝打开；产品不删除、不备份、不迁移不兼容文件。连接启用 `foreign_keys=ON`、`secure_delete=ON`、`journal_mode=DELETE` 和五秒 busy timeout。

字段顺序、类型及全部约束以 [desktop.sql](../src/app/db/src/main/resources/schema/desktop.sql) 为准。19 张业务表：

| 范围           | 表                                                                                                                                                                                |
| -------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 安全           | `security_profile`、`credential`                                                                                                                                                  |
| 服务器         | `server_profile`                                                                                                                                                                  |
| 部署与应用     | `deployment_unit`、`managed_application`、`managed_application_component`、`managed_application_dependency`、`external_application`                                               |
| 配置与秘密版本 | `deployment_unit_configuration_snapshot`、`deployment_unit_configuration_entry`、`deployment_unit_release_binding`、`secret_revision`、`deployment_unit_release_secret_reference` |
| 模型           | `ai_model`                                                                                                                                                                        |
| 任务历史       | `browser_recovery_task`、`browser_recovery_event`、`deployment_agent_task`、`deployment_agent_event`                                                                              |
| 偏好           | `desktop_preference`                                                                                                                                                              |

表名、列名、偏好键采用小写下划线。时间保存 UTC Unix 毫秒，修订为整数，布尔为 0/1。用户配置键、模型名称、路径、URL 和 shared 标识不改写。

### 事务及历史保护

服务器行分别保存连接端点与可信端点/指纹快照。有受管部署关联时禁止修改配置换绑端点，实际连接继续复核信任。部署单元的发布、运行配置、观测和显示覆盖可独立更新，更新一部分不清空其他部分。

整应用、组件及依赖同事务保存，校验同服务器、健康组件归属和依赖无环。健康组件复合外键是延迟检查且删除行为为 NO ACTION，允许事务内重建拓扑。事件引用任务；业务历史的父记录由外键保护，不级联删除。

配置快照、秘密修订和发布绑定不可变；秘密引用完整标志区分尚未登记与明确无秘密。服务器、模型及秘密版本关联与凭据写入共用实际数据库事务；失败整体回滚。

### 主密码与凭据

`security_profile` 为单例，独立保存 Argon2id 密码验证串、包装密钥派生盐和已包装数据密钥。验证盐与包装盐分别随机生成。Argon2id 固定 64 MiB、3 次、1 路；数据密钥随机 256 位。AES-256-GCM 使用 12 字节随机 nonce、128 位标签；凭据 AAD 绑定标识和格式版本。数据库唯一约束拒绝现有凭据 nonce 冲突；未知算法、参数或格式拒绝解密。

`credential` 统一保存 SSH 密码、API Key 和业务秘密，默认加密；业务表只保存凭据引用与精确秘密修订。会话只保留内部数据密钥句柄，读取时按需解密，用后尽力清除缓冲区。主密码修改重新验证并只包装原数据密钥；全库加密转换重新验证后在同一事务转换所有凭据和标志，失败回滚。活动任务阻止两种安全变更。关闭加密后数据库含明文；再次加密不承诺清除外部旧副本。

备份归档密码与 APP 主密码保持独立。

不主动持久化主密码或明文数据密钥；内存清理是尽力而为，不承诺操作系统永不交换内存到磁盘。

### 会话、任务与界面

`app/service/contract/security` 暴露窄安全门面及任务授权，不暴露数据密钥；`app/service/security` 统一管理会话、锁定、任务接纳及安全设置互斥。`app/secret` 持有 Argon2id、AES-256-GCM 和引用计数的内存密钥句柄。`app/ui/shell/DesktopLockController` 遮挡主窗口和从属窗口，屏蔽键盘入口；服务门禁独立于控件状态。

未设密时启动先显示主界面，随后弹窗引导到“设置 → 主密码与凭据”，提供“前往设置”和“稍后设置”。首次设密表单直接显示在设置页，隐藏当前密码和加密开关；设密完成后建立会话并切换为修改密码表单。未设密时不显示锁定遮罩、不启用手动锁定，但服务层仍不接纳业务任务。已设密用户每次启动仍需通过解锁入口验证密码。主密码至少八个字符，首次设置和修改均要求重复输入。

服务层以同一互斥边界处理锁定、任务接纳和安全设置变更。任务调度前取得授权，工作线程显式安装任务上下文；手动锁定只释放交互会话。活动任务及派生救援线程保留自己的句柄；取消、失败和执行结束后释放，正在执行的任务不会因提前请求关闭句柄而失去密钥。

人工输入及审批在服务层等待解锁；如果锁定代次改变，旧响应不会继续生效，恢复后重做确认。恢复任务的人工控制再次经过原子解锁门禁，动作令牌仍由原有任务状态机复核。完成回调不解锁。

锁定层同时覆盖主窗口和从属窗口，清空密码字段、隐藏详细内容及从属标题，阻断菜单、快捷键和右键入口。仅显示任务数量。锁定且有活动任务时不能直接关闭，先解锁处理；可以最小化。无任务时允许退出。当前仅支持手动锁定，不提供自动锁定、账户、设备绑定或找回密码。

### 模型与偏好

`ai_model` 统一保存连接、显示顺序、三个用途的独立启用/调用顺序及文字/视觉验证修订。端点、模型或 API Key 内容变化增加配置修订；异步能力验证只可写回原修订。密码重包装不改变模型修订。用途禁用保留位置，移出调用链清空位置；交换顺序使用事务内非冲突临时位置。

模型调用在同一读取事务确认捕获端点身份、当前有效能力证据和凭据，避免配置编辑后把新凭据发往旧端点。任务的用途顺序和模式快照不因普通偏好调整而变化。

偏好键为 `ui_locale`、`ui_theme`、`ui_navigation_collapsed`、`deploy_mode`、`deploy_approval`。缺失部署偏好首次写入 ASSISTED + AUTOMATIC；非法值报错而不覆盖。用户调整立即保存两项，失败回滚界面。缺少模型提示配置，保留模式选择；高风险人工确认规则继续生效。

### 验证边界

仓库测试使用隔离临时数据库，覆盖结构、事务、密码/密文失败、锁定任务生命周期、配置修订、业务调用和可见 Swing 窗口。验证执行方法见 [1.1 开发文档](development/PHASE-1.1.md#engineering-workflow)。真实 Linux 和真实模型服务需要独立运行有条件的验收，不能由本地模拟或界面测试替代。

### 救援浏览器的锁定协作

APP 救援浏览器通过安全服务登记原生隐私参与者；会话转换前由 `app/windows/window` 隐藏或恢复已验证归属的隔离浏览器窗口。失败时不提交锁定状态，后台浏览器仍由原有任务持有并清理。

APP 打开的独立救援浏览器也随锁定隐藏并禁用原生窗口，自动化和已绑定终端继续运行；解锁后恢复原先窗口状态。此控制只针对私有 CDP 连接识别、且验证为 APP 子进程的隔离浏览器，不操作个人浏览器。若原生隐私切换失败，安全服务拒绝宣称锁定成功并提示结束救援后重试。
