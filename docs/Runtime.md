# WindowsToLinux 运行与行为约定

本文维护活动APP、appapi与官方deployment Mod的当前运行合同。冻结源码及历史验收事实分别保留于`history-src`和开发记录；它们不参与当前运行，也不提供兼容入口。真实Linux、外部AI与正式EXE验收仍需独立完成，备份/迁移Mod和独立更新器不在当前已交付能力内。

配置字段及填写方式统一见[Config.md](Config.md)，结构见[File.md](File.md)，作者合同见[Mod.md](Mod.md)，使用流程见[产品手册](PRODUCT-MANUAL.md)，交付布局见[APP.md](APP.md)。

## 1. 本地化、错误与验证

- 页面通过实际语言设置呈现稳定消息键；业务诊断保留精确错误码、原operationId及实际保存后返回的diagnosticId。
- 业务结果与资源释放独立。超时、断连、提交应答不明及关闭未确认保留UNKNOWN；核对只读取原身份和依据，不生成替代任务、不重放原效果。
- 正常诊断写入H2，数据库不可用时使用有界应急队列；回填保留原ID与时间，实际提交确认后才清队列。报告不包含主密码、密钥、凭据、源码正文或未脱敏响应。
- 安装、重装及日志页面只接收Service观测值；服务私有检验对象、Mod声明实现及DB存储类型不向UI泄漏。审批仍绑定签发服务、原文件身份、摘要与单次消费。
- 当前平台只使用H2建库合同。不包含SQLite平台初始化、表访问或数据转换实现；不自动转换、重置或删除已有用户记录。

## 2. 桌面端数据目录

桌面应用读取 Config 模块 JAR 内的 `gold/debug/windowstolinux/app/config/config.yaml` 资源，按 common 与当前模式字段合并后，由 main 对已验证运行锚点解析唯一数据目录。CLASS 从模块构建输出读取同一资源，不读取程序根的同名文件。允许明确绝对路径；相对路径基准、默认值和错误处理统一见 [Config.md](Config.md)。不加入注册表、ENV、命令行字段覆盖或路径指针文件，不自动搬迁既有数据。以下为发行 YAML 的默认位置：

| 运行模式 | `data` 目录                                          |
| -------- | ---------------------------------------------------- |
| CLASS    | `src/app/db/data`，与 `src/app/db/target` 同级。     |
| JAR      | 最外层主入口 JAR 所在目录下的 `data`。               |
| APP      | `jpackage` 启动器 EXE 所在目录下的 `data`。          |

- `jpackage` 安装包启用按当前用户安装和安装目录选择，避免默认安装到普通用户不可写的 `Program Files`。
- CLASS/JAR 模式使用 `app/db/connect/PlatformDatabase` 的代码源验证 DB 模块和运行模式；JAR 相对数据路径以主入口 JAR 所在目录为基准，不随 DB 模块 JAR 的位置变化，不依据固定 JAR 文件名猜测。Schema 所有者口令仍按原已编码数据库用户名派生。
- CLASS 模式优先依据 DB 模块的 Maven `target/classes`/`target/test-classes` 定位模块；JetBrains 等 IDE 输出不在模块内时，必须先验证工作区中的 `windowstolinux-app-db` POM，再以已验证工作区解析 YAML 相对数据路径，不直接信任任意工作目录。
- 应用启动时必须验证解析出的数据目录可以创建和写入；验证失败则停止启动，需将程序或配置的数据目录调整到可写位置。
- 不得静默回退到用户目录、临时目录或其他位置，避免同一安装出现多个不一致的数据副本。
- APP 模式的默认与相对数据路径以 EXE 目录为基准；明确配置的绝对路径按配置生效，升级和卸载时须保留实际数据位置。

  1.1 默认启动仅打开 `windowstolinux.mv.db` 与 `db-access.bin`，使用 H2 2.5.250 和 Windows 当前用户 DPAPI；缺失配对、身份错误或材料损坏时拒绝打开，不覆盖重建。首次安全设置后可解锁，再次启动保持锁定。正常退出等待凭据操作、持久化非终态任务及物理连接释放；UNKNOWN 不视作已完成。平台子目录职责见 [Mod 数据布局](Mod.md#mod-database)。

程序目录独立定位：JAR 使用最外层主入口 JAR 所在目录，相对数据路径使用同一基准；APP 使用 EXE 所在目录。CLASS 程序根须是经 DB 模块 POM 和 main 模块位置验证的工作区，主模块输出须位于该工作区内；不从无关工作目录加载 Mod。

当前内部布局见 [平台数据根](Mod.md#mod-data-root)：`windowstolinux.mv.db` 保存 H2 数据，`db-access.bin` 保存配对引导材料，`windowstolinux.lock` 保护单实例，`log/emergency` 保存应急日志，`work/source` 保存任务源码工作副本。目录按实际需要创建，备份业务仍随 S6 暂缓。

旧 SQLite `windowstolinux.db`、旧报告目录 `error-logs`、旧备份目录 `backups` 和测试临时目录不属于当前平台数据布局。不自动改名、导入或转换旧平台数据库，也不自动创建新材料代替已有库；不支持的布局保留原数据并明确报告。

- `main` 只能从 `RunModeResolver` 已解析的唯一 `data` 根派生这些固定子项；不得写死 `/var/lib`、Windows 盘符、用户目录或临时目录，也不得绕过已加载 YAML 新增覆盖入口或静默回退。
- 当前 H2 保存平台管理记录与 Mod 自有 Schema；分析得到的逻辑 `ComponentDataPath` 作为经审阅元数据保存，不得直接拼成桌面物理路径。数据库连接保存非秘密信息和精确 `SecretReference`，不保存密码值。
- 实际部署应用的持久化文件、容器卷和数据库保留在目标服务器或对应数据库服务中；本机数据目录的清理不涉及远端业务数据。

<a id="linux-storage"></a>

### Linux 受管数据与取材目录

受管应用标识记为 `A`；多组件继续使用各组件现有独立标识。`DeploymentStorageLocation` 和 `DeploymentStoragePlan` 为当前官方Mod的原生及容器提供同一份路径契约。

| 内容                 | 默认宿主位置                                                                                 |
| -------------------- | -------------------------------------------------------------------------------------------- |
| 程序、版本及当前入口 | `/opt/windowstolinux/apps/A/{releases/<摘要>,current}`                                       |
| 部署环境及秘密配置   | `/etc/opt/windowstolinux/apps/A/` 下的不可变修订                                             |
| 显式配置文件         | `/etc/opt/windowstolinux/apps/A/files/<绑定>/revisions/<内容摘要>/value`                     |
| 普通文件             | `/var/opt/windowstolinux/apps/A/files/<绑定>/`                                               |
| SQLite               | `/var/opt/windowstolinux/apps/A/databases/<数据库标识>/application.db`；显式文件名按声明保存 |
| 自定义相对路径的实体 | 安装根内 `persistent/{configuration,files,databases}/<绑定>/`                                |

- 默认、明确自定义和未确定分别保存。未确定、变量未解析、冲突、越界及异常文件一律报错，不回退默认位置。自定义绝对位置必须位于本应用安装根的严格子路径，排除 `releases`、`current`、`persistent` 和控制目录；自定义配置通过安装根内的不可变修订映射到声明的访问位置。
- `windowstolinux-storage.properties` 声明配置和文件的资源类型、应用访问位置、环境变量接入、宿主选择、读写模式及可选种子；SQLite 在 `windowstolinux-db.properties` 声明。创建目录不等于完成接入，默认位置必须交付到应用已经支持的环境变量或明确访问路径。配置模板只在明确声明时复制。
- 客户端和当前固定 helper 均校验应用归属、路径组件、物理父目录、符号链接、硬链接和特殊文件；远端只允许自身创建并记录的精确映射。执行前再次验证，现有未受管目录不能自动接管。原生服务使用固定不可登录的独立系统账号，程序和配置 root 持有，只向已声明数据开放写入；系统保护和临时目录隔离保持生效。
- Docker/Podman 使用经过校验的宿主 bind mount，保留镜像内访问路径，配置只读、根文件系统只读、临时写入使用 tmpfs。SQLite 使用独立宿主目录和容器内精确别名；必要时从验证后的镜像生成只读目录视图，避免遮住程序文件。镜像种子只在首次创建时导入，现有数据不重新播种；未声明的引擎卷或额外挂载拒绝。
- SQLite 使用宿主 `sqlite3` 一致性备份和完整性检查，业务镜像不需要包含该工具。种子及初始化 SQL 仅在目标数据库首次创建时使用；已有数据库不覆盖、不重跑初始化。应用驱动由项目依赖提供。
- 备份、恢复及双服务器迁移Mod尚未交付；底层helper资源不等于当前产品能力，历史实机记录不作为新布局验收。
- 旧 `/var/lib/windowstolinux/{apps,configurations,data,secrets}` 布局明确拒绝，不迁移、不删除。旧 helper、旧运行时/资源载荷及旧备份格式明确拒绝，不自动清空本机数据。新的默认布局遵循 FHS `/opt` 配套规则；允许用户在安装根内自定义持久位置是本产品例外。
- 部署工具的候选工作区、事务记录、身份登记和 `/var/lib/windowstolinux/backups/` 暂存仍归工具管理。构建临时身份及限容卷不改变；数据库服务器内部数据目录、Docker/Podman 引擎数据根不在迁移范围。
- 新布局真实 Ubuntu 24、CentOS Stream 9、原生/Docker/Podman 及双服务器恢复矩阵均为 `RUNTIME-PENDING`；旧 helper 的实机记录不作为新布局证据。


## Git、来源审阅与部署运行

Git准备使用原平台进程和来源能力，在首个效果前持久化job、进程、工作区与原任务身份。实际进程退出和完整物理回执确认后才使用冻结素材；项目写入、未知结果及恢复沿同一原记账流程，不保留未记账入口。当前支持无凭据HTTPS与明确允许的本地file来源；SSH Git来源仍需独立接线。

来源分析明确携带已审阅逻辑名称，元数据缺失时只使用该名称，不从暂存目录推导业务身份。组件及伴随源码使用已验证声明中的相对来源名称。运行时明确提供身份策略与工作负载，原生/容器后端严格核验，不接受未声明策略或历史健康状态构造。

<a id="ai-命令审批长期规则"></a>

### AI 命令审批

人工审核逐条批准实际命令或完整脚本；自动审批只对高风险命令要求人工批准；完全控制允许独立AI审核通过后执行。三档均通过本地校验和独立AI审核；本地禁止、审核拒绝或不可用时拒绝执行。内容、目标、执行身份或相关证据改变后重新审核，阶段批准不代替实际命令批准。公共审批使用appapi.task.action，当前辅助与自主部署流程保留其各自预算、来源和数据授权边界。

### 部署执行账本

请求、恢复、结果统一版本11；请求从首次记录起包含固定完整身份、引用、来源、发布模板、构建审阅/意图、操作证明及纠正历史字段。未发生状态编码显式空值、空数组或零值；缺字段拒绝，读取不补齐。公共引用操作最多1MiB、初始单组件请求40MiB、图或构建审阅144MiB、后续纠正链272MiB，均按实际操作和阶段验证。

初始发布operation明确等于原task；后续operation必须由实际证明和审阅关联。原提案保持不可变，构建与发布合计最多两次纠正，完整操作链最多三次。跨启动只核对原任务、真实效果与资源依据，未知效果不自动重试。旧版4～10、未来版、畸形或不完整输入明确拒绝；旧行及未确认占用不自动升级、删除或释放。其他协议保留各自当前格式，编号较小不表示旧版。

## Windows更新与卸载交接

`windows.handoff`共用严格版本化、有界且用途隔离的HMAC-SHA256交接封套。认证前不解释路径、决定或更新证据；错误密钥、篡改、截断、跨用途重放及认证后畸形载荷均拒绝。交接字节与当前HANDOFF_INVALID错误码、消息键保持。

当前协调器只允许停止准入、保存程序与H2数据库及`db-access.bin`的一致配对备份并形成不可变交接。实际替换、结构升级、健康及配对回滚需要独立更新器重新核验自身、主进程退出及交接真实性；当前本机端口测试不代表生产更新器已交付。卸载须按明确数据决定、实际安装/数据根和固定Credential Manager命名空间处理，报告未确认残留。

## 业务、检查及交付边界

活动包和Maven模块图使用显式引用与JDK解析后的实际类型共同验证，包括var、泛型、嵌套类型及成员归属。任意长度依赖环拒绝，共用基础能力的菱形依赖允许。运行入口和产物不保留旧SQL资源、旧公开包兼容壳或缺审阅信息的运行分支；冻结历史数据只作参考。

采用JDK21及当前根Maven测试体系；格式检查使用`idea-check`。本地测试涵盖实际H2、进程、资源生命周期及受控Swing/SSH，不能代替真实目标机、外部模型服务或正式安装器验收。

## 当前平台数据库与安全

`windowstolinux.mv.db`、当前Windows用户保护的`db-access.bin`和实例锁共同确定唯一H2引擎。只缺失配对一方、保护材料损坏、代次/结构/版本不符或已被其他实例占用时拒绝打开，不补建、清空或转换。当前DDL以[platform-v1.sql](../src/app/db/src/main/resources/gold/debug/windowstolinux/app/db/schema/platform-v1.sql)为准。

`PlatformDatabase`持有引擎、锁、保护材料及连接生命周期。`PlatformDatabaseInitializer`借用连接执行当前DDL、结构核验、启动标记、异常任务与Mod状态恢复以及首次偏好写入，不关闭或持有引擎资源。原事务、回滚和失败清理顺序保持；Mod Schema生命周期使用独立任务与操作作用域。

### 主密码与凭据

`security_profile` 为单例，独立保存 Argon2id 密码验证串、包装密钥派生盐和已包装数据密钥。验证盐与包装盐分别随机生成。Argon2id 固定 64 MiB、3 次、1 路；数据密钥随机 256 位。AES-256-GCM 使用 12 字节随机 nonce、128 位标签；凭据 AAD 绑定标识和格式版本。数据库唯一约束拒绝现有凭据 nonce 冲突；未知算法、参数或格式拒绝解密。

`credential` 统一保存 SSH 密码、API Key 和业务秘密，默认加密；业务表只保存凭据引用与精确秘密修订。会话只保留内部数据密钥句柄，读取时按需解密，用后尽力清除缓冲区。主密码修改重新验证并只包装原数据密钥；全库加密转换重新验证后在同一事务转换所有凭据和标志，失败回滚。活动任务阻止两种安全变更。关闭加密后数据库含明文；再次加密不承诺清除外部旧副本。

备份归档密码与 APP 主密码保持独立。

不主动持久化主密码或明文数据密钥；内存清理是尽力而为，不承诺操作系统永不交换内存到磁盘。

### 会话、任务与界面

`app/service/security` 暴露窄安全门面及任务授权，并统一管理会话、锁定、任务接纳及安全设置互斥，不暴露数据密钥。`app/secret` 持有 Argon2id、AES-256-GCM 和引用计数的内存密钥句柄。`app/ui/window/DesktopLockController` 遮挡主窗口和从属窗口，屏蔽键盘入口；服务门禁独立于控件状态。

未设密时启动先显示主界面，随后弹窗引导到“设置 → 主密码与凭据”，提供“前往设置”和“稍后设置”。首次设密表单直接显示在设置页，隐藏当前密码和加密开关；设密完成后建立会话并切换为修改密码表单。未设密时不显示锁定遮罩、不启用手动锁定，但服务层仍不接纳业务任务。已设密用户每次启动仍需通过解锁入口验证密码。主密码至少八个字符，首次设置和修改均要求重复输入。

服务层以同一互斥边界处理锁定、任务接纳和安全设置变更。任务调度前取得授权，工作线程显式安装任务上下文；手动锁定只释放交互会话。活动任务及派生救援线程保留自己的句柄；取消、失败和执行结束后释放，正在执行的任务不会因提前请求关闭句柄而失去密钥。

人工输入及审批在服务层等待解锁；如果锁定代次改变，旧响应不会继续生效，恢复后重做确认。恢复任务的人工控制再次经过原子解锁门禁，动作令牌仍由原有任务状态机复核。完成回调不解锁。

任务展示读取运行时发布的不可变活动快照，不等待准入或账本锁；显示状态不替代操作时的真实身份与授权复核。模型清单、模型操作和服务器页以视图代次及请求身份拒绝锁定、关闭和重新解锁前的旧回调，旧完成通知不能清除较新请求的忙碌状态；已接纳业务工作仍沿原任务合同运行。

锁定层同时覆盖主窗口和从属窗口，清空密码字段、隐藏详细内容及从属标题，阻断菜单、快捷键和右键入口。仅显示任务数量。锁定且有活动任务时不能直接关闭，先解锁处理；可以最小化。无任务时允许退出。当前仅支持手动锁定，不提供自动锁定、账户、设备绑定或找回密码。

### 模型与偏好

`ai_model` 统一保存文字、完整音频、实时音频三个独立地址，以及显示顺序、LANGUAGE / VISION / APPROVAL / VOICE 四个用途的独立启用与调用顺序。TEXT / VISION / VOICE_FILE / VOICE_REALTIME 各自保存未验证、可用、不支持或验证失败状态、安全原因与当前修订证据；配置了地址不表示具备能力。模型或 API Key 内容变化撤销所有能力；某协议地址变化仅撤销相关能力，文字输出上限只影响文字和视觉。名称及顺序变化不撤销验证。异步验证只可写回原修订；密码重包装不改变模型修订。用途禁用保留位置，移出调用链清空位置；交换顺序使用事务内非冲突临时位置。

模型调用在同一读取事务确认捕获端点身份、当前有效能力证据和凭据，避免配置编辑后把新凭据发往旧端点。任务的用途顺序和模式快照不因普通偏好调整而变化。

偏好使用既有 `desktop_preference`，包括外观、导航、部署模式、平台授权、传输阈值与 `file_delete_ai_explanation`。删除说明首次初始化及正常缺失键默认为开启；仅 `true` / `false` 是有效保存值。非法值或读取失败须报告并跳过可选说明，不调用模型、不静默覆盖；人工确认和必要审批继续生效。关闭值在重开后保留。缺失部署偏好首次写入 ASSISTED + AUTOMATIC；非法值报错而不覆盖。用户调整立即保存，失败回滚界面。

<a id="file-runtime"></a>

### 通用文件、审批与等待

`app/file` 统一负责真实对象解析、冲突计划、逐项执行、内容发布及受管链接维护，Windows / SFTP 后端只提供当前账户的原语。`app/service/file` 绑定原任务、调用方、服务器准入、用户交互和数据库记录；本机路径不附加人为全局根目录。File 跟随解析链操作实际对象；Link 操作链接自身，包括断链。确认、说明、记录和许可均绑定实际对象及输入链接路径；发出副作用前复核解析链、身份和已批准效果。

目录冲突先选择副本、合并或不处理；合并中的同名文件再选择覆盖、副本或不处理。跳过冲突项保留双方并继续独立项，整体报告部分失败。副本报告实际名称；移动只有在目标发布与内容核验成功、源清理确认后才算完成。覆盖或移动自身的已批准清理不转为普通删除弹窗。统一 API 内的移动、复制及覆盖按实际结果维护已登记链接，外部程序或任意命令不触发扫描与补改。

`file_link`、`file_operation`、`file_operation_step` 在副作用前保存原对象、目标和阶段依据，已证实阶段不重放。断连、重启或记录未确认时保留事实并执行显式核对；旧内存许可不恢复，也不恢复任意 Java 调用栈。受管跨主机内容继续使用原 SSH 会话及既有 SFTP 暂存、摘要、进度、停滞重试和恢复记录。重连后刷新同一文件作用域的实际通道，旧通道和取消观察线程必须物理结束，原语与传输均不向 Mod 暴露原始客户端。两个不同远端间的复制或移动不在本期范围。

回收成功须有实际回收对象及恢复信息的身份回执：Windows 来自系统回收操作的新对象和配对元数据，Linux 来自账户主目录 Trash 对象及 `.trashinfo`。回执在真实效果核验后持久化；重开核对要求回收对象和恢复信息仍匹配原位置。仅原路径消失、缺失回执或恢复信息被替换均不足以确认回收成功，结果保持 UNKNOWN，不自动再删。

原文件操作绑定调用方和发布；新的普通任务可按真实权限核对同一所属操作。`checkOperation` 只补已完成且可证明的登记，不重写正确链接。已证明文件交付完成但链接仍未维护时，`continueOperation` 重新核对目标、缺失旧源、原链接身份及任务范围，获取新的精确许可后只执行未完成链接步骤；新记录关联原操作及原任务。恢复回调明确拒绝此新副作用入口，不重放原移动、内容写入或源清理，也不恢复旧许可。

普通删除始终取得一次新的人工确认，支持可恢复回收时使用回收，否则明确说明永久删除。可选用途说明只读观测元数据，不读取文件内容，且只调用实际 LANGUAGE 列表首个启用成员；首模型失效或调用失败不会改用第二个。没有主模型、说明关闭或说明失败均保留基本信息供人工决定。前置删除许可由实际对象本地复核、独立 APPROVAL 模型审核及适用人工规则共同签发，绑定原任务、调用方、对象语义、效果及 AI 修订；消费时重验并单次使用。普通确认签发的许可不能冒充前置许可；可回收对象不能凭永久删除意图绕过优先回收，回收失败或结果未知不得降级永久删除。

拒绝或关闭普通删除确认后，任务进入持久 WAITING。此时文件保持原状，不保留无必要的文件句柄、SSH 通道、模型请求或数据库事务；任务页提供“继续”和“请求取消”。继续由宿主明确恢复原回调，重新读取对象和确认；终止沿原取消及收尾规则。失效前置许可直接失败，不降级成普通确认。重启后的 WAITING 由已有任务和操作记录核对，不能自动再发删除。

<a id="voice-runtime"></a>

### 音频转写与验证

模型保存与验证是两个独立动作。至少配置一个有效协议地址即可保存纯语音模型，保存不触网。完整音频与实时音频分别通过真实协议提交用户提供的音频并比对预期文字，成功后才记录各自可用证据；不支持与验证失败分别记录，不因失败标为可用或自动加入用途列表。

完整音频使用 multipart HTTP 转写；最小格式为完整 RIFF/WAV、PCM16LE、单声道、24 kHz，至少 100 ms，最多 25,000,000 字节。实时使用 Java 原生 WebSocket 转写会话，输入是相同采样格式的原始 PCM；每块最多 65,536 字节并保持样本对齐，排队容量为 64 KiB～1 MiB。每轮至少 100 ms，最多 64 个待定稿轮次、2,048 个总轮次及 30 分钟音频；正超时最多 30 分钟，路由、凭据捕获、客户端初始化及协议操作共同消耗原预算。凭据最多 4 KiB 可见 ASCII，拒绝重定向转发和响应中泄露提供方诊断。

实时会话在创建时固定模型、协议地址、配置修订及原任务。片段按本地提交顺序关联，支持增量、确认结果及跨片段乱序定稿；未关联或重复终态不伪造成功。发送队列有背压，事件回调仍核对原任务作用域。`finish` 提交剩余有效音频并等待所有定稿后关闭；`cancel` 不提交剩余音频，已发送且未确认部分报告 UNKNOWN，并保留已确认片段。连接、发送、回调及账本释放都完成后才认为会话结束。前次进程核对只识别真实 `ai-http-` / `ai-voice-` UUID，不自动重发音频。

任务宿主把原任务结论、授权和依赖账本分别组织在内部职责对象中，仍使用原 `PlatformTaskRuntime` 同步监视器，不改变公开任务契约或任务身份。`TaskLedger.queries()` 提供原只读查询，写入与归档仍由原账本提交；嵌套查询和归档对象沿用原连接及锁。SFTP 的发布核验与恢复收尾复用内部完成职责，不改变发送顺序或 UNKNOWN 资源保留规则。此职责拆分不表示跨 Mod 的原提供方传输恢复已经闭合；该恢复接线仍需独立验收。

Mod 删除的证据核验、重启请求的读取和准备账本、Schema 中断核对的来源链校验分别由原类内的职责对象完成，仍复用原连接、平台行锁及事务，不增加继承或改变公开准入条件。删除、重装、重启恢复及真实 CLASS Schema 核对的本机定向验证已通过；活动根已切换 APP/appapi/deployment，S3/S4 本机适用合同及受影响门禁已按有效实际结果合集验证；这些结果不代表真实远端验收。

Mod 安装的账本、路径及清单核验，重装的原文件作用域与 VALIDATED 检查点，目录登记的版本与初始选择，分别由原类内部职责执行。内部对象沿用原锁、同一数据库连接、目录身份及阶段次序，不改变公开安装契约。Maven 开发输入采集把已解析构件遍历组织为内部职责，保留原顺序与输入边界。

### 验证边界

仓库测试使用隔离临时数据库，覆盖结构、事务、密码/密文失败、锁定任务生命周期、配置修订、业务调用和可见 Swing 窗口。验证执行方法见 [1.1 开发文档](development/PHASE-1.1.md#engineering-workflow)。真实 Linux 和真实模型服务需要独立运行有条件的验收，不能由本地模拟或界面测试替代。

### 救援浏览器的锁定协作

APP 救援浏览器通过安全服务登记原生隐私参与者。锁定先撤销交互会话、拒绝新的平台授权并覆盖所属 Swing 窗口，再由串行后台工作经 `app/windows/window` 隐藏已验证归属的隔离浏览器窗口；原生调用不持有安全会话监视器。隐藏失败仍保持平台锁定，遮罩独立显示“原生窗口隐藏未确认”并提供重试。已接纳任务仍持有原授权和清理责任。

APP 打开的独立救援浏览器随锁定隐藏并禁用原生窗口，自动化和已绑定终端继续运行。解锁在后台验证密码并按相同串行边界恢复原窗口状态，只有仍属当前代次的结果才能发布新会话；旧转换不能覆盖新的锁定请求。登记参与者在初始隐私状态同步确认后才返回。此控制只针对私有 CDP 连接识别、且验证为 APP 子进程的隔离浏览器，不操作个人浏览器。平台锁定与原生窗口隐藏是分别报告的状态。

固定受管 helper 当前协议为 14，组装摘要为 `7ae55e01e280af793c42f000777012c2a5b12f8bd83b706cf85ccd11c004749f`。原三参数 snapshot／discard 和七参数 publication status 保持合同；独立尝试采用 5／8／4 参数，真实根任务 UUID 用于审批及归属，operation UUID 用于快照身份，快照在应用锁内核对已审阅旧 CURRENT 摘要或明确空目标。健康失败后的有界重试、原任务跨 boot 恢复、应用管理及公开协作已通过本机适用合同验证；未知效果只核对原状态，半图确知后回滚清理，不补发布未发送组件。原协议 13 的应用管理与交付可选 helper 动作保留在固定包，真实远端未验收。


### APP 网页控制台救援边界

官方deployment通过`Mod.start`登记原`deployment-publication`恢复器，启动只装配恢复图。用户显式核对时，宿主先核实并释放原任务旧连接，再依据当前协议的原发布状态、版本11完整模板和原检查点核对。仅在全部原事实匹配时补本机提交或推进原清理；缺失、冲突或不明效果保持UNKNOWN，不重发构建、发布或回滚。旧执行信封4～10和未来版本在业务解释前拒绝，保留原记录、任务身份及资源依据。

默认桌面的“任务与恢复”页经内部 `app/service/task/TaskManagement` 访问中央任务，由 `PlatformTaskManagement` 核对当前安全状态并调用原句柄协作取消或原任务核对。任务清单及操作在后台执行，取消不强制终止或提前释放资源；精确宿主救援身份走 `SshRecovery` 的精确命令确认，元数据归档路径不调用业务恢复。任务页锁定/关闭时清空当前数据并销毁确认，旧代次的异步结果不能重新显示。已知结果归档后从清单移除，摘要进入既有数据库管理页。默认启动已装配原版本 Mod 恢复图；明确核对结束后调用原图清理，失败保留会话或已核验收尾凭据，退出时重试原清理。缺少登记不会放开原占用。

恢复图依据现由 `PlatformTaskAdmission` 在原准入事务捕获，`TaskLedger` 与任务行原子保存至既有 `recovery_json`。格式 2 固定原 Mod 与全部传递提供方的版本、内容摘要及数据代次；不保存源码、参数、返回值或凭据，也不新增资源申请。格式1用于当前宿主任务且明确没有Mod恢复图；格式及原任务/Schema 申请不一致时拒绝执行，不能用当前登记重建旧事实。`PlatformModRecovery` 在普通启动准备前校验完整原图及 `service.v1` 记录；共享提供方合并成一个恢复组，身份冲突或代码变化时整组保持阻断。只有原版本 RECOVERY 会话登记任务核对，页面隐藏、服务与普通图隔离、新业务提交拒绝；独立普通部分继续。原组全部任务结束后逆序停止。当前启动保留普通启用阻断，用户下一次手动重启才使用所选版本。

`ModRecoveryLedger` 复用 `mod_operation` 的 RECONCILE 类型，为组内每个成员保存固定操作/摘要身份、完整原图及旧运行凭据；`mode=MOD_SESSION` 与 Schema 核对区分，阶段固定为 RECOVERING → VERIFIED。记录先于作者构造，并在原任务归档后继续存在。会话实际释放后保存 FINISHING/VERIFIED/SUCCEEDED，随后原子写摘要、确认精确旧运行状态和删除操作行；仅归档失败时跨启动补元数据，不重新启动作者或重做任务。未应用 WAIT_RESTART 意图保留，恢复不提前应用开关、单选或迁移。

`PlaywrightDriver` 保留创建返回的原连接和原 `Process`，不把依赖的 `close()` 返回视为驱动已退出。关闭被接受后仅等待原进程；仍存活时保留工作线程、隐私登记和任务占用，后续收尾不重新创建驱动。即使进程已退出，连接清理异常也不能被忽略。该适配针对固定 Playwright 1.58.0：其公共 API 不提供进程对象，因此在创建前核验内部 `driverProcess` 字段结构和访问能力，再取得原对象；依赖升级须重验这个边界。创建中途失败且无法取得原对象时保留未确认状态，不推定资源已释放。

`app/linux/ssh/recover` 独占 Playwright Java 1.58.0 对象、终端契约与安全 Problem，并在专用线程处理页面事件和终端输入；不接管个人浏览器配置。`app/windows/window` 仅提供所属子进程窗口隐私适配，不持有 Playwright。关闭先封闭新调用；等待超时保留同一个清理任务和工作线程，后续关闭继续观察原任务。实际浏览器进程、工作线程及隐私登记全部释放后才报告完成。`TaskBrowserSession` 已连接原中央任务：创建前持久登记 `browser.v1`，实际 PID/系统启动时间提交后才允许终端使用；完整清理后先记录 `browser.closed.v1`，再释放占用，失败保留原对象和记录。关闭检查点保留原创建事实，只允许原物理启动、原任务和原资源身份确认，不能退回创建状态；检查点或释放失败可在原对象重试。

跨启动核对原救援任务时，只有明确关闭检查点允许释放浏览器占用；STARTING/STARTED、格式不合法或其他未确认资源使整次核对保留 UNKNOWN，不先释放其中已关闭的部分。仅凭主 PID 消失或启动时间不同不足以证明驱动等资源全部退出。核对仍要求用户确认旧终端动作已结束，只记录中断，不重放模型请求、浏览器命令或 SSH 业务。已通过真实浏览器关闭/H2 故障注入及数据库重开验证；重开测试使用受控持久状态，不代表真实 JVM 崩溃或远端修复验收。

默认 `ApplicationLauncher` 的服务器页已装配独立救援：`platform.ssh.rescue.v1` 使用 `@platform`、实际宿主版本及完整 SERVER 占用，浏览器、模型和 SSH 都属于原中央任务，不创建旧独立执行器。固定 SSH 复核先验证保存的主机指纹和认证，再执行宿主固定回显（15 秒、1024 字节）；只有该平台任务类型可以调用此入口，不改变公开 Mod 命令审批。原控制器直接在中央回调运行、使用同一任务 UUID 记录状态和动作摘要，取消不强制中断线程。认证、主机身份及非连接错误停止本轮；只有明确连接失败可触发只读再查。未确认终端命令不重放，原任务核对要求用户确认旧动作已结束。

救援临时状态与事件现在随原中央任务收尾：业务结论和实际资源确认后，在同一 H2 事务写入固定 `browser_recovery` 摘要、清理 `browser_recovery_event/task`，并提交平台任务摘要及执行清理。救援摘要 ID 按 `WTL-BROWSER-ARCHIVE-1:` 与原持久 `archive_log_id` 确定性派生；记录原协议、服务器、最后观察状态/事件、命令 SHA-256、事件及提交次数，不保存命令或终端正文。任一步失败整体回滚，原任务保留 FINISHING；补归档不再探测 SSH 或调用作者恢复。原状态记录不被日志清理直接删除，迟到回调不能重建已结束记录。没有原中央任务、协议/服务器不匹配的记录保留，不能仅凭 RECOVERED 字样自行清理。

完整 SSH 救援闭环归 `app/linux/ssh/recover`：`SshRecovery` 持有原中央任务准入、会话、预算、动作确认、模型建议、固定 SSH 复核、原任务核对和资源收尾。`SshRecoverySession`、`BrowserRecoverySnapshot` 与 `TerminalTarget` 是唯一受控交互及纯值边界，不再保留 Service 的救援包或重复 UI 快照。`app/main/start/PlatformRecoveryHost` 仅接入既有任务、安全、模型及 DB 接口，保存配置变化核对、原身份与原清理凭据；Linux 不引用 Service、DB、UI 或冻结 shared 类型。UI 只能访问受控救援入口、会话及纯值，不能取得 SSH 连接、浏览器、模型调用或宿主注入对象。DB 继续保存救援元数据和归档事务。

救援固定提示、建议影响分类和严格 JSON 解析归 `app/linux/ssh/recover` 的 `RecoveryProtocol` 与 `RecoveryAction`；`app/ai` 仅提供通用模型用途、能力和调用协议。Linux 救援包的 `PlatformRecoveryModels` 经启动层注入的原平台任务及实际 AiService 分别调用视觉/语言用途，不使用审批模型生成建议；宿主输出上限为 2048 Token，并按各候选模型已配置上限取较小值，每次调用期限为 60 秒。普通 Mod 显式 AiRequest 的超限拒绝规则不变。完整响应结构不合格不另换模型；发送后结果未知保留原任务，不请求下一条建议。该模型适配已接默认救援入口。模型仅生成观察和建议，不执行命令；历史 shared 源码保留于 `history-src`，不进入活动构建。

公开 `AiPurpose` 区分 LANGUAGE、APPROVAL、VISION 和 VOICE；内部配置 `AiPurposeType.DEPLOYMENT` 对应公开 LANGUAGE，其余用途同名。`AiCapabilityType` 分别记录 TEXT、VISION、VOICE_FILE、VOICE_REALTIME 的验证。显示排序与用途调用顺序分离，任务持有精确配置快照。视觉识别只返回受控观察，语言和审批保持独立上下文。当前 H2 的模型、用途及能力记录保存独立顺序和配置修订，任务及事件表保存非秘密历史。三模式自动部署不接入浏览器救援，独立救援继续要求用户逐项授权。
