# UI 设计与交互规范

本文面向开发者和 AI 编码助手，维护桌面 Swing 界面的通用视觉、卡片交互和页面布局规则。服务器清单是多行对象卡片的展示基准，AI 页面作为同一套规则的应用实例。

本文记录已经确认并与当前实现核对的规则。产品操作流程见[产品说明书](PRODUCT-MANUAL.md)，字段和存储结构见[源码结构与约定](File.md#database-structure)，任务、安全及执行合同见[运行与行为约定](Runtime.md)。预览图中的候选设计不自动成为实现规范；Mod 商店仍在讨论的布局不在本文记录为已实现行为。

## 1. 适用范围与布局原则

对象清单使用统一圆角卡片、行间留白、选中底色及左侧标记。任务和日志等普通表格、文件多选、下拉菜单、系统选择器保留各自交互，不强制改成卡片。详情是否随选择展开由页面决定，不把服务器的伸缩布局强加给所有清单。

主窗口默认内容区为 1600×900，最小内容区为 1280×720，系统窗框另算。各页面应在正常和最小窗口下保持操作可访问；空间不足时滚动内容，不靠缩小按钮或隐藏必要动作解决。

标题、搜索和操作区固定，清单与详情分别在自己的视口内滚动。列表、按钮和滚动条应按所属模块对齐，不能因为展开详情而打乱原有标题或操作区的中心线。

## 2. 颜色与内容层次

### 2.1 中性灰阶

中性表面使用以下三档纯灰，RGB 三个通道取相同值。页面背景与卡片相差 10，与次要按钮等中性控件相差 20。主题配色及共用 Swing 控件默认值统一采用这些数值。

| 表面用途 | 深色模式 | 浅色模式 |
| --- | --- | --- |
| 卡片、详情内容块、全局导航栏 | RGB(20,20,20)，`#141414` | RGB(250,250,250)，`#FAFAFA` |
| 页面内容区背景 | RGB(30,30,30)，`#1E1E1E` | RGB(240,240,240)，`#F0F0F0` |
| 次要按钮等中性控件 | RGB(50,50,50)，`#323232` | RGB(220,220,220)，`#DCDCDC` |

深色模式保留“卡片比页面更深”的关系。浅色搜索框采用最高亮度档 250，使它与页面背景 240 清楚区分；深色搜索框使用控件档 50。服务器、Mod 商店和原始代码管理的搜索框共用此规则。

最左侧全局导航栏采用内容档 20／250，与使用页面档 30／240 的右侧主界面区分，并与应用内顶部标题区形成统一框架。未选导航按钮沿用导航栏底色，保留既有蓝色选中及悬停、按下反馈。页面内部的模型清单与详情布局继续使用各自表面角色。

其他共用表面按所属角色映射：

| 位置 | 表面角色 | 深／浅灰阶 |
| --- | --- | --- |
| 普通输入框、下拉框、数字输入、禁用背景及滚动条滑块 | 中性控件 | 50／220 |
| 菜单弹层、提示框、树及普通表格内容 | 内容块 | 20／250 |
| 工具栏、菜单栏、表头及滚动条轨道 | 页面 | 30／240 |

Swing 自绘标题栏同样使用页面档；操作系统原生窗框由系统绘制。

滚动条滑块的静止颜色与次要按钮一致，轨道使用页面档。悬停和按下时采用共用控件的交互色，不复用文字色或输入框边线色。

Mod 自有内容卡片同样使用内容档；读取标准 Swing 配色时可使用 `Table.background`。`Panel.background` 和卡片清单的 `List.background` 是页面底色，不能用作未选卡片或详情块的表面。

主题表面颜色由 [ThemePalette](../../src/app/ui/src/main/java/gold/debug/windowstolinux/app/ui/display/ThemePalette.java) 提供，共用控件颜色由 [DesktopControlDefaults](../../src/app/ui/src/main/java/gold/debug/windowstolinux/app/ui/display/DesktopControlDefaults.java) 设置。搜索框通过 [DesktopPartFactory](../../src/app/ui/src/main/java/gold/debug/windowstolinux/app/ui/control/DesktopPartFactory.java) 声明专用表面角色；主题切换重新读取颜色，不替换输入文档、数据模型或操作监听器。

### 2.2 强调色、状态色与文字

三档灰阶约束中性表面，不替代蓝色强调色、选中底色、正文、弱化文字及语义状态色。主动作、对象图标和选中线使用统一蓝色；浅色选中底色为浅蓝，深色使用对应的蓝色底色。悬停、按下、禁用和焦点反馈沿用共用控件样式，保持文字可读。

| 信息 | 表达规则 |
| --- | --- |
| 正文、名称 | 使用主题正文色，不与背景混在一起 |
| 副文本、辅助字段 | 使用弱化文字色，仍须可读 |
| 可用、检查通过 | 绿色，并保留明确状态文字 |
| 核验失败、检查失败 | 红色，并保留失败原因或错误入口 |
| AI 明确不支持 | 棕色，和核验失败区分 |
| AI 未验证 | 灰色减号和“未验证”文字 |
| 服务器未检查 | 正常正文色，不显示成失败 |

颜色不能代替文字和语义。带状态图标的行应同时显示状态文字；已有胶囊状态可保留文字与底色，不为统一形式额外增加图标。失败、未验证和 UNKNOWN 不得画成成功；深色主题采用相应的可读颜色。

## 3. 字体、尺寸与对齐

### 3.1 字体与缩放

全局首选字体族为 `Microsoft YaHei UI`，在 FlatLaf 初始化前设置；目标系统缺少该字体时沿用 FlatLaf 的系统字体处理，不捆绑字体文件。普通控件、日志、命令和代码输出使用同一字体族，不保留专用等宽分支。字体绑定应随主题和缩放更新，不能只改当前显示字体而留下旧绑定。

下表尺寸为缩放前基准；几何尺寸使用逻辑像素，字号通过现有字体缩放机制处理，不重复缩放。

| 用途 | 字号与字重 |
| --- | --- |
| 普通控件全局基准 | 13，常规 |
| 列表标题，如“服务器列表”“全部模型” | 20，粗体；旁边计数使用普通字体 |
| 详情中的对象名称 | 24，粗体 |
| 详情分区标题 | 18，粗体 |
| 服务器、AI 卡片名称 | 16，粗体 |
| 服务器连接信息、AI 模型副文本 | 14，常规 |
| 服务器状态徽标 | 12；不把所有页面的状态文字强制改为 12 |
| 公共日志、命令和代码输出 | 12，沿用统一字体族 |

### 3.2 卡片与图标基准

| 项目 | 基准 |
| --- | --- |
| 服务器、AI 清单行高 | 116，包含行间留白 |
| 行的上下外留白 | 各 9，相邻卡片可见间距为 18 |
| 上述基准行的可见卡片高度 | 98，不把行高 116 误作纯卡片高度 |
| 对象卡片圆角 | 绘制弧宽、弧高为 24，等效半径 12 |
| 普通详情内容块圆角 | 绘制弧宽、弧高为 20，等效半径 10 |
| 对象卡片内部留白 | 上下 10、左右 16 |
| 左侧选中蓝线 | 宽 4，沿圆角边界裁剪 |
| 卡片对象图标 | 30，蓝色 |
| 详情对象图标 | 32，蓝色 |
| 六点手柄图标 | 16，使用独立的手柄命中区域 |

服务器和 AI 使用上述行高。其他业务卡片可按内容需要采用不同高度，但应说明用途差异，保留共用表面、留白、选择和滚动规则。不能为增加内容而叠套第二层卡片包装，或让内部不透明组件遮住圆角。

### 3.3 按钮与中心线

服务器和 AI 的常规操作按钮采用上下 8、左右 14 的内边距；“收起详情”采用上下 8、左右 22，保持与服务器主检查动作相称的大小。按钮宽度按文字和图标自然计算，不把短按钮横向拉满所在栏。按钮、输入框和下拉框使用共用圆角表面，不额外添加静态黑边或焦点外框，以底色和交互反馈区分状态。

列表标题和同排操作按钮按垂直中心线对齐。详情标题的图标、名称和收起按钮整体居中；服务器详情标题还与左侧标题／搜索区的中心线对齐。卡片内图标与两行文字整体居中，名称、副文本保持紧凑间距。状态徽标的文字居中，徽标只留必要内边距，不做成与文字脱节的大胶囊。

AI 四个用途按钮在全宽态和用途栏展开后保持相同尺寸，当前用途变蓝，其余为灰色；不能因为右栏可用宽度增加而拉长。窄栏应调整可用布局空间以容纳按钮，避免裁切。

## 4. 卡片选择、拖动与滚动

### 4.1 选择与取消

| 操作 | 结果 |
| --- | --- |
| 无修饰的左键点击卡片主体 | 选中该卡片 |
| 再次点击当前卡片主体 | 取消选择 |
| 点击其他卡片主体 | 切换选择 |
| 点击间隙、列表空白 | 不误选，也不误取消当前卡片 |
| 点击六点手柄 | 不触发主体的选择切换 |
| 拖动后释放 | 只结束拖动，不误触选择或打开详情 |
| 键盘、右键、程序化选择、原有多选 | 保留各自语义，不套用普通主体点击的切换逻辑 |

明确取消选择后，刷新和异步回填不得强制选回第一条。取消选择只改变界面选择及关联展示，不能隐式保存配置、丢弃编辑草稿、取消已接纳任务或改变任务归属。页面应清除失效的操作目标和待确认计划，并拒绝过期异步结果回填。

### 4.2 仅手柄起拖

通用 `draggable` 布尔值同时控制排序能力和六点显示：`true` 显示标准六点并允许通过手柄起拖；`false` 不显示六点、不保留占位，也不能通过主体拖动排序。渲染、实际命中检测和拖动引擎必须读取同一个标志，绑定重排回调不自动启用拖动。

手柄命中范围取实际渲染边界并随缩放调整；短点不启动重排，达到 5 逻辑像素的移动阈值后才起拖。拖动复用浮动预览、邻行移动、自动滚动和取消机制。已包装行更新拖动标志时须同步手柄，避免视觉和能力不一致。

锁定、加载和保存等运行门禁仍须满足。筛选、刷新、模型变化、锁定、关闭、失焦或主题重装时取消未完成手势，不把取消或原位释放记为排序。AI 和导航实际起拖时沿用其源项选择策略；服务器始终保持原选择及详情状态，避免因起拖展开详情而改变列表宽度。服务器搜索非空时不允许重排。

### 4.3 常驻滚动条

| 项目 | 规则 |
| --- | --- |
| 可见滑块宽度 | 6 |
| 滚动条命中区域宽度 | 12 |
| 卡片到可见滑块的留白 | 18 |
| 列表为空、内容不足或恰好不溢出 | 滚动条仍显示，滑块占满轨道 |
| 内容溢出 | 按真实滚动范围缩短滑块 |
| 箭头 | 隐藏 |
| 右侧对齐 | 可见滑块最右边缘与所属模块右侧操作按钮对齐 |

卡片行间距和卡片到滑块的留白虽都为 18，但属于两个不同方向的尺寸。标题、搜索和操作区不随卡片滚动；列表全宽或详情展开时均保持该规则。不通过伪造滚动模型制造可滚动状态，主题切换和缩放不得叠加留白或重复绑定监听器。

## 5. 排序草稿与保存反馈

服务器、AI 总清单、四种 AI 用途、平台导航和 Mod 工作区导航是八个独立排序域。每域独立维护已确认排列、当前草稿及有效排序次数，不能跨域累计。

- 拖动、上下按钮、Alt+方向键及恢复默认造成实际顺序变化时各计一次；取消、原位释放和普通选择不计数。用途成员加入、移除标记待存，不增加排序次数。
- 前两次先显示草稿，第 3、6、9……次串行保存；离开用途、所属页面或正常退出时补存剩余修改。业务调用和数据库读取仍使用已确认配置。
- 保存期间阻止重复排序。失败保留草稿及计数，不循环重试；下一保存节点或再次离开时重试。离开保存失败则不转场、不关闭。
- 基线冲突默认“保留草稿”，只有明确选择“重新读取”才舍弃草稿。成功离开后结束该域编辑会话并清零计数。
- 正常退出先补存再锁定、关闭服务。手动锁定立即生效，锁定期间不写草稿，导航照常；解锁时不以重读覆盖待存状态。锁定且有未存草稿时，正常退出需先解锁。
- 主题、语言和缩放变化不重置草稿、选择或计数。导航排序保留隐藏入口的槽位，不能因为当前未显示就改变它们的位置。

实现复用 `CardOrderSession` 和 `CardEditGate`，离开、用途切换、刷新及关窗使用同一套异步保存门禁。保存提交完整排列快照，以已确认配置校验基线，不能拿已经重排的界面草稿代替数据库基线。

此处的自动保存适用于排序和用途成员状态。模型、服务器等配置表单继续按自己的显式保存流程执行，不因取消选择、收起详情或关闭表单而自动保存输入。底层字段与约束见[字段规范](File.md#database-structure)；服务器显示顺序仅影响展示，新项追加末尾，编辑保留原序，不修改认证结果、业务目标或任务身份。

## 6. 内容块分隔与信息反馈

浅细分隔线用于同一内容块内多个字段、条目之间，不用于卡片与卡片之间，也不用于独立区块之间。线条随浅深主题更新，保持低于正文的视觉权重。

- 上下排列的配置行、能力行和连接记录使用浅横线。
- 服务器信息的字段内部为上标签、下数值；同一行的相邻字段列之间使用浅竖线，行末不留竖线。
- 保留卡片和区块原有留白，不用额外线框把整页切成表格。

界面只呈现必要的字段、可操作入口、错误和任务状态。排序操作说明、自动保存规则和流程解释写入产品说明书，不在卡片底部或窗口角落放装饰性提示、示例标记或说明性副标题。内部详情不重复外侧页面标题；保留对象名称及分区标题。长文本应按用途换行或省略，并提供完整提示，不挤占按钮或泄露秘密内容。

## 7. 页面实例

### 7.1 服务器

| 状态 | 清单与详情 |
| --- | --- |
| 初始、无选择 | 清单占满内容区，不显示详情 |
| 选中服务器 | 约 40% 清单／60% 详情 |
| 点击其他卡片 | 切换详情对象 |
| 再击当前卡片或“收起详情” | 清空选择，恢复全宽 |
| 手柄拖动 | 保持原选择及详情状态，仅改变展示顺序草稿 |

列表标题为“服务器列表”，计数使用较小的普通字体，名称和连接信息按共用字号层级显示。卡片与详情使用蓝色服务器图标；“收起详情”与右侧身份标题居中，并保持与“检查 SSH”相称的按钮尺寸。

详情的信息块显示服务器地址、SSH 端口、用户名及凭据状态，保持上方标签、下方数值的竖排字段。正常宽度四列，窄栏自动排成两行两列；浅竖线只分隔同一行内相邻列。

“SSH 认证结果”只显示最近一次结果、说明和时间，不重复放在详情标题下，也不新增历史检查表。通过用绿色、失败用红色、未检查用正文色。任务错误、取消和恢复反馈留在对应任务区域，不混入另一个服务器的认证结果。

### 7.2 AI 三态

| 状态 | 清单、入口与右侧内容 |
| --- | --- |
| 全宽清单 | 卡片占满内容区；“添加模型”紧跟“全部模型”；四个用途按钮位于顶部右侧 |
| 模型详情 | 左右约 40%／60%；添加按钮与左栏滚动条右边缘对齐；隐藏四个用途入口；右侧显示配置、核验与当前模型未结束任务 |
| 用途编排 | 原清单留在左侧，左右近等宽；添加按钮仍与左栏滚动条对齐；四个用途入口位于右栏顶部；右侧显示成员及调用顺序 |

全宽态点击模型进入详情；详情态点击其他模型切换，取消选择或“收起详情”返回全宽。用途态点击左侧只选候选，不打开详情。必须关闭详情后才能进入用途编排。

全部模型始终使用通用机器人图标，默认蓝色，不随用途变化，也不显示能力或是否核验的标签。右侧成员按语言、审批、视觉、语音使用对应用途图标。当前用途不允许加入的候选卡片及图标灰显，并禁用加入操作；已加入成员后来失效仍保留位置，可排序或移除，实际调用继续校验当前能力。

用途按钮点一次变蓝并打开右栏，再点当前用途变灰并关闭；不用右上角叉号承担用途关闭。四个按钮不随右栏拉长，用途区不放“启用／取消／保存”按钮。排序和成员状态按第五节保存，配置编辑仍显式保存。

每条模型记录提供一个必填的完整接口 URL，通过独立编辑流程保存；保存配置不触发核验。加入用途本身表示成员身份，不另设用途启用开关。音频资源、传输协议及证据有效性的细则引用产品说明书，不另设 UI 层规则。

详情左上角为蓝色机器人图标和模型名称。“编辑模型”位于配置区标题右侧。核验按以下顺序固定为三列，状态列与按钮列跨行对齐：

| 能力名称 | 状态表达 | 操作 |
| --- | --- | --- |
| 文本 | 实际状态的文字、颜色及图标 | 独立“核验”按钮 |
| 原生工具调用 | 同上 | 独立“核验”按钮 |
| 视觉 | 同上 | 独立“核验”按钮 |
| 完整音频 | 同上 | 独立“核验”按钮 |
| 实时音频 | 同上 | 独立“核验”按钮 |

可用用绿勾，失败用红叉，不支持用棕色叉，未验证用灰色减号；各行以浅横线分隔。每种结果保留原有文字和原因，不用统一绿色状态代替不同证据。

核验任务绑定稳定模型 ID；详情只展示当前模型的未结束任务。同一模型有未结束检查时禁用重复核验和编辑，切换模型或收起详情不取消已接纳任务。保留“取消任务／核对中断／刷新”，UNKNOWN 只核对原任务，旧配置结果不得写回新修订。旧任务没有稳定绑定时留在通用恢复入口，不按模型名称猜测归属。单 URL、内置音频、协议及任务恢复的完整行为见[产品说明书 §16.3](PRODUCT-MANUAL.md#163-全部模型详情与四种用途)。

宿主通过列表、卡片表格和滚动 UI 委托统一接入这些规则，保留原数据模型、排序器和渲染内容。Mod 使用标准 Swing 清单沿用宿主展示，不依赖宿主内部控件，也不因本文增加公开 appapi。

服务器 `server_profile.display_order` 位于名称后、SSH 端点前，字段细节见[字段规范](File.md#server_profile)。维护旧开发库时按[离线工具说明](../../.mvn/tools/server-order/README.md)退出应用并核验配对备份；该工具不接入启动、不增加 Schema 版本。AI 核验在请求前通过既有 `model-probe.v1` 检查点记录模型 ID、配置修订和能力；音频资源及证据处理沿用产品说明书，不在 UI 层另造协议或任务关联方式。

后续修改 UI 时按受影响场景检查浅／深主题、100%／150% 缩放、中英文、正常／最小窗口、空列表、内容不足和溢出。核对点击取消、手柄拖动、禁用、键盘及主题重装后的行为；检查按钮和状态列不裁切、对齐和留白不累计、模型及监听器不被替换或重复绑定。验证采用真实 Swing 渲染，并注明适用范围；设计预览和历史截图不能当成新版本验证结果。

纯文档整理只检查内容、链接、锚点及差异，不因此启动 Maven 或界面测试。修改主题颜色时需同时验证主题配色、共用控件默认值和页面局部样式，并检查主题切换后的现有控件。
