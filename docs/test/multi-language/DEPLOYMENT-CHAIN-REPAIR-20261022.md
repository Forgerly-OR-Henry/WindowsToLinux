## Agent

Agent私有拒绝适配绑定原任务、候选根、完整实际请求与真实独立审核，先持久化无许可、未发送事实，再允许不同方案。隔离探测、PATCH计划及实际PATCH命令均覆盖；同一已拒动作不能换一个审核入口再次申请。取消、无效审核、记账失败和发送不确定仍保留UNKNOWN。

本地19项审核检查、2项实际Session隔离拒绝和2项实际Session PATCH拒绝检查通过。不同方案重新取得独立审核及新的宿主许可；第二次发送故意失败时，原Session保留UNKNOWN且不再继续调用主模型。这些Session夹具不等于完整Workflow的资源释放验证。

完整Workflow故障注入进一步确认Agent候选清理的确定缺陷：实际固定请求声明正式目录和候选目录两个资源，私有补充证据却只匹配正式目录，合法请求在清理前被拒绝；其状态观察捕获也遗漏候选、快照和应用锁三个真实目标。现已按实际两资源清理、四资源观察修正，并对目标排序。实际清理正例、缺失/替换/增加资源及授权后原绑定变化的13项反例通过；原UNKNOWN记录保留，清理成功不代替业务结论。

清理证据测试类的53项检查分别通过，包含原生完整证据分页、健康与清理拒绝、原宿主命令结清、缺席观察不确定、绑定变化和损坏旧控制器索引。后者在恢复入口明确返回UNKNOWN，未执行远端动作或改写原日志；首次失败和定点回验结果均保留。

控制器操作新增版本1原请求和类型化回执。发送前保存原源码身份、精确参数、服务器与指纹及目录身份；大请求使用带片数、长度、SHA和结束记录的ActionLog片段，检查点仍遵守12000字节限制。恢复只观察原操作，经独立审批及新许可清理精确原unit、cgroup、mount、loop和私有镜像，再观察并持久化结清证明。worker、原prepare/bind、工具版本选择和产物晋升均不重放；共享安装和不可变绑定保留。

执行结果与效果结清分别保存。清理成功不会把原FAILED或UNKNOWN改为执行成功；只有实际传输和完整回执可证明失败且效果已结清，才可作为已知失败交回主模型。旧无原操作创建证明、身份冲突或活跃子进程继续UNKNOWN，不释放占用。

新增15项证据一致性与留存反例、61项控制器状态检查、18项失败证据检查、5项tracked回执检查，以及2项控制器存储恢复检查通过。重读时检查原请求结束记录、原发送、实际结果、最后恢复观察和结清证明的因果次序；检查点中的回执必须与同一实际传输的原结构化回执逐值一致。原结果写入缺口仅允许追加结清，不补造原RESULT。

新增传输审计只保留状态、退出码、截断、长度、摘要及有限受控错误码。只有实际完整成功、空stderr并通过原请求严格编解码校验的单行结构化回执才保存原字节；无效输出、UNKNOWN/FAILED输出、stderr及任意异常正文不新增全文留存。4个秘密哨兵分支已包含在上述15项检查内。

Python新增20个受控场景已分别通过，覆盖创建半途、回包丢失、原失败保留、父进程结束但原进程组仍活跃、子进程创建记录缺口、unit停止次序、loop/mount身份变化、placeholder半创建和晋升rename窗口。本机夹具替代部分Unix权限、锁及系统调用，不能证明真实Linux内核、systemd或loop/mount行为。

控制器跨启动六个场景分别通过：原PREPARE/BIND回包丢失、清理回包丢失后再次启动、worker已失败，以及旧无完整原证据和服务器指纹冲突。前四项的恢复动作各自取得新独立审核及许可，不重放原prepare/bind；核清原效果后以原业务FAILED完成，保留原RESULT和原载荷身份。全新进程确认正式归档、零占用及同目标新任务准入，该准入进程的远端连接、AI调用和命令发送均为零。后两项保持UNKNOWN、原占用和原证据，不产生审核许可或执行发送；恢复模式仍拒绝新业务任务。

旧Agent真实验收保持暂停，不因本地修复自动恢复。

控制器跨启动组使用实际Mod注册、TaskService和H2，受控恢复任务调用产品ControllerRecovery入口，验证原控制器恢复及同目标任务准入，不包含主Agent重新规划、构建或发布验收。平台结束任务通过正式归档入口查询；已释放检查点按原有平台归档规则清理，归档前核对其原字符串，归档后核对作者日志中的原RESULT、传输摘要和结清证明。该规则未在本轮修改。
