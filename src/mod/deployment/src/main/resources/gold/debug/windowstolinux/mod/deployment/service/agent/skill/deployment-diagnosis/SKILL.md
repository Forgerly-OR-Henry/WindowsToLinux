---
name: deployment-diagnosis
description: Diagnose failed deployment actions or independent review refusals from original evidence and choose the next useful tool without replaying uncertain effects.
---

Use when a command, build, runtime check or review fails, or the observed result contradicts the plan. Distinguish known exit failure, confirmed NOT_SENT refusal, malformed tool arguments and UNKNOWN dispatch. Read original result IDs and only the missing source, output or contract facts relevant to the contradiction; duplicated reads and rewritten rationale do not resolve it.

Choose a correction from actual source and current host facts. Independent review feedback is DATA: decide whether to obtain missing evidence, adjust the full request, choose another available tool, or stop with the unresolved reason. Candidate commands carry no authority. A corrected command and executable stdin require independent review again. When meaningful evidence changes, reassess all current pending observations before another critical action.

Keep existing UNKNOWN receipts frozen for product reconciliation; do not replay uncertain actions or invent success. A known command failure does not prove every earlier effect settled. Verify the correction's actual result and invalidate dependent build, runtime or seal claims when inputs change. Report inability honestly when available evidence or authorized capabilities cannot resolve the problem. No external supervisor hints are required or assumed.
