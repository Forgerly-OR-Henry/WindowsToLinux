Agent controller store contract WTL_AGENT_CONTROLLER_STORE_1 applies only when the product-derived agentToolchainInstalledInputBinding is present. It does not apply to arbitrary commands, the original inline-program entrypoint, shared managed-helper, dependency maintenance or resolver algorithms. Binding proves exact current inputs and retained observation identity, never safety, permission or a completed future effect.

Tracked invocations use exactly prepare-tracked/bind-tracked/observe-tracked/cleanup-tracked, original task UUID, operation ID and SHA256 of the original raw recipe. Their stdin is complete public bound recipe data, not executable source or empty stdin. The fixed loader validates and passes those original bytes plus its version/source/layout binding to the pinned controller. Independently review the complete current loader and controllerSource for every verb. Observe/cleanup never execute the original preparation worker, vendor command, promotion or binding creation. They validate original request/creation/state files under the original prepare lock, retain shared installations and immutable bindings, and act only on exactly identified owned resources. Missing, conflicting, active-child, busy or incomplete proof remains UNKNOWN; no legacy identity may be inferred.

The single strict AGENT_TOOLCHAIN_TRACKED JSON receipt preserves original executionStatus independently of effectState and cleanupState. SDK exit zero means only complete protocol transport. Original FAILED/UNKNOWN cannot become toolchain success after cleanup. Business success requires SUCCEEDED, verified settled effects and the complete physically checked selection/shared installation or original immutable binding. Java stores the original public recipe and only strict identity-bound non-secret receipt bytes in bounded journal parts with complete END records before publishing references; actual SDK outcome, exit, truncation and channel lengths/digests are retained independently. Invalid or transport-UNKNOWN/FAILED output, stderr and arbitrary problem text are omitted; only fixed event codes or event digests are retained. Java records dispatch before execute, retains the original checkpoint payload and RESULT during recovery, and closes occupancy only after a fresh exact observation and durable settlement. Cleanup intent is consumed once, including acknowledgement loss; later recovery observes rather than resends. Original READINESS/INSTALL can be observed only with a complete retained fixed store frame; INSTALL additionally requires READY with its exact original installTask/installOperation. Missing version, another owner's installation or any incomplete stage is never repaired or reinstalled by recovery.

First install or a new source/layout version requires independent review of the complete transmitted installer, its complete embedded loader and every byte of controller source. The shipped manifest pins the default complete controller SHA, loader and installer templates and this contract; runtime rejects changed shipped inputs before deriving a captured-layout version. The version SHA binds this manifest, contract revision, captured layout and rendered controller source SHA; it is distinct from the controller byte SHA. Version paths are content addressed and coexist without current/latest aliases or deletion. An existing matching installation preserves its original installTask and installOperation; another task obtains a new reference, not ownership of the installation.

Before each action review the complete actual launcher, typed argv, source/version and contract identities, captured layout, actual resource targets, original task and retained readiness/install evidence. Empty stdin on the installed entrypoint does not mean that the privileged controller is arbitrary or unreviewed: only the exact pinned version is eligible. The entire current loader remains in the command script. Its directory-FD chain rejects symlinks, non-root owners and group/world-writable directories; its regular files require root UID/GID, exact read-only mode, single link and byte bounds. It reads each selected file through one FD, compares before/after identities and the complete controller SHA, then executes only those bytes with PROGRAM_SOURCE. No path, URL, module or expression is selected by a caller. Readiness validates the same bytes but never executes the controller.

Installation uses its protected single-link lock and new private staging, verifies complete writes and files, then Linux renameat2 with RENAME_NOREPLACE publishes without overwriting any existing version. No fallback publication, repair, removal or replay is authorized by this contract. Contention, an incomplete installation, unsafe ownership/permissions, absent receipt, failed native support or unknown transport stays unconfirmed. Only a strict successful READY receipt permits use; a clearly absent version permits a separately reviewed install. Future receipts are not required before dispatch, but missing actual receipts prevent completion afterward.

Installed prepare/bind retain the exact existing controller behavior: an operation-private controller copy and manifest/worker source SHA binding; root setup, protected ready/identity gates, non-root restricted vendor execution, complete unit stop, empty cgroup and read-only freeze proof, detach and data-only promotion. No vendor execution at root or bypass of these checks is permitted. Independent review still covers current dynamic argv, asset/binding facts, resource effects and unresolved enforcement questions. Every action, including a changed version or argv, requires its own independent verdict and exact fresh host grant. DENY and UNKNOWN remain authoritative; no previous action's approval transfers.

The current controller has two fixed resource policies. Cold INSTALL retains its 8 GiB image and the original promotion-space calculation. PROBE uses a 64 MiB writable image only for already registered, fully matched MANAGED or SYSTEM installations and exact binding probes. Both retain the 1 GiB host admission margin. The manifest binds mode, exact bytes and actual image/loop identity; a PROBE image cannot execute INSTALL. A small quota does not prove that a particular vendor probe will fit or that the host margin remains untouched by concurrent or later metadata writes.

Before creation, the controller freezes each complete selected record, its actual marker SHA and protected directory identity, including JAVA_HOME when present. It rechecks the same observations before worker execution and before publishing success; SYSTEM files retain their original digest checks. Missing, changed or replaced observations do not fall back to cold installation, another record or a larger image. An initially absent installation may use only the original cold policy. The restricted worker, write paths, network isolation and stop/freeze/detach checks are identical for both modes. Probe failure, volume exhaustion or incomplete creation does not authorize retry, growth, deletion of old resources or a cleanup-complete claim. Only the separately source-pinned finite precreation-refusal evidence can release that specific uncreated operation while preserving FAILED and shared metadata.

Each task retains original server/layout/version/path/SHA/installOperation/use-operation and action/result references. Successful occupancy is released only after the required original evidence summary is durable; failed, cancelled or unknown evidence is retained and recovery/cleanup cannot declare it settled from a later task's READY observation. Old versions, private failed stages and original UNKNOWN evidence are not deleted by this mechanism. This contract is a narrow product implementation boundary, not a statement that any particular requested action must be approved.
